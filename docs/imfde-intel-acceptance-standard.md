# imfde 情报产品验收标准 v1.0（待确认基线）

> 本文定义「一条合格情报」与「一期合格产品」的判据。它是**内容验收标准**，不是工程验收标准，也不是页面设计方案。
> 后续任何首页、简报、情报台、付费层的改动，先过本文；不过红线的， page 做得再漂亮也不算完成。
> 依据见文末，借用与改写处已标明。**未经确认前不作为已生效基线。**

---

## 0. 本体定义（先定这个，否则后面全是空谈）

imfde 做的是**公开来源的行业情报**：把外部世界发生的事，经过信息学工序加工，压缩成可回溯、可比较、可更新的信息，传递给读者。

工序（缺一不可）：

```
选源 → 辨源/去重 → 筛选 → 受控标引 → 摘要 → 跨源综合
     → 来源批判 → 组织/标引 → 传递 → 跨期核对与改判
```

**产品是信息，不是建议。** 采购、招聘、组织、成本、任务书属于咨询交付物，越界即不合格（见 R8）。
读者的决定由读者自己做；情报提供的是信息优势，不是决策代劳。

## 1. 依据与改写

| 依据 | 借用 | 改写 / 不适用 |
|---|---|---|
| **ICD 203《Analytic Standards》**（ODNI，2015 签署、2022 技术修订） | 5 项分析标准、9 条 tradecraft standards；明确要求「标准为产品定期评价的核心评估准则」(D.2)；来源质量与可信度描述、不确定性表达、事实/假设/判断分离、替代分析、主信息前置、判断变化说明、准确性、视觉有效性 | 不涉国安、PII、政治倡导；将「不受政治考量影响」改为「不受商业立场、赞助、流量诱惑影响」；将「customer relevance」改为「读者相关性」，且**不包含替读者给行动方案** |
| **ICD 206《Sourcing Requirements》**（由 ICD 203 引用） | 来源摘要陈述、来源描述符、影响可信度的因素（准确性、完整性、时效、立场、动机、可达性、验证程度） | 本轮 PDF 下载成功但文本层为空，未逐字引用；按 ICD 203 中对它的转述执行 |
| **Admiralty / NATO 双轴评级**（STANAG 2511 / AJP-2.1 体系） | 源可靠性 A–F 与信息可信度 1–6 **独立评级**；F/6 = 无法判断，不等于否定；E/5 才是否定 | 用于 OSINT 与厂商自述分级，不冒充机密情报评级 |
| **信息学工序** | 辨源去重、受控词表标引、摘要与综合、来源批判、可回溯性 | — |

### 本项目专用源评级（映射表，固定不可随意改）

| 码 | 材料类型 | 能支撑什么 | 不能支撑什么 |
|---|---|---|---|
| B1 | 官方公告 + 独立媒体交叉确认 | 计划存在、日期、公开承诺 | 计划已完成、交付效果 |
| B2 | 官方公告单一来源 | 厂商自己的表述 | 实际落地、客户效果 |
| C2 | 厂商客户案例（具名自述） | 存在该客户与该项目、过程描述 | 独立验证的 ROI、行业基准 |
| C3 | 媒体报道中的具名案例 | 过程叙述、引用 | 数字口径、因果 |
| D2 | 招聘 JD / 岗位普查 | 组织意图的可见信号 | 团队规模、交付成熟度、实际人数 |
| F6 | 本地结构化整理字段、抓取超时未存快照 | 线索、待核清单 | 任何对外结论、数字引用 |

**硬规则**：任何数字若其来源码为 F6，不得进入判断句，只能进入「待核清单」。

## 2. 一票否决（红线 R1–R9）

**任一命中即退回，不得发布、不得进入付费层、不得用工程验收抵消。**

| 编号 | 红线 | 判定方法 |
|---|---|---|
| R1 | **不可回溯**：判断句找不到具名来源，或来源状态未标注 | 每个事实句能点回 URL/原文快照；缺一项即挂 |
| R2 | **事实与判断混写**：假设、推论、AI 整理结果被写成事实 | 全文逐句标注 `事实 / 判断 / 假设` 三类，缺标即挂 |
| R3 | **口径混用**：不同样本、分母、时间窗的数字被比较、相加或平均 | 每个数字必须带口径三件套：样本、时间窗、分母 |
| R4 | **时态造假**：计划/承诺/目标写成已完成/已上线/已验证 | 逐句核对动词：宣布 ≠ 完成，目标 ≠ 结果，在招 ≠ 到岗 |
| R5 | **空白被填满**：未披露项被写成「没有发生」「效果为零」 | 只写「该来源未披露」；不写「没有」 |
| R6 | **同源未去重**：同一公告的多篇转述被当作多条独立证据 | 必须有同源簇 ID；转述数不得计入证据数 |
| R7 | **无证据的锐利**：为制造「价值感」而造矛盾、造冲突、造结论 | 反直觉结论必须有 ≥2 个独立源；否则降级为「观察」 |
| R8 | **本体越界**：替读者做采购/招聘/组织/成本决定 | 出现方案、任务书、成本测算、决策建议即挂 |
| R9 | **假连续性**：台账、历史期次、兑现记录是编造或演示数据却按真实呈现 | 每条台账记录必须能回指某期原文与核对日期 |

## 3. 内容质量评级（过红线后打分）

每条情报卡按 12 项打 0 / 1 / 2 分，满分 24。

| # | 检查项 | 0 分 | 1 分 | 2 分 |
|---|---|---|---|---|
| C1 | 主信息前置 | 埋在中间 | 有结论但靠后 | 首句即判断 |
| C2 | 事实/判断/假设分离 | 混写 | 部分标注 | 逐句可辨 |
| C3 | 来源描述 | 只给链接 | 给发布者+日期 | 加源类型、立场、局限、Admiralty 码 |
| C4 | 来源批判 | 无 | 提一句「自述」 | 说明为何该源在此处足够/不足 |
| C5 | 不确定性表达 | 无 | 只有「可能」 | likelihood 与 confidence **分句**表述，并写明成因 |
| C6 | 替代解释 | 无 | 一句带过 | ≥1 个合理解释 + 什么证据会区分它 |
| C7 | 反证与未披露 | 无 | 只列未披露 | 列出会削弱判断的反证 |
| C8 | 跨期关系 | 无 | 写「延续」 | 明确「首次 / 一致 / 变更」+ 变更依据（ICD 203 #7） |
| C9 | 下期核对指标 | 无 | 泛泛「持续关注」 | 可判定的具体信号（谁、何时、什么动作） |
| C10 | 信息密度 | 复述原文 | 有压缩 | 删掉复述，只留新信息与必要背景 |
| C11 | 措辞精度 | 模糊动词 | 基本准确 | 「宣布/计划/完成/验证」无一处误用 |
| C12 | 读者相关性 | 无关 | 相关但泛 | 与读者要判断的外部变化直接相关，**且不越过 R8** |

**判定**

- 任一 C 项为 0 → 退回，不论总分。
- **A 级**：≥20 分且无 0 分项 → 可进入正式期次、可作付费层内容。
- **B 级**：16–19 分且无 0 分项 → 仅可作免费公开简报，不得放付费层。
- **C 级**：<16 → 退回重做。

**付费层额外门槛**（在 A 级之上）：必须有 ① 跨期核对记录 ② 替代分析 ③ 来源评级表 ④ 改判留痕。缺一不设付费入口。

**上线门槛**：连续 **3 期**达到 A 级，才允许开放订阅/付费入口；此前只做免费层。这是防止「先卖后补」的硬约束。

## 4. 证据卡（每条情报的强制字段）

```yaml
id: 唯一编号
headline: 判断句（≤20 字，首句即主信息）
facts:            # 仅底层情报信息
  - text: 事实句
    source_id: [...]
    source_code: B1/B2/C2/...   # Admiralty 映射
    scope: {sample: , window: , denominator: }
    dedup_cluster: 同源簇 ID
judgment:         # 分析判断
  text: 判断句
  based_on: [fact_id...]
  likelihood: 几乎不可能/不太可能/大致可能/很可能/几乎确定
  confidence: 低/中/高        # 与 likelihood 不同句
  uncertainty_causes: [信息类型, 时效, 缺口, 议题性质]
assumptions:      # 显式列出；说明若假设错了判断如何变
  - ...
alternatives:     # ≥1 个合理解释 + 区分指标
  - ...
contrary: 会削弱本判断的反证 / 本来源未披露项
sources:          # 每条：url / 发布者 / 日期 / 类型 / 立场 / 局限 / 快照状态
change_from_last: 首次 | 一致 | 变更（附依据与日期）
next_check:       # 可判定的具体信号，不是「持续关注」
evidence_status: 已核实 | 仅摘要 | 待快照 | 待逐句核对
review: {by: , date: , result: A/B/C/退回}
```

**机器预检**（发布前自动跑，不替代人工）：字段齐全、URL 可达、口径三件套存在、同源簇去重、evidence_status ≠ 已核实 的数字不得出现在 judgment、likelihood/confidence 不同句。

**人工复核**（发布前）：判断句 100% 回溯；事实句抽样 ≥20% 回溯；全部来源码抽检；与上期一致性核对。

## 5. 工程验收与情报验收分离

| 工程验收（不能替代内容验收） | 情报验收（本文） |
|---|---|
| 页面能打开、tab 能切、筛选可用、无 console error、移动端无溢出、构建通过 | 红线 R1–R9、C1–C12、证据卡、跨期核对、来源评级 |

之前几轮我拿「浏览器零报错 / 交互可用 / 截图好看」当作交付完成，**这是用工程验收冒充情报验收**，是这一轮要纠正的核心错误。

| **用户改写的 v4 简报** | 无 | **A−** | 事实/判断分离、承诺标成承诺、构想标成构想、未披露写「我读到的部分没有」、缺处挂「待补」不补推测。**作为内容基线** |

## 7. 复核与改判机制

1. **每期发布前**：机器预检 → 人工复核 → 按 C1–C12 评级 → 记录 `review.result`。
2. **每月产品评价**（对应 ICD 203 D.2 的 regular program of review）：抽 5 条已发判断，回溯来源、检查下期核对是否执行、统计改判次数。
3. **改判留痕**：任何判断从「追踪中」变「兑现/证伪/证据不足」，必须写：改判日期、触发它的具体新信息、旧判断错在哪。不得静默替换。
4. **标准本身可修订**：每季度评一次；红线只增不减，修订需写明理由与生效期。

## 8. 生效方式

- 本文件为**待确认基线**。确认后：任何内容改动先按 R1–R9 自检，再按 C1–C12 评级，评级记录随产物一起交付。
- 未达到「连续 3 期 A 级」前，不接订阅、不做付费墙、不对外宣称「付费情报」。
- 下一步工作不再是「改一版页面」，而是：**按第 4 节证据卡，把一条真实情报从原始材料加工到底，用本标准验收通过**，再谈期次与产品化。

## 依据

- [ICD 203《Analytic Standards》官方 PDF（ODNI）](https://www.dni.gov/files/documents/ICD/ICD-203.pdf) — 5 项分析标准 + 9 条 tradecraft standards；D.2 规定标准为产品定期评价的核心评估准则。本轮已下载并提取全文核对。
- [ICD 206《Sourcing Requirements》官方 PDF（ODNI）](https://www.dni.gov/files/documents/ICD/ICD-206.pdf) — 本轮下载成功但 PDF 无文本层，未逐字引用；按 ICD 203 对它的转述执行。
- [Admiralty / NATO 双轴评级说明](https://www.threatintelreport.com/intelligence-reliability/) — A–F 源可靠性、1–6 信息可信度、两轴独立。
- [Cyberint UK: Applied Intelligence / Intelligence Operations](https://www.cyberint.uk/applied_intelligence/intelligence_operations/) — 评级定义与矩阵。
- [MISP admiralty-scale taxonomy](https://github.com/MISP/misp-taxonomies/) — 机器可读的评级词表。
- [UserSearch: Admiralty Code in OSINT](https://usersearch.com/resources/intel-hub/blog/admiralty-code-osint-source-grading) — F/6 表示「无法判断」而非否定；两轴不可合并打分。
- [Kelly et al. (2024), *The Effect of Source Reliability and Information Credibility on Judgments of Information Quality in Intelligence Analysis*](https://econpapers.repec.org/article/cupjudgdm/) — 指出专家与新手都可能误用信息评价体系，因此本标准要求「来源码 + 人工复核」双轨，不迷信自动评级。
