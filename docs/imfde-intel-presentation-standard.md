# imfde 情报展示与解释规范 v1.0

> 配套 `docs/imfde-intel-acceptance-standard.md`。前者管「情报本身合不合格」，本文件管**「合格的情报怎么放到读者眼前、怎么把判断解释清楚」**。
> 这是信息学里独立的第二门手艺：加工是替读者做信息劳动，展示与解释是替读者做**认知劳动**。同一份情报，展示错了，读者拿到的就不是同一份情报。
> 状态：待确认基线。确认后与验收标准一起生效。

---

## 0. 为什么展示也是手艺：一个真实事故

Sherman Kent 1964 年《Words of Estimative Probability》记录了 NIE 29-51 的失败：

> 判断原文：对南斯拉夫的进攻「应被视为一种 **serious possibility**（重大可能性）」。
> 作者本人心里是 **65:35 偏向进攻**；政策规划办公室的读者理解成「远低于此」；同一委员会内部成员的理解从 **20:80 到 80:20** 不等。

**情报没写错，但传达出来的意思完全不是情报员想表达的意思。** Kent 的结论是：产品必须让读者分清「什么是确知、什么是推理判断、每个关键判断背后有多大的确定度」，且措辞必须受控——「possible」不许加任何修饰词，要"赤裸地"使用。

由此得到本规范的第一原则：

> **读者接收到的意思 = 情报员想表达的意思。** 这不是文风要求，是准确性要求（ICD 203 tradecraft #8 明写：analytic message a customer receives should be the one the analyst intended to send）。

## 1. 三层读者，三种阅读契约

同一个人会在不同时间处于不同层；产品必须让这三层各自成立且互相可达。

| 层 | 读者状态 | 应看到 | 字数上限 | 阅读契约 |
|---|---|---|---|---|
| **L1 扫读** | 20 秒，判断值不值得读 | 主判断 + 确定度 + 「与上期相比变了什么」 | 1 句判断 + 1 行标注 | **只读这一层也能得到正确结论，且不产生误读** |
| **L2 理解** | 3 分钟，想知道凭什么 | 事实 / 判断 / 假设分区 + 来源评级 + 反证与未披露 + 替代解释 | 一屏 | 能独立复核每一句判断的来路 |
| **L3 核验** | 要引用、要追溯、要挑战 | 证据卡全字段、原文快照、同源簇、口径、改判留痕 | 不限 | 能走到原始材料，并看到本判断历史上改过没有 |

**硬约束**：L1 必须能**独立成立**（NIE 的 Key Judgments 设计要求「可独立成篇」）。任何把关键限定语藏在 L2/L3 的写法都算展示失败——因为 80% 的读者只到 L1。

反面例子（我写过的）：「69 个岗位，0 个可验证结果」——L1 极锐利，但限定条件全在 L2 之后，扫读的人读到的是一个并不存在的矛盾。按本规范属 P2 红线。

## 2. 一条情报的固定版式（倒金字塔 + 分区）

```
┌ L1 ────────────────────────────────────────────┐
│ 判断句（≤20 字，首句即主信息，不铺垫）           │
│ 标注行：Likelihood: 很可能 ｜ Confidence: 中     │
│         （两个词必须分句，不得同句）             │
│ 跨期标签：首次 / 与上期一致 / 变更（附依据）     │
├ L2 ────────────────────────────────────────────┤
│ 【事实】  2–4 句，每句带来源码与口径三件套       │
│ 【判断】  从哪些事实推出、推理链的哪一步是推断    │
│ 【假设】  显式列出；假设错了判断会怎么变          │
│ 【反证】  会削弱本判断的事实 / 来源未披露项       │
│ 【替代解释】 ≥1 个；什么证据能把它与本判断区分开  │
├ L3 ────────────────────────────────────────────┤
│ 来源表（发布者/日期/类型/立场/局限/快照状态）    │
│ 同源簇、口径、原文链接、证据状态                 │
│ 下期核对指标（可判定，不写「持续关注」）         │
│ 改判记录（日期 / 触发信息 / 旧判断错在哪）       │
└────────────────────────────────────────────────┘
```

**版式规则**

- 一屏只放一条情报的判断链；不把三条不同判断压进一张卡片。
- 判断句与来源之间**视觉相邻**，不能把「依据」折叠到要点击才看的地方（折叠会制造误读）。
- L1 → L2 → L3 是渐进披露，**不是隐藏**：L1 里出现的每个数字，L2 必须立刻能看到它的口径。
- 与读者自身处境无关的内容一律不进 L1（对应「不替读者做决定」）。

## 3. 措辞受控表（解决 Kent 事故）

### 3.1 三类语句，固定动词

| 类别 | 允许动词 | 禁止 |
|---|---|---|
| 事实（已发生、有来源） | 发布、宣布、公布、披露、上线、签署 | 证明、标志着、意味着（这些是判断） |
| 计划/承诺 | 计划、目标、承诺、拟、预期 | 完成、实现、落地、已培养、已部署 |
| 判断 | 我们判断、据此推断、更可能是、尚无证据表明 | 显然、无疑、必然、事实是 |
| 不确知 | 该来源未披露、我们未能核实、证据不足 | 没有、为零、不存在、全部锁在 NDA 里 |

**禁令**：不得给「可能」加修饰（「重大可能」「相当可能」「不排除」）。likelihood 只用固定词表，且**不在同一句里同时写 likelihood 与 confidence**（ICD 203 明令）。

### 3.2 固定词表（ICD 203 七档，全站只用这一套）

| 档 | 中文 | 约当 |
|---|---|---|
| 1 | 几乎没有可能 | 1–5% |
| 2 | 不太可能 | 5–20% |
| 3 | 可能性偏低 | 20–45% |
| 4 | 大致相当 | 45–55% |
| 5 | 很可能 | 55–80% |
| 6 | 极有可能 | 80–95% |
| 7 | 几乎确定 | 95–99% |

**confidence 单独一行**：低 / 中 / 高，依据 = 源的数量与质量 + 逻辑链完整度 + 是否存在反证。**不允许把 confidence 偷偷换算成 likelihood 的措辞**。

### 3.3 数字展示三件套

任何数字在 L1 出现，必须在同屏紧邻处给出：`样本是什么 / 时间窗 / 分母`。
- 反例：「69 个岗位，0 个可验证结果」（两个数字的样本与分母都不同，却并列成矛盾）。
- 正例：「近 14 天采集到 42 条事件（样本：自有 89 信源；其中 27 条为岗位发布）；本期 5 条部署案例均未在该来源段落披露量化成效」。

**禁止跨口径汇总**：厂商自述、媒体转述、招聘 JD、结构化整理字段四类数字不得相加、平均或排名。

**市场对照（2026-11-11 实抓）**：FDE Pulse 的 `$185K Median Base` 紧邻 `n=216 disclosed`、`Active FDE Jobs 1261 updated weekly`；FDE Hub 首屏指标紧邻 `Indeed · 2025.4–2026.4`、`LinkedIn · 2023–2025`；Perspective AI 报告写明 `1,500 respondents / 154 companies / Feb–Apr 2026`。**这三家都把口径做成展示元素，不是脚注**。因此 D4 的最小可接受形态是：数字旁直接显示 `n=` 与时间窗；只放在文末「数据来源」页视为未通过。本会话早前 demos 把 559 条案例、69 个岗位等数字裸放在首屏而无口径，按 D4 应退回。

## 4. 视觉编码：只编码结构，不制造结论

| 视觉手段 | 用来表达 | 禁止 |
|---|---|---|
| 左竖线 + 淡底 | 事实 / 判断 / 假设 / 反证 / 替代解释的**分区** | 用颜色深浅暗示「这条更重要」 |
| 小号标签（B1/C2/F6） | 来源等级，固定位置 | 用红绿表达「可信/不可信」 |
| 时间线 | 事件发生顺序、跨期变化 | 用斜率暗示趋势 |
| 同源簇折叠 | 20 篇转述归为 1 条事实 | 把转述数画成「证据强度」 |
| 台账状态字 | 追踪中/部分兑现/证据不足/证伪 | 进度条、百分比、评分 |
| 空白 / 「未披露」 | 信息缺口 | 用 0、横线、灰色块填充 |

**ICD 203 tradecraft #9 的边界**：视觉只在能澄清主信息时使用；任何装饰性图表、仪表盘、评分卡都算噪音。情报台不是数据大屏。

**不确定性的视觉化**：在判断句旁用固定位置的标签表达，不用颜色深浅、不用仪表盘、不用概率条。研究（2025 *Intelligence and National Security*）指出视觉编码能降低认知负荷，但也强调目前尚无统一惯例——因此在有统一惯例前，**宁可用文字标签，不发明图形语言**。

## 5. 「解释」要解释什么（这是被漏掉最多的一层）

解释 ≠ 把判断再复述一遍。解释必须交代四件事：

1. **推理链**：从哪几条事实，经过哪一步推断，得到这个判断；哪一步是推断而不是事实。
2. **为什么不是别的解释**：至少列一个合理的替代解释，并写出「什么证据出现会让我们改选它」（ICD 203 #4 / ACH 的诊断性证据原则：能区分假设的证据才算证据，与所有假设都相容的不算）。
3. **确定度从哪来**：源的数量、质量、时效、立场；逻辑是否完整；有没有反证。不是拍脑袋写「中」。
4. **怎么会被推翻**：具体、可判定的信号；不写「持续关注」。

**ACH 的展示形式**（用于重大或反直觉判断，不必每条都用）：一个小矩阵，行=证据，列=本判断 / 替代解释 A / 替代解释 B，格内标「一致 / 不一致 / 无关」。重点展示**哪些证据具有诊断性**（只与某一个解释相容），而不是给假设打分排名。CIA《A Tradecraft Primer》明确：ACH 的价值在于**排除**，不是选出「得分最高」的假设。

**关键假设检查**：若判断依赖某个未写出的前提，必须在 L2 显式列出，并说明「若该前提不成立，判断会变成什么」。

## 6. 跨期展示：连续性的界面

情报台与普通简报的差别，全在跨期关系的展示上。每条判断必须带：

```
跨期状态：首次 ｜ 与上期一致 ｜ 变更（附新信息与日期）
下期核对：{谁} 在 {何时} 出现 {什么可判定动作}
改判记录：[日期] 触发信息 → 旧判断 → 新判断 → 旧判断错在哪
```

**展示要求**
- 台账按「判断」组织，不按「日期」组织；读者要能一眼看到某条判断从提出到现在的全部状态变化。
- 「证据不足」是正式状态，不是失败，不得隐藏或合并进「追踪中」。
- 未执行的下期核对项要显式暴露（「本期未核对：…」），不许静默跳过。
- 历史期次若未经回填，必须标注「演示数据 / 未回填」，不得与真实台账混排（对应红线 R9）。

## 7. 展示红线 P1–P9（与内容红线并列，一票否决）

| 编号 | 红线 | 判定 |
|---|---|---|
| P1 | **限定语藏在后面**：L1 的锐利结论，其限定/口径要展开才看得到 | 只看 L1 是否会产生误读 |
| P2 | **制造不存在的矛盾**：为吸引阅读把不同口径数字并置成冲突 | 核验两数字样本/分母 |
| P3 | **颜色/视觉暗示结论**：用高亮、绿色、进度条暗示某方案/判断更优 | 关掉 CSS 后结论是否不变 |
| P4 | **折叠依据**：把「依据」「来源」默认隐藏，需要点击才展示 | 默认状态下可见 |
| P5 | **置信度与可能性混写**：同句出现「高置信度、很可能」，或用模糊修饰词 | 逐句查词表 |
| P6 | **复述冒充解释**：解释段只是把判断换句话又说一遍 | 是否写了推理链/替代/确定度/推翻条件 |
| P7 | **无替代解释**：反直觉或低证据判断只给一种解释 | 至少 1 个 + 区分指标 |
| P8 | **跨期关系缺失**：不写首次/一致/变更，也无下期核对指标 | 查跨期字段 |
| P9 | **常驻营销指标冒充本期变化**：把「+729% 岗位增幅」「559 条案例」这类长期背景数字放在首屏，却让读者误以为是本期新发现（FDE Hub 首屏四个指标是常驻营销数据，不是本期情报） | 首屏每个数字必须标明「本期新增 / 截至某日的存量 / 常驻背景」三者之一；未标即挂 |

> P9 依据：`.zcode/research-fde-intel.md` 对 FDE Hub 首屏的核查。P1–P9 为 v1.1 版。

## 8. 展示验收（D1–D10，过 P1–P9 后打分）

| # | 检查 | 通过标准 |
|---|---|---|
| D1 | 20 秒测试 | 只看 L1 的读者能复述出与情报员一致的意思（复述偏差 = 失败） |
| D2 | 独立成篇 | 遮住 L2/L3，L1 仍成立且不误导 |
| D3 | 溯源距离 | 任一句事实 → 来源 ≤1 次点击 |
| D4 | 口径同屏 | L1 每个数字，同屏可见 `n=` / 样本 / 时间窗 / 分母；只放文末来源页视为未通过 |
| D5 | 分区可辨 | 关掉样式（纯文本）仍能分清事实/判断/假设/反证 |
| D6 | 措辞合规 | 全篇 likelihood 只来自固定词表；confidence 不同句 |
| D7 | 解释完整 | 推理链 + 替代解释 + 确定度来源 + 推翻条件，四项齐全 |
| D8 | 反证可见 | 削弱判断的事实与未披露项在 L2 默认可见 |
| D9 | 跨期可见 | 状态、下期指标、未核对项、改判记录均可见 |
| D10 | 无装饰噪音 | 删掉全部图表/配色后，信息量不减 |

**判定**：D1–D10 全过 → 可发布；任一不过 → 退回重排。工程验收（渲染、响应式、零 console error）另算，不能替代本表。

## 9. 用同一条情报展示「差 / 好」对照

**差（我写过的 v2）**
> **69 个岗位，0 个可验证结果。**
> FDE 招聘数量在爆炸，但真正的部署证据全锁在 NDA 里。这是行业的谎言，也是你的机会。

违规：P1（口径藏在后面）、P2（不同样本数字并置成矛盾）、P5（无 likelihood/confidence）、P7（无替代解释）、R7（无证据的锐利）、R2（"锁在 NDA 里"是无来源推测）、R8（"你的机会"滑向建议）。

**好（按本规范重写，同一批材料）**
> **判断：供给侧制度化的公开证据，多于交付效果的公开证据。**
> Likelihood：很可能。Confidence：中（源数量足，客户侧独立核验缺失）。
> 跨期：首次提出。
>
> 【事实】Anthropic 于 10-02 宣布 Academy 计划（B1：官方公告 + 媒体转述）；近 14 天自有 89 信源采集 42 条事件，其中 27 条为岗位发布（D2）；本期 5 条部署案例的来源段落均未披露同口径成效（C2/C3）。
> 【判断】前两类材料能证明「有供给计划与组织信号」；它们不记录客户侧效果。由此推断两类证据的公开密度不对称。
> 【假设】以「公开材料里有无同口径成效」作为证据密度的代理指标。若厂商普遍只在私下披露成效，本判断只描述公开面，不代表实际交付无效果。
> 【反证】若出现≥2 个带基线、观察期与复核方式的客户案例，本判断被削弱。
> 【替代解释】交付证据可能已存在但未公开；区分指标：是否有具名客户访谈或合同披露。
> 【下期核对】Anthropic 是否公布首批认证完成人数与真实部署项目；新增案例中带基线+观察期+复核方式的条数。
> 【来源】B1 / D2 / C2 / C3 分级表见证据卡；本轮正文抓超时者标「待快照」。

同一批材料、同一个观察，差别全在**解释与展示**：没有造矛盾，没有越界给建议，读者能复核、能推翻、能下期对照。

## 10. 与验收标准的衔接

- 内容合格看 R1–R10 + C1–C12；**内容合格但展示不合格（P1–P9）仍不得发布**。
- 评级记录需同时写 `content: A/B/C` 与 `display: 通过/退回`。
- 连续 3 期「内容 A + 展示通过」才允许开放付费入口；付费层必须卖功能（跨期台账/全库检索/来源快照/方法论页四选三），不卖更多同类文章。
- **连续性的最低成本形态**：即使尚未建台账系统，每期至少有一句公开回指旧判断并说明新信息是否印证（Stratechery 正文 `...it strongly affirms my initial analysis` 是市场实抓到的最低可行做法）。系统可后建，留痕习惯不能等。
- 本规范与验收标准同版修订；红线只增不减。
