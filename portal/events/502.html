Natalie Meurer：驻场工程师

Natalie Meurer · 访谈

驻场工程师和软件工程的下一步（Natalie Meurer）

这篇是 AI Engineer World's Fair 当天，Latent Space 跟 Sierra Agent Engineering 负责人 Natalie Meurer 的问答。她带着全球一百二十多人，给企业做客服对话式 AI。进 Sierra 之前做过科技政策，自己学的编程，在 Palantir 干了五年。

驻场工程是当天 World's Fair 的一条赛道。Meurer 会前说：驻场一开始是把强技术的人放到客户身边。现在这个头衔在 AI 行业里盖了很多岗——包括 Sierra 叫的 agent 工程师：系统接入、做 agent，还要懂客户怎么运转、产品和最终用户是什么感觉。她认为驻场更多是对客户负责，不是某一套技能；产品和面向客户的工程，可能正在合流。

她给驻场下的定义：这个岗没有统一口径。从一路走来到现在，更清楚的是对客户负责，而不是岗位长什么样、你具体干什么。这份负责有力量。但绑在上面的技能面已经宽到几乎说不清。

她怎么进这个岗：先做科技政策。政策控，边上自学写代码，凭这个进了 Palantir 隐私组当工程师。大约五年，做过执法、防务和基础设施工程。后来去读商学院，想把生意这一维补上。再后来进 Sierra，把 agent 工程这条线立起来。

Palantir 的驻场模型对 Sierra 有影响，但他们故意叫 agent 工程师，不叫驻场工程师。驻场可以指太多东西。他们觉得头衔该写出技术活长什么样，而不只是「围着客户转」。所以选了 agent 工程师。她把 agent 工程看成驻场的子集，或挨着驻场的一种：更具体的面向客户工程，核心是做 agent。

Sierra 做客服：呼入、呼出，把客户系统接到低延迟的语音和聊天 agent 上，也做客服邮件。岗位要数据接入这类技术活，也要品味：设计语音 agent 时，什么听着顺、什么像人。这一截是 agent 工程特有的。

项目不是一上来就有定好的用例。他们跟客户做发现，找两件事的交汇：真难（他们擅长难的），而且对生意有分量。金融里可能从争议处理起：又复杂、又必须做对，还是高情商的对话。信用卡账单上出现一笔欺诈，人会怕，agent 得把人稳住。几乎每个 Sierra 客户，都在往「agent 当前门 IVR」这条路上走：客户来电，第一个接的就是它。

模型层不是大头。他们把 agent 看成一簇编排好的模型。内部一直在评哪个模型适合哪份活，再把评得好的带到客户。真正跟这家客户绑在一起的活，多半在编排层，不在模型本身。有时会接客户自己的模型，也会帮客户用平台、自己做 agent。很多活是帮他们把自己内部的知识和上下文用进去。

定制和可复用是混着的。每个客户做的 agent 都故意贴这家组织：跟这个品牌打交道，就该是最好的那一次。有些能力更能复用，比如按知识库答题。金融、医疗、旅行酒店、零售，他们有行业的人，带着领域知识和做法。但卖点根本上是定制。跨行业的大组织，他们见过 40 到 60 天就进生产。每个 agent 仍按客户的 API、系统、标准作业、品牌和语气来裁。

多 agent 架构花样很多。「agent」可以指接电话的那个，也可以指子 agent，甚至一个带工具的 prompt。每家企业都想知道：这套 agent 生态能干的事，怎么维护。接入要管，往里贡献的团队也要管。这里面有一部分是变革管理。Sierra 倾向一个 agent 管整段客户交互，不管底下是哪段子任务。子任务他们叫 journeys。企业仍然需要一种办法，让成百上千的人能往这些系统里贡献、看清什么在变、走离散的发布流程。

客户内部能力上来之后，驻场会怎么变？她认为还会面向客户。但代码写起来变便宜了，把客户洞察直接做成产品也更容易。产品工程和驻场工程因此在合流——至少两边最好的那些人是这样。做产品的该跟客户聊；做驻场的该把产品做出来。她觉得这是新的。面向客户仍然重要。就算有接近 AGI 的推理模型，每次都能自己琢磨流程，你还是得把流程编对。你不会希望系统第一十万次处理退货时，自己另想一套。你要的是它按同一套走。所以客服跟别的 agent 场景不一样：写代码的 agent 常常在解第一次碰到的新题；客服是同一道题，换个说法，一周可能十万次。平台、以及帮客户把规则编进去的伙伴，需求就不一样。agent 会越来越好做，但永远需要能跟客户一起干活、再把学到的写进产品的人。

开发者会不会越来越需要产品和面向客户的本事？她信这个，最好的开发者会补上。很多人在问一两年后工程岗长什么样。一种看法是专家更重要，因为他们有 agent 不容易拿到的知识。另一种她更倾向：通才会更值钱。驻场历史上就是典型的通才岗：工程加上面向客户。所以驻场——或者 agent 工程师——处在 AI 和工程里最往前看的那一块。

「agent 工程师」会不会变成默认叫法？她说不准。她预期整个工程会走向更整的定义，把现在叫驻场的那部分收进去更多。市场上现在有 GTM 工程师、驻场工程师、agent 工程师、AI 工程师。她觉得这些都会变成工程手艺的不同面。也会冒出工程师要干的全新岗位。
