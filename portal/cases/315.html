公司自己讲的数字 · 比较可靠

一个 agent，每一扇门：StoreEase 怎样把需要的时刻变成能持久的忠诚

在自助仓储这一行，大家卖的都是一盒盒空气。一家运营商跟另一家拉开差距的，是出了事时怎么待你。StoreEase 的 CTO David Wu 这样描述这个行业：一家设施里的储物单元，看上去跟街对面下一家运营商的差不多——CEO Josh Boyd 也持同样看法。StoreEase 的生意就押在这一点上，数字也站得住：在 StoreEase 管理的设施上，客户停留时间是行业常态的 1.4 倍，终身价值几乎是行业常态的两倍。Wu 说，这一切归结为真正理解客户。

「我们的客户是在需要的时刻来找我们的，」Wu 说。「没有人某天早上醒来会说：『我一直想租一个仓储单元。』他们来，是因为生活里刚发生了什么变故。」搬家、缩小居住面积、工作调动、离婚、家里有人身故。自助仓储很少是一桩高兴、低利害的购买，人们存进去的东西，通常比这笔交易本身更要紧。Wu 说，这个时刻服务得好，客户会留下来好几年；服务得差，关系还没真正开始人就走了。把这个时刻服务得始终如一——任何钟点、任何通道——现在是 Amber 的工作。

一个 agent，客户可能出现的每个地方

这个行业历史上，服务被人手封顶。一家设施能有多可用，取决于柜台后面那个人有多可用，于是就是锁着的大堂门、一块指向网站的牌子、一扇营业时间很少能对上真正危机的客服窗口。StoreEase 的答案是 Amber：建在 Sierra 上的 AI agent，在客户可能伸手去够的每个通道上始终出现——每一条通道都由 EaseOS（StoreEase 的自助仓储操作系统）里的一个产品驱动。电话上，Amber 一天 24 小时在，没有语音信箱，也没有「请在办公时间再打回来」。网上，Ease Web Assistant 接更愿意在线自助的客户。现场，StoreEase 的 Ease Virtual Console 开始把同一个 agent 带进设施大堂本身，好让走进来的人永远不必站在锁着的门前读二维码。

「有了 AI，就像培训一名员工，并且知道整个队伍都遵守同一套规则，」Wu 说。历史上，管一支分散的设施员工队伍意味着不断出差，只为让所有人对齐；经理一周周在地点之间跳，就为几小时当面时间。把服务集中到一个培训一致的 agent 上，把那笔开销整个拿掉，同时给客户的体验比一支轮换、人手稀的队伍所能给的更好。

从漏缴到锁门

StoreEase 的 agent 今天跑接近 30 条不同旅程。付款排在最前：没开自动扣款的租户缴月费，或问滞纳金，全部直接经 EaseOS 操作系统里内建的安全支付流处理。接下来是门禁问题，包括更棘手的一种：租户因漏缴被「overlocked」（加锁）。agent 识别原因，发送付款链接，确认付款，然后在设施管理系统确认账户已缴清之后，恢复门禁并分享大门密码。最后这一步，反映的是 Wu 和 Sierra 给 agent 定下的设计哲学：Wu 所谓「constrained beats improvising」（约束胜过即兴）。每条旅程都是强制工作流，agent 不能走到外面去。它把门禁和账户信息挡在真实认证和良好存续后面，而不是为了「显得有帮助」绕过安全。它维护一份不会回答的问题清单，每一条都是测试里真正出现幻觉之后加上的。而且，租户门禁到底有没有被恢复，永远以设施管理系统——而不是 agent 自己的判断——为最终结论。

EaseOS：从正确答案到正确动作

那些旅程每一条的终点都不在对话里——过一笔款、查实时库存、让门禁系统开门。一个自己做不了这些动作的 agent，不过是会说话的语音信箱。StoreEase 与 Sierra 的合作补上的就是这个缺口：Sierra 给 Amber 推理和对话，EaseOS 给她手，把自助仓储所跑的设施管理系统、门禁厂商、支付处理商和上架通道，归一成 agent 能采取的一组动作，护栏建在动作本身里，而不是 prompt 里。这套系统不只是 StoreEase 自己的优势。公司把它提供给行业其余部分，并接到自助仓储生态里大多数流行软件选项。「StoreEase 的平台是为了让典型自助仓储生意用的那一堆不同系统能无缝运转而建的，」Wu 说。「把 AI 接到这套 harness 上，让任何运营商都能轻松插上，最快两周就能看见 agent 在自己的生意里干活。」

账本两边的结果

收入这一侧，最清楚的信号出现在 StoreEase 经 agent 上线端到端租赁之后。以前下班后打进来、以语音信箱结束的电话，现在直接转化——就在生意以前根本没人值班接听的那些钟点。那些下班后接起的电话，转化成数百条新线索、额外 2–3% 的搬入，以及数十万美元增加的 LTV——生意的一项主要收入指标。而贯穿始终，客户评价——StoreEase 盯得最紧的指标，因为一次糟糕体验才是真让运营商丢掉留存的东西——保持平稳，没有下滑。成本这一侧，StoreEase 能在接入更多设施的同时，用更少的人/站点去支撑它们，而不是编制跟组合规模齐步走。agent 现在端到端消化 65% 到 70% 的服务电话，不必升级到人。

下一步

StoreEase 正在设施大堂里试点 Ease Virtual Console，让 Amber 当面迎接走进来的客户，并在请求超出 AI 能解决的范围时，升级到与人工坐席的实时视频通话。还早，但据 Wu 所知，这也是行业里唯一一次认真尝试，把 AI-native 服务带进物理设施本身。「如果客户关系总体上在朝这个方向走，而 AI 只会随时间把这些互动做得更好，」Wu 说，「那你就会想在客户可能来找你的每个通道里，都有同样质量的互动。要在现场做到这一点，唯一办法是把那条通道也数字化。」对一个建在卖一模一样的盒子上的行业，StoreEase 押的是盒子周围的体验——无论客户何时、以何种方式出现，都可用、一致、可信——才是真正能换来长期忠诚的东西。

给负责人

要解决什么
在搬家、离婚、身故等生活事件带来紧急需求时，通过电话、网页和大堂 24/7 服务自助仓储客户——并且能行动（付款、开闸），而不只是说话。
结果
非工作时间端到端租赁：数百条新线索、额外 2-3% 迁入、LTV 增加数十万。智能体端到端拦截 65 到 70% 的服务来电。客户评价保持稳定。StoreEase 管理设施上的客户停留时间长 1.4x，LTV 接近行业常态的两倍（公司基线，并非完全归因于 Sierra）。
接了哪些系统
Sierra 推理 + EaseOS 动作框架；对接主流自助仓储软件；其他运营商最快两周即可接入。
用了什么数据
EaseOS 设施管理、门禁、支付处理商、挂牌渠道；身份验证与良好状态检查。
人还管哪一步
大堂 Virtual Console 无法解决时升级到与真人视频；约束优于即兴。
多久上线
其他运营商：智能体最快两周可用（Wu 原话）。
怎么交给客户
David Wu, CTO；Josh Boyd, CEO。

给现场的人

主要用在哪
Amber：24/7 电话、Ease Web Assistant、大堂内 Ease Virtual Console；付款、滞纳金、解除逾期锁 + 闸门密码。
以前怎么干
服务受现场人手上限：大堂上锁、语音信箱、营业时间错过危机；经理在各站点奔波以对齐员工。
卡在哪
非工作时间租赁来电死在语音信箱；逾期锁/门禁和付款需要经认证的操作。
用了什么模型
Sierra AI 智能体（Amber）。
事情怎么流转
约 30 条强制旅程；付款链接；逾期锁查明原因/付款/恢复通行；设施系统为事实源；测试出现幻觉后建立拒答清单。
怎么验收
服务来电拦截率；非工作时间线索/迁入/LTV；客户评价保持稳定。
怎么上线
电话 + 网页已上线；大堂 Virtual Console 试点中。
失败了怎么改
维护智能体拒答问题清单，每条都在测试中真实幻觉后加入。
能不能复用到下一家
EaseOS + Sierra 提供给其他运营商；大堂 Virtual Console 试点。
有了 AI，就像培训一名员工，并确信整个团队都遵循同一套规则。——David Wu, CTO, StoreEase

Sierra 官方客户页。第一方：65-70% 拦截率、额外 2-3% 迁入、数百条新线索 / 数十万 LTV。1.4x 停留 / 约 2x LTV 是 StoreEase 管理设施基线。
