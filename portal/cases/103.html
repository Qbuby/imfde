Factory · 制造工业

Chainguard

公司自己讲的数字 · 比较可靠

两周、一次会话、无穷软件包

和大多数真实的工程问题一样，我们的用例需要来自多个上游源和多个内部仓库的大量上下文。特别是在 Chainguard，我们同时处理内部代码库和不断增长的开源生态系统。

Josh Wolf 是 Chainguard 的 Staff Engineer，他试过 AI 工具生态里所有能找到的记忆方案，包括 memory MCP、memory 工具、自定义 SDK。Chainguard 的工程团队在大型代码库上工作，不断有上游包更新和需求涌入，还要通过严格的工程评审流程，每一步都需要上下文。现有工具跟不上。

Josh 开始用 Factory 时，也以为会遇到同样的限制。结果他发现自己连续跑同一个会话两周，上下文感知和质量都没掉。Factory 的压缩引擎让上下文跨会话保留，在 Josh 看来就像和一个记得住事的同事一起工作。

现在大家都在吹不同 agent 的记忆在变好。当你不用操心上下文窗口时，你就能把 Droid 当成一个同事，它记得你们聊过什么。

这对 Chainguard 的工程组织很重要，因为他们的工程流程不只是写代码。Josh 的日常工作从 brainstorm 复杂想法，到把想法拆成可交付的设计文档让同事评审支持，最后上线生产。代码现在很便宜，brainstorm 和设计工作不便宜。

在 Chainguard，交付安全的开源软件往往遵循可识别的模式。某种东西按某种方式构建后，这些模式就能复用，去规模化构建未来多个迭代。

我可以像带 junior engineer 一样启动一个 Droid 会话，自然地教它执行任务一两次，我们一起做。然后我就拥有了一个 senior engineer，能独立运作，只需很少干预。

Josh 的日常工作包含多个长时间运行的会话，通常在同一个项目的不同部分，他自己管理 git work tree 来隔离 agent。他试过 Claude Code、Codex 以及其他工具。

我最关心的是 compaction。其他工具有些小功能我放弃了，因为这个方案就是能用，而且用得很好。

Factory 给 Chainguard 带来的不是更快的自动补全或更好的代码生成器，而是能把一条工作线程从最初的 brainstorm 会话一直维持到工程评审，再到生产部署，跨好几天。为什么做这个决定、考虑过哪些替代方案、评审反馈是什么，所有这些上下文都保持可访问。

能有东西突破其他工具的当前限制，这很宝贵。对于一家大规模构建可信开源软件、评审流程要求工程师在每一步解释思路并对产出负责的公司来说，Factory 的会话连续性改变了可能做到的事。不是让代码更便宜，代码本来就便宜，而是让工程对话持久。

Chainguard 跑了一个 Droid 会话两周，跨六个仓库，构建了 80 个包，没有丢失上下文。当你不用操心上下文窗口时，你就能把 Droid 当成一个同事，它记得你们聊过什么。

给现场的人

主要用在哪
跨六个仓库、为期两周的连续 Droid 会话，构建了 80 个软件包，上下文从头脑风暴保持到工程评审和生产部署。
以前怎么干
Staff engineer Josh Wolf 试过 memory MCP、记忆工具和自定义 SDK。日常工作覆盖头脑风暴、同事评审的设计文档，以及交付生产。同一项目不同部分上多个长时间会话，用 git worktrees 隔离智能体。还试过 Claude Code、Codex 和其他 CLI 智能体。
卡在哪
用例需要来自各种上游源和多个内部仓库的上下文。上游软件包更新不断涌入，严格的评审流程要求每一步的上下文。其他 CLI 智能体需要精心整理 skills 和命令来填充上下文窗口。
用了什么模型
Factory Droid（压缩引擎）。页上与 Claude Code 和 Codex 比较；未点名具体底层模型。
事情怎么流转
像带初级工程师一样把任务教给 Droid 一两次，然后让它以最少干预独立运作。同一项目不同部分上多个长时间会话并行。
怎么验收
会话时长（两周）、保持在上下文中的仓库（6）、构建的软件包（80）。定性：为何做某决策的上下文仍可取用。
怎么上线
Chainguard 工程工作流中使用长时间 Droid 会话。页面未公布全组织推广规模。
失败了怎么改
Josh：试过所有 memory MCP/工具/SDK — 没有一个兑现承诺。其他 CLI 智能体需要整理 skills/命令来填充上下文窗口；用 Droid 他不必这样做。
能不能复用到下一家
可复用模式：一旦以某种方式构建，这些模式可复用于该软件的后续迭代扩规模。
我一直跟 Matt（Moore，CTO Chainguard）说，我同时跑着多个已持续数周的 Droid 会话。因为压缩就是这么好。——Josh Wolf，Staff Engineer @ Chainguard

Factory 官方案例（2026 年 1 月 30 日）。页上第一方量化：6 个仓库、2 周会话、80 个软件包。具名 Staff Engineer Josh Wolf；Matt Moore 具名为 CTO Chainguard。无全组织采用百分比或周期倍数。
