原文

中文全文还在写入。下面两栏是已经拆过的字段。

给负责人

要解决什么
企业里 agents 被孤立地部署，缺乏共享业务上下文，每加一个 agent 反而增加复杂度；需要端到端地构建、部署和管理能真正干活（do real work）的 AI coworkers
接了哪些系统
与 systems of record 集成：数据仓库、CRM、工单工具、内部应用；基于开放标准，不强制 replatform；支持自研 agent、OpenAI agent 与第三方 agent
用了什么数据
data warehouses、CRM systems、ticketing tools、internal applications
人还管哪一步
human managers 通过内置评估与优化机制看到什么有效、什么无效，从而改进 agent 行为
怎么交给客户
建立你的团队可长期拥有并扩展的可重复模式

给现场的人

主要用在哪
AI teammates（数据分析、财务预测、软件工程）；Business processes（收入运营、客户支持、采购）；Strategic projects（跨部门高价值专项）
以前怎么干
agents 各自为政，能看到和能做的事情都被隔离；数据分散在多个云、数据平台和应用里
卡在哪
系统碎片化、治理分散；agent 缺少足够上下文，每次集成都变成一次性项目；模型能力与实际能部署的能力之间出现 opportunity gap
用了什么模型
OpenAI 模型（对时效性任务优先提供低延迟访问）；未指定具体模型名
事情怎么流转
三层架构：Business Context（共享语义层 + 机构记忆）→ Agent Execution（推理、文件处理、运行代码、调用工具，多 agent 并行）→ Evaluation and Optimization（评估优化闭环，agents 随运行积累 memory）
怎么验收
内置 evaluation and optimization 循环，使 agents 随经验改进；Observability：agent 动作可见、可审计，留存详细日志
怎么上线
agents 可跨本地环境、企业云基础设施与 OpenAI 托管 runtime 运行；每个 agent 有独立 identity、显式权限与 guardrail；通过 SOC 2 Type II、ISO/IEC 27001/27017/27018/27701、CSA STAR
能不能复用到下一家
Frontier 作为平台产品化；Enterprise Frontier Program；Frontier Partners 计划（Abridge、Clay、Ambience、Decagon、Harvey、Sierra）
Enterprise Frontier Program 把来自 The OpenAI Deployment Company 的前线部署工程师与你的团队配对，共同设计架构、把治理落地，并在生产中运行智能体——建立你的团队可长期拥有并扩展的可重复模式。

备注

OpenAI 官方产品页，架构、治理、评估与 FDE 交付模式描述具体，但无单个客户的落地细节
