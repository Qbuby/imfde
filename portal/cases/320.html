Behind the Build：GoFundMe 如何把筹款创建重做成一场对话

Behind the Build 是一系列，Sierra 客户讲他们怎么设计、部署和规模化 AI agent。多数创建 GoFundMe 的人以前从没做过。他们不是营销人或讲故事的人。他们是孩子刚拿到诊断的家长。火灾后号召支持的邻居。想帮朋友的朋友。他们在人生一些最难的时刻来到平台——脆弱、不堪重负、面对一张空白页。这份张力让 GoFundMe 产品团队从头重想筹款创建。产品经理 Taruvar Aggarwal：「我们预期组织者来，分享标题、写故事、想出目标、加图片，然后把筹款发布给世界看，而他们以前从没做过。对一个正在经历人生最难处境的人，这要求太多了。」

GoFundMe 一直相信人的教练的力量：一位有知识、有共情的向导能帮组织者更有效地讲故事、触达更多捐赠者。挑战是规模。团队开始问：把这种教练体验扩到数百万场筹款会是什么样？今天，有人在 GoFundMe 上开始一场筹款时，迎来的是一场对话。由 Sierra 驱动的 agent 问他们的处境，给提示，帮他们建故事、标题、目标和一组图片，而不让组织者觉得只是在填表。结束时他们有一份完整筹款，过程更像被引导的支持。agent 从数百万场过往筹款的知识里抽指导，真正有上下文。如果你在为生病的宠物筹款，它也许会建议加一张你们俩的合影，或附上兽医账单，因为那些细节帮捐赠者接到你处境的现实。Aggarwal 说目标是「以能引起共鸣的方式」引导人，同时永不牺牲故事的真实性。「不是要他们写出一篇只是技术上读起来好的故事。你不是在拿走他们写真实故事的能力。」

评影响时团队做了故意选择：不为发布率或发布用时优化。那些数字从来不是重点。他们问更难的问题：他们是否真的在困难时刻给了组织者创建筹款内容所需的支持？他们用调查、定性访谈和基于 LLM 的评测理解组织者对体验的感觉。结果惊人。65% 到 75% 的组织者说 agent 让筹款感觉压力更小。他们感到更被支持。也许最有意义的：在筹款旅程里他们感到不那么孤单。Aggarwal：「最后那条对我非常有意义，因为那就是我们在试着做的。」定量结果跟着来。组织者募到的捐款多 5%，基于早期结果，这可能在美国今年带来估计 $125 million 的额外帮助。但对 GoFundMe 团队，那些数字次于他们真正在追的东西：一个正在经历危机的人，有一位教练帮他把故事写成字、在最需要时开口求支持。

走到那里不只是技术挑战。Aggarwal 说得很清：从试点到生产本质上是组织问题。写 agent 的任何代码之前，他们建了治理委员会，把法务、营销、政策和跨职能团队拉进房间，定义 agent 能做什么、不能做什么。他们跑了数百万次模拟和红队演练。他们按设计把范围收窄，按地理、用户画像和生命周期阶段限制最初上线。不是缺野心，是理解信任必须先挣到才能扩展。「信任是脆弱的，」Aggarwal 说。「甚至在你想试点之前，请先建那些治理结构。」他们也抵抗衡量一切的拉力。选一小套反映他们真正在意的指标，忽略不相关的，给团队清晰度，把工作钉在原初意图上。

给负责人

要解决什么
危机中第一次做筹款页的人面对空白页（标题、故事、目标、图片），在数百万筹款页规模下没有人在旁辅导。
结果
65–75% 的组织者表示智能体让筹款感觉压力更小；他们感到更被支持、更不孤单。组织者多筹到 5% 捐赠——基于早期结果——估计今年可在美国额外筹集 $125 million 援助（页面自己的估计）。
接了哪些系统
GoFundMe 筹款启动流程中的 Sierra 智能体。
用了什么数据
来自数百万过往筹款页的知识；调研、定性访谈、基于 LLM 的评估。
人还管哪一步
治理委员会定义能做/不能做；因信任脆弱而初始范围很窄。
怎么交给客户
Taruvar Aggarwal, product manager, GoFundMe。

给现场的人

主要用在哪
对话式筹款页创建：情境 → 故事、标题、目标、图片；按情境给提示（例如宠物 + 兽医账单照片）。
以前怎么干
期望组织者没人帮也自己写完并发布；有人工辅导但铺不开。
卡在哪
在人生最艰难的时刻，要求人们表现得像营销人员。
用了什么模型
Sierra 驱动的创建智能体。
事情怎么流转
询问情境；给出提示；帮助撰写故事/标题/目标/图片；给情境化建议但不拿走真实故事。
怎么验收
刻意不优化发布率或发布时间。用调研 + 访谈 + LLM 评估压力/支持感/孤独感；捐赠提升。
怎么上线
按地理、画像、生命周期阶段有限初始推出。
失败了怎么改
抵制衡量一切；小指标集绑定最初意图。
能不能复用到下一家
Behind the Build 系列；治理优先的智能体推出。
