Behind the Build：Paychex 押注 AI 能感觉像本地办公室一样个人

Paychex 给美国十一分之一的私营部门工人发薪。对靠它付账单、养家的中小企业及其员工，payroll 不是行政。是生存。公司 1971 年建在本地关系上：你镇上的一间办公室、一个知道你名字的人、「我认识你因为我认识你」的服务模型。但业务规模化、产品套件扩到退休计划、HR、福利登记等之后，那份亲近更难维持。

摩擦可预期地出现在日历上最忙的几周。圣诞和新年那周通话量激增，常常超过 Paychex 的人员产能。结果：延长的等待、员工强制加班、服务代表并不总有知识处理每个问题。运营与客户体验 SVP Liz Roaldsen：「想象你想去孩子学校的节日音乐会，刚被告知必须强制加班。人们想要工作生活里的可预期。」客户这一侧，往往已经在楼里戴着每顶帽子的企业主，在等一件现在就需要发生的事。预期还在升。Liz 称为「我们所做一切的 Amazonification」。

Paychex 着手为 payroll 处理建语音 AI agent 时，简报超出自动化电话。是：交付即时、全天候 payroll 处理，达到人的准确度……并让它感觉不费力。声音、问候、信息被捕捉的速度，每项对着单一标准衡量：这感觉本地、人性、被信任、可依赖吗？使用 agent 的人的早期结果验证了做法：95% 正面客户满意度分数，93% 正面客户费力分数，试过 agent 的客户会回来再用。「那就是证明，」Liz 说。「他们在再用。他们给高分。它以出色准确把活干完，我们的团队有更多时间花在客户身上。」

真正的工作是变革管理。团队缩短了问候、压缩了法律套话、按持续反馈迭代。技术持续改进。更大的挑战是说服客户先试，而这一次电话一次电话发生。有人意识到 agent 不是他们在防备的痛苦 IVR 体验时，什么东西咔嗒对上。Paychex 按设计保持耐心：证明概念、收集数据、让体验自己说话。

对 Liz，故事最重要的部分是 agent 周围发生的事。Paychex 大约有 700 名 HR 业务伙伴，就吸引人才、福利和合规等 HR 事项提供深、专家级指导。agent 处理事务性量——「这周给 Tracy 记十小时」这类电话——好让服务代表出现在需要人的专长和判断的时刻。Liz：「录入你的 payroll 那些要紧时刻，大概不是客户希望我们花时间的地方，反过来也是。我们想被知道的是：有人提供深度专长，并借助 AI 使能的技术。」它也给服务员工不那么有形但同样宝贵的东西：可预期。能九点来五点走。能做站得住的托儿安排。Liz 给还在观望的 CX 领导的忠告：从业务问题开始。「对我们，业务问题是尽快给客户接电话。就这么简单。」「那些好处会随时间侵蚀。你得雇人再训人。你有高流失的高占用岗位。知识会淡。那些在 agent 身上都不会发生。」

给负责人

要解决什么
提供全天候薪酬处理，体感上像本地 Paychex 办公室一样可信，并消化节假日周的来电高峰，而不强制加班。
结果
使用该智能体者的早期结果：95% 正向客户满意度分数，93% 正向客户费力度分数，以及试用过智能体的客户会再来使用。
接了哪些系统
Paychex 运营中的语音 AI；根据反馈迭代问候语和法律措辞。
用了什么数据
薪酬处理系统。
人还管哪一步
约 700 名 HR 业务伙伴保留深度 HR 指导；agent 承接事务性量。
怎么交给客户
Liz Roaldsen，Paychex 运营与客户体验高级副总裁。

给现场的人

主要用在哪
事务性薪酬的语音智能体（「这周给 Tracy 记十小时」），让 HR 业务伙伴去做人才/福利/合规专长。
以前怎么干
自 1971 年起的本地办公室亲近感；约 700 名 HR 业务伙伴；节假日周推高等待时间和加班；代表并不总能了解每一款产品（薪酬、退休、HR、福利）。
卡在哪
对即时性的「Amazonification」预期对照人员容量；客户为必须马上发生的事情排队等待。
用了什么模型
Sierra 语音 AI agent。
事情怎么流转
语音全天候处理薪酬；缩短问候；压缩法律措辞；试用过的客户会复用。
怎么验收
客户满意度、客户费力度、试用 agent 者的复用。
怎么上线
语音薪酬 agent 已生产，并公布早期结果。
能不能复用到下一家
耐心、先证明概念的铺开，而不是强迫采用。
