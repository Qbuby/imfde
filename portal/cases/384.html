MongoDB（Atlas API平台团队）

公司自己讲的数字 · 一般

MongoDB Atlas API Platform 团队怎样靠专门的 AI agent 往上扩

故事。把 Augment 的推理能力和 MongoDB 的工程严谨叠在一起，团队把 AI 从助手变成基础设施。扩质量，还不拖慢工程。MongoDB 的 Atlas API Platform 团队是放大器——让数百名工程师在 MongoDB 云生态里做出一致、高性能的 API。保质量要平衡两头压力：守住严格的 API 设计和性能标准；又不能让流程开销拖慢交付。传统自动化（比如 lint 或静态校验）抓不住细的架构或性能问题。团队需要能在大代码库上推理、并适应团队 API 规范的系统。「多数助手盯代码生成，可那从来不是我们的瓶颈，」MongoDB Atlas API Platform 团队工程师 Wojciech Trocki 说。

给负责人

要解决什么
Atlas API Platform 团队（数百名 MongoDB 工程师的力量倍增器）需要在不增加流程开销的情况下守住严格的 API 设计/性能标准。
结果
无数字交付 KPI。已交付 agent：架构校验、对数百 MB CI 日志的隔夜性能分析、动态 API 标准 MCP。引言：最大收益是减少来回，而不是写代码更快。
接了哪些系统
IDE、Augment CLI、MCP 到包括 CI/CD 的内部系统。
用了什么数据
技术规范、内部指南、先前实现、CI/CD 日志、MongoDB API Standards 站点。
人还管哪一步
Agent 在人工审查前浮出风险；「拉取请求甚至还不存在时的反馈」。志愿倡导者。
多久上线
性能 agent 隔夜在大型 CI 日志上运行。

给现场的人

主要用在哪
架构校验 agent（规范 + 指南 + 先前实现）。对 CI/CD 日志（常常数百 MB）隔夜运行的性能分析 agent。动态指南引擎：API Standards 站点作为活的 MCP 源。
以前怎么干
Lint 与静态校验抓不到细微的架构或性能问题。跨职能工作组测试 AI IDE 助手。
卡在哪
代码生成不是瓶颈。需要对架构、测试与标准做推理。
用了什么模型
Augment Code CLI + MCP；专门 agent。无单个模型名。
事情怎么流转
从既有 CI/CD、校验与架构审查工作流调用 CLI agent。
怎么验收
工作组工具评估。无全组织速度表。
怎么上线
Atlas API Platform 团队（页眉：30）。下一步：把可复用 CLI 工作流与 AI 辅助 PR 校验铺到工程。
失败了怎么改
不想要「光鲜的自动补全」。
能不能复用到下一家
四级 AI 成熟度模型；计划面向更广 MongoDB 工程的可复用 CLI 工作流。
CLI 改变了一切。能从我现有工作流——CI/CD、校验、架构审查——直接调用 agent，这才让它对我和我团队里的工程师成真。——Wojciech Trocki，MongoDB Atlas API Platform

备注

官方 Augment 案例。具名 Wojciech Trocki。丰富的 agent/MCP 细节；无数字组织结果。「数百名工程师」是 Atlas API Platform 的既有角色，不是归于 Augment 的人数。页眉团队规模 30。
