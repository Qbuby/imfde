Webflow

公司自己讲的数字 · 一般

Webflow 开发者靠 Augment 有上下文的 AI 建议，留在心流里

故事。深上下文、稳住心流、工具也更成熟。有了 Augment，Webflow 的前端和后端团队能更高效地在复杂技术栈里找路。

挑战。领先的网站体验平台 Webflow，技术栈扎在 JavaScript 生态里，又复杂。难点是把开发者生产力拉满，并让人尽快摸清代码库各块，尤其入职时。专精的前端和后端团队很难高效逛庞大代码库。「我们的技术栈相当复杂。保持一致、把开发放大，变得越来越难，」Webflow 工程总监 Suchitra Hari 说。为什么选 Augment？Webflow 要一个有上下文的 AI 助手，提高生产力、理顺入职。

给负责人

要解决什么
在复杂、对一致性敏感的 JS 栈上提高生产力并更快入职工程师，前端与后端专精者难以导航更广代码库。
结果
无数字 KPI。定性：更少苦活；无自我入职提问；保持心流状态。
接了哪些系统
IntelliJ、VS Code。
用了什么数据
Webflow 前端与后端代码库。
人还管哪一步
具名：Suchitra Hari（工程总监）、Merrick Christensen（Principal Engineer）、Huda Syed（工程经理）。
多久上线
入职被描述为改善；无周/月数字。

给现场的人

主要用在哪
不必手工提供上下文的代码库问答；结对程序员感觉；入职自助。
以前怎么干
与 GitHub Copilot 比较。一位 EM 把 Augment 聊天中的提示工程称为顿悟。
卡在哪
难保持一致性并规模化开发；入职依赖资深人员。
用了什么模型
Augment Code（页上：Context Engine / agent / 补全；除非另有说明，无单个模型名）。
事情怎么流转
聊天 + 补全 + diff 视图接受/拒绝。
怎么验收
定性。无数字表。本页无团队规模数字。
怎么上线
前端与后端团队。
失败了怎么改
Copilot 被当作先前不那么精巧的工具。
Augment 不让你去想上下文，意味着你可以问未知的未知，并得到真正有洞察的回答。——Merrick Christensen，Webflow Principal Engineer

备注

官方 Augment 案例。具名 Suchitra Hari、Merrick Christensen、Huda Syed。无数字结果或团队规模。
