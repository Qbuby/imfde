Pocketlaw 用 Augment 的上下文感知 AI 编码助手加快法律科技开发

故事。AI 优先的法律管理创业公司 Pocketlaw，怎样用 Augment 又快又有上下文的编码助手，理顺开发工作流、提高工程师满意度，并更高效地做出 AI 法律方案原型。

挑战。Pocketlaw 自己在给律师做 AI 工具，工程团队很清楚 AI 能理顺工作流、跟踪知识、少花时间在琐事上。可他们给工程团队找好的 AI 搭档，一直不对。有了 Augment，Pocketlaw 想解掉耗时、重复、拖生产力和满意度的编码活。产品与工程副总裁 Faruk Sahin 说：「做一个大项目时，你有几百、几千个文件，分在不同文件夹里……」

给负责人

要解决什么
在 Copilot 和其他工具不够之后，削减大型多文件夹法律科技代码库中耗时的重复编码。
结果
仅延迟/UX：<100 ms 建议；提问 3 秒对照 3 分钟。无交付 KPI（无 sprint/PR/周期数字）。
接了哪些系统
IDE 内聊天。
用了什么数据
Pocketlaw TypeScript/Python/React 代码库。
人还管哪一步
产品与工程副总裁 Faruk Sahin；开发者接受补全。

给现场的人

主要用在哪
低于 100ms 的补全；从其他文件拉取类型；带标记文件的聊天；更快原型化 AI 法律功能。
以前怎么干
已在 GitHub Copilot 上；CEO 引入 Augment；工程师起初怀疑，直到最初几分钟/几小时。
卡在哪
数百/数千文件；难知道做什么、在哪做；Copilot 在跨文件类型上更弱。
用了什么模型
Augment Code（页上：Context Engine / agent / 补全；除非另有说明，无单个模型名）。
事情怎么流转
Tab 补全 + 文件标记聊天。
怎么验收
延迟主张：下一条建议不到 100 毫秒。提问门槛：三秒对照其他工具的三分钟。
怎么上线
团队规模 38。高满意度被定性陈述。
失败了怎么改
先前寻找 AI 伙伴一直不够；Copilot 已在使用。
它极其快。你看到下一条建议不到 100 毫秒。对人眼几乎感觉是即时的。——Faruk Sahin，Pocketlaw 产品与工程副总裁

备注

官方 Augment 案例。具名 Faruk Sahin。量化主张是延迟/UX（<100 ms；3 秒对 3 分钟），不是交付结果。团队 38。
