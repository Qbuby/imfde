公司自己讲的数字 · 一般

AMP 用 Augment 的低延迟 AI 代码助手理顺机器人软件开发

故事。AI 回收方案领先者 AMP，怎样用 Augment Code 优化软件开发。靠低延迟补全和多语言支持，AMP 的资深开发者少敲键盘，把精力放到复杂的机器人任务上。

挑战。AMP 给废弃物和回收提供规模化 AI 分拣，需要管先进回收设施上的复杂代码库。团队语言很多：嵌入式用底层 C 和 C++，上层应用用 Rust、Python 和 JavaScript。这种多样环境要求跨很多框架和库保持一致，同时少出错、加快开发。

给负责人

要解决什么
让资深机器人开发者在嵌入式 C/C++ 与更高层 Rust/Python/JavaScript 之间保持心流，而不淹没在样板与协议管道里。
结果
无归于 Augment 的数字工程 KPI。定性延迟/上下文/多语言收益。不要把 AMP 的 1500 亿件 / 240 万吨 / 400 套系统当作 Augment 结果。
接了哪些系统
VS Code。
用了什么数据
AMP 巨型多语言仓库。
人还管哪一步
资深开发者留在真正的工程问题上。

给现场的人

主要用在哪
多语言补全（C 到 JS）；带 Git-diff 视图的复杂重构；注释/描述性代码。
以前怎么干
跨语言的呼叫-响应 / pub-sub 连接组织；先前工具缺乏来自巨型仓库中分散文件的上下文。
卡在哪
乏味管道、schema/协议、高延迟或无视上下文的补全。
用了什么模型
Augment Code（页上：Context Engine / agent / 补全；除非另有说明，无单个模型名）。
事情怎么流转
即时短补全；重构 diff UI。
怎么验收
对照先前工具的定性。公司级 1500 亿件 / 240 万吨 / 400 套 AI 系统是 AMP 业务统计，不是 Augment 结果。
怎么上线
团队规模 150。
失败了怎么改
先前工具缺乏分散文件上下文。
延迟让我震撼。试 Augment 之前我没意识到低延迟有多重要……它让我保持心流而不挡路。——Carter Schultz，AMP 机器人架构师

备注

官方 Augment 案例。具名 Carter Schultz。团队 150。结果定性。AMP 分拣量统计是公司背景，不是 Augment KPI。
