Sourcegraph 帮 CERN 在任务关键应用里对付代码复用和代码变更

Sourcegraph 的通用代码搜索帮 CERN 的 300 名开发者避免重复、减少技术债、找出可复用代码，省时间、促协作。CERN 的物理学家用世界上最强的一些粒子加速器，发现宇宙由什么组成、怎样运转。过去 18 年，该组织加速器控制的 Java 代码库长到大约 15 million 行。CERN 在一套自包含软件系统里运转，由将近 300 人开发和维护，全部代码都在 Sourcegraph 里。要高效开发和安全升级，开发者需要能迅速、有效地搜遍整份代码库的工具，好在需要时轻松改和复用代码。

给负责人

要解决什么
在一套自成一体、历时 18 年、约 15M 行的 Java 控制代码库中搜索，让约 300 人能复用代码、安全演进 API，且不让 LHC 停机。
结果
约 300 名开发者；18 年间约 15 million 行 Java，全部在 Sourcegraph。结果为定性：复用而非重写、减少技术债、能够衡量此前会挡住必要变更的 API 变更影响。无小时数/百分比数字。
接了哪些系统
通用/语义代码搜索被用作复用与变更管理的首选工具。
用了什么数据
全部加速器控制代码都在 Sourcegraph（约 15M LOC Java；约 300 人）。
人还管哪一步
库所有者在演进 API 前用搜索查看所有 API 客户端。团队仍自己做变更。

给现场的人

主要用在哪
找到已有实现以便再利用；发现已弃用/内部 API 使用；把工具类抽到核心库；衡量 API 变更的爆炸半径；在升级窗口识别冗余方法。
以前怎么干
先前的搜索「没法让我们对某个特定类的方法如何、在何处被使用做详细而精确的搜索」，因此计划中的 API 变更被跳过。
卡在哪
重复、已弃用/内部 API、困在特定项目里的工具类。LHC 需要在 5 年运行期内保持稳定；1–2 年升级窗口允许更激进的变更。出错可能让加速器停机。
用了什么模型
Sourcegraph 通用代码搜索（语义）。未点名 Cody/LLM。
怎么验收
定性：「无数小时」没有重做工作；有信心去做代价高昂的变更。无数字时间 KPI。
怎么上线
所述全部控制代码都在 Sourcegraph；约 300 名开发者。
失败了怎么改
先前工具无法回答「这个类方法在哪里被使用」，因此必要的 API 变更没有做。
Sourcegraph 帮助我们减少技术债并整合代码库：让我们避免重复，发现已弃用 API 或内部（非 API）库代码的使用，并识别特定项目中的通用代码（如工具类），以便抽到核心库中共享。——Chris Roderick，Applications and Services Section Leader，CERN

备注

Sourcegraph 官方案例（抓取 2026-08-29）。具名 Vito Baggiolini 和 Chris Roderick。300 名开发者 / 15M LOC / 18 年 / 5 年 LHC 运行 / 1–2 年升级是页上规模，不是 Sourcegraph KPI。「无数小时」不是数字。
