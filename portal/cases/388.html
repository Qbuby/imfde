Augment Code · 软件科技

Kong

公司自己讲的数字 · 一般

Kong 用 Augment 的 AI 编码平台让开发者更专注、跨语言协作更好

故事。Kong 管着复杂的微服务架构，开发者生产力和协作都有坎。Augment 帮他们理顺开发流程，让工程师把精力放到更高层的解题上。

挑战。Kong 跑一套 API 管理平台，撑住身份、授权、审计日志、通知等关键内部服务。技术栈包括 Go 微服务、TypeScript 应用、PostgreSQL 和 DynamoDB，部署在复杂的 Kubernetes 环境里。开发者常常被重复活和语言切换拖住，很难盯更大的工程题。团队全球分布式，协作也不容易。

给负责人

要解决什么
让开发者在多语言微服务/Kubernetes 平台（身份、授权、审计、通知）上专注高阶问题，并改善全球协作与入职。
结果
无数字 KPI。定性：更少上下文切换、更一致的骨架、更好的文档/测试焦点。
接了哪些系统
VS Code、IntelliJ。
用了什么数据
Go 微服务、TypeScript 应用、Postgres、Dynamo、Kubernetes。
人还管哪一步
工程师细化生成的骨架并拥有边界情况测试。

给现场的人

主要用在哪
跨语言工作（Go/TypeScript）；像对五岁小孩解释的入职；骨架/测试生成；文档 / OAS 驱动生成被讨论为推动。
以前怎么干
重复编码以及 Go 与 TypeScript 之间的语言切换；分布式全球团队。
卡在哪
上下文切换税；入职难；样板与测试骨架手工写。
用了什么模型
Augment Code（页上：Context Engine / agent / 补全；除非另有说明，无单个模型名）。
事情怎么流转
IDE 内生成骨架与测试；选中并解释。
怎么验收
定性。无数字表。
怎么上线
团队规模 234。
Augment 非常有帮助，让我专注于解决问题，而不是去写解决那些问题的代码。——Nick Anderson，Kong 高级工程师
