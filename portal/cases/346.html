FactSet 从 Perforce 迁到 GitHub

FactSet 用 Sourcegraph 提高开发者效率：能在 12,000+ 个仓库里高效搜代码，少做重复活，保证一致性，并在从单体 Perforce 迁到 GitHub 微服务的过程中提高代码复用。

用 Sourcegraph 之前：迁到微服务后没法跨仓库搜索；不了解现有代码，导致不必要或重复的代码；很难在全公司保证一致。用上之后：能用任何语言（包括 C++）搜全部 12,000+ 个仓库；工程团队不再重复干活；能从代码库里找例子复用，一致性更好。「有了 Sourcegraph，我们才能从 Perforce 顺滑迁到 GitHub。」

给负责人

要解决什么
在 2019 年 Perforce→GitHub 微服务迁移期间恢复代码搜索，使团队（尤其是市场数据）能在 12,000+ 仓库中找到类实例，并停止用 30 种方式重写同一套图表。
结果
跨全部 12,000+ 仓库搜索（任何语言，包括 C++）。超过 500 名 FactSet 开发者使用 Sourcegraph。对 200+ 队列的调查：每天或每天多次使用。页上：消除重复努力；复用示例以保持一致。无数字节省工时 KPI。
接了哪些系统
先部署到实时新闻与报价引擎，然后 200+ 开发者，然后 500+。
用了什么数据
12,000+ 仓库包括 C++；摄入交易所数据的市场数据平台。
人还管哪一步
开发者复制/复用找到的示例；Developer Services 开每周迁移会。
多久上线
从第一个团队铺到 200+ 然后一个月后调查；当前数字是 500+ 用户。除 2019 年 Perforce 迁移开始外，未给出精确日历跨度。

给现场的人

主要用在哪
跨 12,000+ 仓库搜索所有语言包括 C++；复用图表/库示例；市场数据类实例查找。
以前怎么干
单体 Perforce。前 20+ 仓库迁到 GitHub 后，市场数据（同一模板的约 100 个子类）再也搜不到代码。Developer Services 每周与开发者开会。
卡在哪
新员工常常不懂 Perforce。迁移中期的搜索缺口。冗余实现与不一致的风险。
用了什么模型
Sourcegraph 代码搜索（未点名 Cody/LLM）。
怎么验收
扩展到 200+ 开发者后的用户调查：强烈偏向每天或每天多次使用。现在 500+ FactSet 开发者使用 Sourcegraph。
怎么上线
实时新闻/报价先 → 200+ 开发者 → 500+ 开发者。
失败了怎么改
离开 Perforce 后失去搜索。原生 GitHub 搜索对市场数据模板/类模式不够。
有了 Sourcegraph，我们能够从 Perforce 平滑过渡到 GitHub。——Derrick Faunce，Associate Director of Developer Services

备注

Sourcegraph 官方案例（抓取 2026-08-29）。具名 Derrick Faunce 与 Joseph Majesky。12,000+ 仓库与 500+ 用户在页上。其后结果是定性（复用、一致性、「平滑过渡」）。无小时/% KPI。
