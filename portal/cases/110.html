公司自己讲的数字 · 比较可靠

SafetyCulture 如何用 Glean 有效扩规模、将搜索时间缩短 50%，并用 Agent Builder 走向 AI-first

SafetyCulture 是一家全球科技公司，助力一线团队每天改进工作。他们的移动优先运营平台每年处理超过十亿次检查，每天提供约 85,000 条经验教训，覆盖 180 多个国家的 200 万用户。

在快速扩张期，工程团队人数增长 50%，新工具不断引入，内部调研发现知识搜索成了最大痛点。数据散在多个应用，知识孤岛明显，员工希望获得更多上下文。

SafetyCulture 考虑过自建方案，但不想让工程师从零做企业搜索和 AI 平台。他们需要开箱即用的工具，能给出可信搜索结果、加速全公司流程，并提供安全统一的 AI 平台，于是选择了 Glean。

实施前，工程师每周手动搜索内容的时间最长达四小时。Glean 上线后，搜索时间立即减少 50%，返回的结果带有完整上下文、细微差别和引用。Glean 迅速成为公司默认的原生搜索工具。

Glean 的 Agent Builder 让每位员工都能试验、构建和分享新 Agent。几个月内，SafetyCulture 就推出了多种 Agent，涵盖会议摘要、绩效评估、调试和内部支持等问题。

产品团队的 Customer Insights Agent 可按行业、地区和账号规模综合客户痛点与用例信息，每周节省团队数小时工作。PRD Agent 帮助工程师评估 PRD 的完整性和准备度，标准化框架结构与质量。Performance Highlights Agent 从 Jira、Github、会议记录等多处拉取数据，生成员工成就摘要，每次绩效评估节省 30–40 分钟。Product Help Agent 让员工即时获取内部功能最新进展，无需再问产品团队。Engineering Assistant Agent 每天用于调试常见错误和复杂问题，还能评估架构变更文档和数据模型质量。GTM & Support Agent 帮助 GTM 和支持团队快速回答产品相关问题，无需等待研发回复。

Glean 界面直观，数百个高质量连接器让集成变得简单。安全优先的数据策略，以及可在自家云租户内托管的能力，也让 SafetyCulture 放心选用。

Craig McPhee（Engineering Director）说：“Glean 改变了每个人的工作方式。它是我们所有信息的起点，帮助我们把 AI 融入一切。”

Viral Panchal（Engineering Manager）说：“超过 90% 的 Glean 用户推荐把它作为标准工具，如果停用会感到失望。它不仅彻底改变了搜索方式，还改变了我们理解公司知识的方式。我们想一直用下去。”

如今企业搜索问题已解决，创新 Agent 构建能力已在全公司普及，SafetyCulture 正迈向 AI-first 公司，释放员工的创造力、生产力和潜力。

给负责人

要解决什么
在工程人员增加 50% 并引入新工具后，解决知识搜索（内部调查的首要问题），而不把工程师从核心产品抽去自建搜索。
结果
相对工程师每周最多四小时搜索，搜索时间缩短 50%（叙述）。超过 90% 的 Glean 用户推荐它作为标准工具（Panchal）。Performance Highlights：每次绩效评估节省 30–40 分钟。页首还印评审周期每名工程师节省 20 分钟 — 未与 30–40 平均。
接了哪些系统
数百个连接器。在自有云租户中托管 Glean。成为默认原生搜索。
用了什么数据
Jira、Github、会议笔记（Performance Highlights）。产品 payload/路线图（GTM & Support）。架构变更文档与数据模型（Engineering Assistant）。洞察智能体的客户痛点来源未逐项列出。
人还管哪一步
工程师仍在智能体支持下评估 PRD 和架构。绩效摘要辅助评估。
多久上线
搜索缩短 50% 为「立即」。智能体在「数月内」。无天数。

给现场的人

主要用在哪
默认原生企业搜索。Agent Builder 全公司使用。智能体：Customer Insights（PMM）；PRD review；Performance Highlights；Product Help；Engineering Assistant；GTM & Support。
以前怎么干
数据分散在多个应用；知识孤岛。考虑过自建内部搜索/工作 AI 平台。工程师每周最多花四小时手工搜索。
卡在哪
知识搜索是内部调查中最大的问题。希望有更多上下文。自建会把工程师从一线工人产品上抽走。
用了什么模型
Glean 搜索 + Agent Builder。无基础模型名。
事情怎么流转
PMM 洞察智能体按行业/地区/账户规模综合痛点。PRD 智能体评审就绪度/完整性并标准化结构。Performance Highlights 把 Jira/Github/笔记拉成成就摘要（每次绩效评估节省 30–40 分钟）。Product Help 回答内部功能/时间线问题。Engineering Assistant 调试并评审架构/数据模型质量。GTM/Support 智能体在每周数百次 payload/路线图变更中回答产品问题。
怎么验收
工程师每周最多花四小时搜索；Glean「立即」把搜索时间缩短 50%。页首：每周搜索时间少 50%；评审周期每名工程师节省 20 分钟；90% 的用户推荐 Glean 作为标准工具。正文：Panchal — 超过 90% 的 Glean 用户推荐它作为标准工具，如果停用会失望。Performance Highlights 每次评估 30–40 分钟（页首评审周期 20 分钟是另一标签）。
怎么上线
公司默认原生搜索。每个用户都能构建/分享智能体。内部活动以建立 AI 信心。计划进一步标准化 PRD 流程。
失败了怎么改
考虑过自建并否决，以便工程师留在核心产品上。
能不能复用到下一家
内部 AI 活动；进一步标准化 PRD 开发。迈向 AI-first — 方向性表述，不是 KPI。
超过 90% 的 Glean 用户推荐 Glean 作为标准工具，如果我们停用会失望。它彻底改变的不仅是我们搜索的方式，还有我们理解公司知识的方式。——Viral Panchal，Engineering Manager
