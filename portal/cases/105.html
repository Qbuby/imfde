Nav 如何用 Factory 加快软件开发

作为一家处理敏感金融数据的金融科技公司，我们曾担心如何在利用 AI 的同时保持严格的数据隐私和安全标准。Factory 提供了一种安全、可控的方式，让我们统一工程上下文，同时不影响合规要求。这和把敏感信息随意输入各种 LLM 完全不同。

Nav 的使命是让每位小企业主都有成功的机会。在 Nav.com 上，小企业主有一个专用平台，用于建立和管理企业信用、跟踪现金流模式，并在申请前了解金融选项。已有超过 240 万家小企业信任 Nav 来改善财务健康。公司需要跨多个团队和技术扩展开发，同时保持高代码质量和安全。

但真正的挑战不只是写代码，而是围绕代码的一切：理解上下文、收集需求、规划功能、确保团队间一致性。工程师在开始编码前要花数小时拼凑信息，同时还要确保符合金融法规。

多个代码库——从遗留 Rails 单体到较新的 Java 服务——让工程师在保持敏感信息安全的同时，理解变更全貌变得越来越难。工具集也支离破碎。代码在 On-Premise Gitlab，文档在 Confluence，工单在 Jira，讨论在 Slack。工程团队不断切换系统，难以保持一致性和推进速度。

Nav 需要一种方式统一开发流程——不仅要更快写代码，还要让工程师获得规划、协作和高效构建所需的完整上下文。

一个能与 Nav 现有工具无缝集成并统一工程上下文的智能体 AI 平台。

跨代码库、文档和项目管理系统检索相关信息。

我们从工程师各自摸索如何在工作流中使用 AI，变成了拥有一个标准方案，所有上下文都能以合规方式获取。Factory 与现有工具的集成让我们无需迁移核心系统或一次性重构所有开发者工作流，就能立即看到价值。

在 Factory 之前，理解一个功能的完整上下文可能需要数小时。现在，Factory 平台会自动把我们需要知道的一切——从相关代码到历史决策——汇集到一个地方。

Factory 改变了 Nav 工程团队的软件开发方式，把重点从收集上下文转向创新和解决问题。工程师在开始任何实现任务时，都会本能地使用 Factory 自动收集上下文并制定合理计划。

这些好处在 Nav 复杂的金融集成中尤为明显。Factory 的统一上下文帮助我们在集成问题出现前就预判并解决——这在以前碎片化的方式下几乎不可能。

通过统一工程上下文和自动化工作流，Nav 能在不牺牲质量的情况下提高开发速度。开发流程随着客户需求增长无缝扩展，团队生产力和满意度都得到了提升。

有了前所未有的系统可见性，我们能自信地更快行动，为数百万小企业客户交付新功能。

Nav 在自己的安全边界内统一了工程上下文，削减了拖慢每个功能的速度的上下文切换成本。Factory 提供了一种安全、可控的方式，让我们统一工程上下文，同时不影响合规要求。现在，Factory 平台会自动把我们需要知道的一切——从相关代码到历史决策——汇集到一个地方。

给负责人

要解决什么
在多个团队和技术上扩大开发，同时保持高代码质量、安全与金融服务合规 — 不只是更快写代码，而是统一工程上下文。
结果
上下文切换时间减少 60%。功能开发周期快 2 倍。100% 的工程上下文自动统一。加快新开发者上手（无上手时间数字）。页面还提到一次重大信用监控更新在统一上下文帮助下预判了集成问题后上线（无单独 KPI）。
接了哪些系统
Factory 与现有工具集成 — 无需迁离核心系统。Shared Sessions 与 Workflows。页面：跨仓库、文档和项目管理系统检索信息。
用了什么数据
本地 GitLab 仓库（Rails 单体 + Java 服务）；Confluence；Jira；Slack；历史决策与相关代码。
人还管哪一步
工程师仍负责实现；Factory 收集上下文并帮助规划。合规/安全约束仍在。加快新开发者上手（未量化）。
多久上线
页面：无需迁离核心系统即可立即看到价值。日期 2025 年 2 月 25 日。未公布试点时长。

给现场的人

主要用在哪
开始任何任务时自动收集相关上下文；带着依赖理解执行复杂功能。点名一次信用监控系统的重大更新，统一上下文帮助在集成挑战变成问题之前预判并解决。
以前怎么干
包括 GitHub Copilot 在内的 AI 编程助手。多个仓库，从遗留 Rails 单体到较新的 Java 服务。代码在本地 GitLab，文档在 Confluence，工单在 Jira，讨论在 Slack。
卡在哪
编码前花数小时拼凑信息同时还要保持合规。碎片化工具集导致不断切换上下文。Copilot 有助于更快写代码，但不能理解上下文、收集需求、规划功能或保持跨团队一致性。
用了什么模型
Factory 智能体平台（无具体基础模型名）。
事情怎么流转
任务开始时自动组装上下文；用共享 Sessions 和 Workflows 协作；工程师先用 Factory 收集上下文并产出有理据的计划，再实现。
怎么验收
页上 Key Performance Gains 列表：上下文切换时间、功能周期速度、工程上下文统一占比。
怎么上线
所有上下文可用的标准批准 AI 方案。页面未公布工程师人数或推广比例。
作为一家处理敏感金融数据的金融科技公司，我们担心如何在保持严格数据隐私和安全标准的同时利用 AI。Factory 为我们提供了一种安全、受控的方式来统一工程上下文，而不损害我们的合规要求。这与敏感信息流入随机 LLM 之间的差别有如天壤。——Gian Perrone，CTO @ Nav
