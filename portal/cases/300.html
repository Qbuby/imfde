大型欧洲保险公司：AI Smart Claims

同一篇 Palantir 保险产品页。一家大型欧洲保险公司每年要处理数百万件来件理赔。文档内容和格式差异极大，没有 AI 就无法把评估步骤全自动化。

即时经 API 摄入：非结构化来件理赔在客户理赔服务器收到后数秒内在 AIP 里本体化。AI 驱动结构化：20+ 项所需理赔属性由 AI 模型自动抽取并解释。回写运营系统：所需细节成功抽出后，已结构化理赔写入客户理赔处理系统和归档库。计算机视觉加 LLM：计算机视觉模型把摄入理赔存成机器可读格式，LLM 再抽取解释所需细节。自主承保评估：用一套保险保单规则自动评估理赔，规则由保单专家在 AIP 里用低代码 UI 维护。自动执行赔付：评估结果送到客户发票赔付系统，自动做确定的扣减并向客户赔付。

页上数字：每年自动处理 500,000 件非结构化理赔；每年解锁 35,000 小时专业人工处理产能；每年通过防止不当赔付实现 €5M 节约；在不改变员工人数的情况下支撑 >30% 的同比增长。页上未写这家欧洲保险公司的名称。

同一页 Sompo Japan 段落写过去三年 $60 million USD 利润改善、预期接下来三年再 $100M USD。Swiss Re 段落写 >50% 员工是活跃 Palantir 用户、三分之一每周使用；支撑大约两打业务域；单一用例 9 位数美元影响。这些是并列客户段落，不要串到「大型欧洲保险公司」头上。

给负责人

要解决什么
每年数百万件进件理赔，文档内容和格式差很大，没有 AI 就没法把评估完全自动做完。
结果
>50% 员工是 Palantir 活跃用户（每周三人中有一人）；Palantir 撑住约二十多个业务域；单个用例带来 9 位数美元影响。
接了哪些系统
Palantir AIP；客户理赔服务器 API；赔付系统。
用了什么数据
非结构化理赔（文档、图像、通话）、保单规则、理赔处理系统。
人还管哪一步
保单专家在低代码 UI 中维护规则；伦理护栏防止未经人工确认即拒绝赔付。

给现场的人

主要用在哪
经 API 即时摄入理赔；AI 把 20+ 项理赔属性结构化；回写运营系统；计算机视觉 + LLM 结构化；用低代码界面维护的保单规则自动评估承保范围；自动执行赔付。
以前怎么干
跨多种格式的手工理赔评估。
卡在哪
无法完全自动评估理赔；规模瓶颈。
用了什么模型
多模态/计算机视觉 + LLM 用于理赔结构化；保单规则评估。
怎么上线
生产环境理赔自动化，覆盖 two dozen 个业务域。
