Itaú 如何在全球金融规模上把 AI 部署到整个 SDLC

已为 300,000+ 个代码库写文档

测试覆盖率翻倍，从约 50% 到约 90+%

Itaú Unibanco 是巴西最大银行，资产约 5000 亿美元，客户超 7000 万，业务覆盖 18 个国家，拉美最大工程团队之一，技术人员超 17000 人。

Itaú 部署 Devin，是全球金融机构最大规模的 AI 落地之一，覆盖整个软件开发生命周期。

“在技术快速演进、竞争激烈的今天，速度是终极优势。AI 能大幅加速我们响应客户需求、交付创新方案的速度，巩固市场地位。对此，Devin 是一项重要战略投资。”
Carlos Eduardo Mazzei，Itaú CTO

Itaú 最初尝试传统 A/B 测试，把用 Devin 的团队和不用 Devin 的团队对比。但这种方法假设 Devin 只是处理离散任务。实际中，团队一旦熟悉 Devin，就会不断发现新用法。

“大家熟悉 Devin 后，自然会扩大与它的协作方式。”
Roberto Frossard，Itaú 科技研究院负责人

于是 Itaú 改成衡量团队全面采用 Devin 后的效果。有一个 squad 在工作流里广泛使用 Devin，三个月交付两次版本，是原计划的两倍。工程师能处理长期积压的任务，复杂工作推进更快，把更多时间花在高价值事项上。

“对我们来说，价值在于帮助工程师更快学习、探索更多路径、解锁原本需要更长时间的工作。”
Roberto Frossard，Itaú 科技研究院负责人

五个月内，需求激增，等待名单接近 1000 名开发者。九个月后，Itaú 与 Cognition 合作，把 Devin 扩展到全行技术人员。目前 75% 的团队在使用 Devin。连 CTO Cadu 也每天使用 Devin。

这次转型离不开与 Cognition 的紧密合作。

“与 Cognition 团队的合作非常出色。他们能以极快的速度和极高的产品质量解决超级复杂的问题，背后是一支技术顶尖的团队。我们很高兴共同构建未来，探索新的协作与学习方式。”
Carlos Eduardo Mazzei，Itaú CTO

“Cognition 团队始终响应迅速，随时准备深入技术难题。以客户为中心是 Itaú 的核心价值观，Cognition 也展现了同样的承诺，与我们一起探索新的工作方式，提升开发者体验，帮助我们为客户交付最好的产品。”
Gabriel Pegorelli，Itaú 开发者体验负责人

Itaú 用 Devin 的两种方式

机构知识层
Devin 为 Itaú 的代码库持续更新文档。工程师可以像咨询资深工程师一样向 Devin 提问。这大大改善了新人 onboarding、遗留系统理解和生产力。这个持久的知识层形成了长期组织记忆，减少瓶颈，让工程师更快交付新功能，是 Itaú 可持续价值创造战略的核心。

“开发者对 Devin 的能力感到兴奋。我们看到它能处理我们最初认为太复杂的问题，尤其是在处理海量代码库的团队中，其他产品很难吸收那么多上下文。”
Stéfano Georgetti，Itaú 新兴技术产品经理

工程师专用平台
Devin 并行执行编码任务，加速原本需要大量手动工作的工作。它支持迁移与现代化、修复安全漏洞、审查代码、编写测试、清理工单积压。目标是赋能人类工程师。通过把重复执行工作交给 Devin，工程师可以专注于架构、设计和业务关键问题解决，加速交付，同时提升人类工程师的角色。

全行范围内，Itaú 看到吞吐量提升 20-30%，周期时间缩短 10-15%，在以下用例中影响尤为显著。

迁移与现代化
挑战：大规模迁移工作量大、重复性高，阻碍团队交付功能。Itaú 面临原本需要数月工程时间的大型项目。

解决方案：
CNPJ 合规：新法规要求在 300,000+ 仓库的数十万文件中为税号增加字母数字支持，包括 COBOL 等遗留栈。之前认为无法自动化，Devin 实现了跨所有应用的 COBOL 变更自动化，与多种工具配合，简化并加速流程。一个团队的 SQL Server 迁移，覆盖 800 个数据库对象和存储过程，速度提升 5 倍。
.NET → Java：Itaú 需要把 59 个遗留 .NET 后端服务迁移到 Java。Devin 分析 .NET 服务，按 Itaú 架构标准生成 Java 等效服务，并合并为 9 个服务。借助 Devin，项目用时减少 6 倍，从数月缩短到数周，成本降至 1/5，路线图更高效，长期架构更简洁。

自动修复安全漏洞
挑战：SonarQube、Fortify、Veracode 等静态分析工具标记大量问题。手动处理这些告警会产生运营摩擦：安全团队需跨多个 squad 协调修复，工程师花费时间处理低复杂度问题，这些问题在代码库中累积。

解决方案：Devin 集成到 CI/CD 流水线。当 SonarQube、Fortify 或 Veracode 标记问题时，Devin 自动分析并修复，只需工程师审查补丁。现在约 70% 的漏洞自动解决，清理历史积压，降低安全风险。

大型代码库文档化
挑战：Itaú 有 300,000+ 仓库，是拉美最大软件生态之一，包含数千个服务，横跨遗留系统、现代微服务、监管数据流和关键金融负载。在这种规模下，保持文档全面、最新且易于发现是一项持续挑战。

解决方案：Itaú 正在全行部署 Devin 的 Wiki 和 Devin Search，作为知识层的一部分。

给负责人

要解决什么
在一家技术条线 17,000+ 人、300,000+ 个仓库（含 COBOL）的银行，把 AI 部署到软件开发生命周期。
结果
59 个 .NET BFF 服务 → Java 快 6x、成本低 5x，合并为 9 个服务。SQL Server 800 个对象快 5x。约 70% 的 SonarQube/Fortify/Veracode 漏洞自动解决。测试覆盖 2x，从约 50% 到约 90+%。300,000+ 个仓库已文档化。首席工程师设计架构约快 10x（一则引语中完整提案需 10–15 分钟）。全行吞吐量提升 20–30%，周期时间降低 10–15%。75% 的团队使用 Devin。
接了哪些系统
CI/CD：当 SAST 标记问题时，Devin 分析并修复供工程师审查。服务令牌和 GitHub Actions 用于初审 + wiki 条目。等候名单九个月后，扩展到所有从事技术工作的人。
用了什么数据
300,000+ 个仓库；COBOL 及其他遗留；SonarQube/Fortify/Veracode；支持葡萄牙语的 Devin Wiki/Search。
人还管哪一步
工程师审查补丁和初审。首席/解决方案架构师用 Devin 做架构提案。
多久上线
五个月内约 1,000 名开发者的等候名单；九个月后全组织扩展。
怎么交给客户

给现场的人

主要用在哪
59 个服务的 .NET→Java（合并为 9 个）；SQL Server 800 个对象；自动修复 SonarQube/Fortify/Veracode；Wiki/Search 知识层；测试；初审；事件诊断；一天内完成 Treasury UI。
以前怎么干
传统 A/B（有 vs 无 Devin 的团队）因使用自然扩散而放弃。静态分析发现靠人工跨小队协调。架构规划从数周逆向工程开始。
卡在哪
大型迁移消耗数月；300,000+ 个仓库难以文档化；安全工具体量；遗留栈中的事件分诊。
用了什么模型
Devin（Wiki、Search、Review）
事情怎么流转
机构知识层（持续文档）加上专项执行（迁移、漏洞、测试、审查、积压）。在数十万个文件（含 COBOL）上支持 CNPJ 字母数字。
怎么验收
小队发布次数；全行吞吐量和周期时间；迁移速度/成本；测试覆盖；漏洞自动解决率；采用度。
怎么上线
如今 75% 的团队使用 Devin；CTO 每天使用 Devin。技术条线 17,000+ 人。
失败了怎么改
传统 A/B 测试假定离散任务，与使用的自然扩散不匹配。
能不能复用到下一家
Devin Wiki 和 Search 作为银行知识层；CI/CD 自动修复；即将在每个 PR 上由 Devin 生成初审。
