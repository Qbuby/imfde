Pigment

公司自己讲的数字 · 一般

Pigment 用 Augment Code 把样板活自动化，测试也更简单

故事。Pigment 怎样用 Augment Code 把样板任务自动化、把测试做简单。靠 Augment 有上下文的建议和多语言支持，开发者能留在心流里，更快交出价值。

挑战。领先的业务规划平台 Pigment 想加快开发，还要保住代码质量。工程师后端主要用 C# 和 .NET 8，前端是 React 加 TypeScript，AI 产品用 Python，SRE 团队还有 YAML 和 Go。多数开发者专前端或专后端，很少同时跨整栈。难点是管样板代码和低价值活。写测试也是卡点，因为测试套件是自然长出来的，结构散。

给负责人

要解决什么
加快开发并让新人在难导航的代码库上爬坡，同时保持质量；样板与非结构化测试套件是阻碍。
结果
无数字 KPI。定性：无聊任务上时间更少；测试更容易；聊天用相关代码作答。
接了哪些系统
VS Code、IntelliJ。欧洲租户；引用 SOC2。
用了什么数据
Pigment 多语言代码库。
人还管哪一步
工程经理 Christophe Plat；开发者保持心流并接受建议。

给现场的人

主要用在哪
样板补全；聊天跨前端、后端和 SQL 迁移定位功能；测试编写/重构。
以前怎么干
多数开发者专精前端或后端，很少全栈。对照 GitHub Copilot 比较。
卡在哪
研发快速增长；新人无法导航；测试有机增长且难写。
用了什么模型
Augment Code（页上：Context Engine / agent / 补全；除非另有说明，无单个模型名）。
事情怎么流转
小增量建议加上代码库聊天。
怎么验收
定性。无数字表。
怎么上线
90+ 团队。欧盟租户。
失败了怎么改
看过 Copilot；想要更小的建议和更强的安全姿态。
我超级震撼，因为它让你能说：「嘿，Augment，这个功能在哪实现的？」然后它能浮出前端代码、后端代码，还有 SQL 迁移。

备注

官方 Augment 案例。具名工程经理 Christophe Plat。SOC2 与欧洲租户是供应商姿态事实，不是结果。无数字 KPI。
