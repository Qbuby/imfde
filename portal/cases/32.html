LendingTree 使用 Augment Code 提升规划、报告和 DevOps 工作流中的速度

LendingTree 的 IT Operations 团队用 Augment Code 减少重复劳动、加快规划、简化复杂流程，从 sprint 规划到云支出分析全覆盖。

Howard Zeemer 是 IT Operations 总监，他说自己的工作就是“让别人跑得更快”。他的团队负责 LendingTree 的全部基础设施和 DevOps 文化，支撑所有产品和内部服务系统。

他们管理 1,200 多个微服务，跨多个云平台，遇到几个痛点：

Sprint 规划和故事生成：要把 Confluence 的简报手动转成 Jira 故事、估算故事点、拆子任务。

云支出报告：对账账单数据，常需手动导出、用 Excel 透视。

调试和上下文切换：要理解几十个仓库里分布式服务的交互。

单元测试覆盖：写和维护测试用例占到开发者 30% 的时间。

文档和报告：要生成一致、及时更新的文档，横跨工单和流水线。

之前试过别的 AI 工具，但都需要太多设置和喂上下文。Howard Zeemer 说：“很多工具得花大力气才出结果，投多少出多少。”

LendingTree 引入 Augment Code，把上下文感知的智能带进日常流程。Zeemer 的团队需要能跨多个工具、理解现有自动化流水线、适应 DevOps 环境的 AI。

“在用过的所有工具里，Augment 最接近需求，还能发现我没想到的东西。”

Augment 能无缝吸取多个仓库和 CI/CD 流水线的上下文。Zeemer 说：“我让 Augment ‘用我们的规则建流水线’，它直接接过去跑了，连多看一眼都没。”

把 Augment 连上 Jira 和 Confluence 后，团队用它来解析规划简报、生成并估算用户故事、创建子任务和 sprint 执行的评分标准。

“我的 PM 们兴奋坏了。以前要花一天，现在几分钟就完。”

Augment 还能自动对比 AWS 和 Azure 的支出，按服务给出百分比和金额变化。

“它告诉我哪个组织支出变化最大、跟什么有关。我还用 Augment 写了个 Azure MCP 来管支出。”

有一次团队花了好几个小时追一个 WebSocket 权限的 bug，Augment 几分钟就定位并修好了。

“一个工程师把 Augment 对着代码，它 15 分钟就把问题解决了。”

Augment 还生成了完整的单元测试，工具一年的费用在一个月内就回本了。

影响领域 使用前 使用后

“目标很简单：让 AI 干苦活，我们干有意思的事。”

给负责人

要解决什么
IT 运营（Howard Zeemer）要让别人在 1,200+ 微服务和多云上更快——冲刺规划、云支出报告、调试、单元测试、文档。
结果
前后对比表：单元测试从占开发者时间 30% 变成自动化，工具支出 ROI 1 个月内覆盖全年；冲刺规划经 Jira+Confluence 从 1–2 天 → 数分钟；云支出从手工 Excel 变成自动摘要/图表；关键缺陷调试 2+ 小时 → 15 分钟（WebSocket 权限示例）；文档内联生成。1,200 微服务 / 多云是环境规模，不是 Augment 产出。
接了哪些系统
JetBrains、VS Code；Jira + Confluence；用于支出的 Azure MCP（用 Augment 编写）。
用了什么数据
多个仓库、CI/CD、Jira、Confluence、AWS 和 Azure 账单。
人还管哪一步
Director of IT Operations 加上 PM/工程师/运营人员。
多久上线
Sprint 规划：每个 sprint 1–2 天 → 数分钟。调试示例：2+ 小时 → 15 分钟。单元测试工具支出：1 个月收回全年 ROI。
