Napster 3D Studio（Infinite Reality）

公司自己讲的数字 · 一般

Napster 用 Augment Code 加快测试、原型和开发者生产力

故事。面对定制 Web3D 引擎的复杂和快速扩张的工程团队，Infinite Reality 找 Augment Code 提高测试覆盖、加快原型，并让开发者更会跟 AI agent 干活。结果：交付更快、自动化更多、质量规模化的路更清楚。

挑战。Infinite Reality，现在也以 Napster 3D Studio 运转，在做一套头一遭的 SaaS 平台，做沉浸、可交互的 3D 网页体验。公司的定制游戏引擎用 Three.js、React 和 TypeScript，接入自有渲染技术和 AI agent，把平面网站变成个性化 3D 空间。「我们卡在游戏和网页技术的交汇处——没有现成的东西是为我们这种事建的，」临时 CTO Griffin Rowell 说。「连工程师入职都难，因为我们的栈太窄。」

给负责人

要解决什么
在难以入职的小众定制 Web3D 引擎（Three.js/React/TypeScript 加专有渲染）上提高测试覆盖、原型速度与 AI agent 熟练度。
结果
无全组织倍数。原型数分钟对照数小时。一些先前怀疑的 IC 现在每天管理数百次 agent 调用。测试覆盖「快速改善」——无百分比。
接了哪些系统
分析集成进 sprint KPI（页上未公布那些 KPI 值）。
用了什么数据
开源栈上的定制引擎与专有层。
人还管哪一步
学习/实验而不是强制。经文档与内部工具为 agent 管理技能缺口做技能提升。
多久上线
原型：数小时搭建 → 数分钟。

给现场的人

主要用在哪
快速测试生成；从粗想法 + 库列表在数分钟对照数小时内实验；IC 每天管理数百次 agent 调用。
以前怎么干
非正式多工具实验；正式评估收窄到 Gemini 与 Augment；团队 hackathon 决定给 Augment。
卡在哪
没有东西是为他们的游戏+网页栈建的；入职难；样板与测试慢。
用了什么模型
Augment Code（页上：Context Engine / agent / 补全；除非另有说明，无单个模型名）。
事情怎么流转
结对程序员加上远程 agent；最高产 IC 每天管理数百次 agent 调用。
怎么验收

怎么上线
部署到核心工程团队；150 名工程师。使用稳步上升（未量化）。
失败了怎么改
其他工具缺乏专有引擎的上下文/训练数据。Gemini 在 hackathon 落败（未公布分数）。
能不能复用到下一家

没有对手。这个 agent 是力量倍增器。变成：你能用 Augment 构建吗？答案是能。——Griffin Rowell，临时 CTO
