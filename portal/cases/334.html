Ramp 如何把工程心态用到客户体验上

Ramp 的使命是给客户省下他们最在意的两样东西：时间和钱。集成平台跨公司卡、费用管理、采购、旅行和会计自动化。但那份转型超出软件功能。对 Ramp，兑现承诺需要同样稳健的客户体验。领导客户运营和对话 AI 产品的 Ben Levick：「钱是任何生意最敏感的部分之一，所以表现和信任不可商量。支持不只是解决问题——是帮客户从 Ramp 拿到更多价值。」

2023 年 Ramp 自建了一套内部 AI 助手来 deflection 简单问询。结果有希望，但维护的技术负担变清楚。Ben：「我们到了建多步工作流和用户特定动作的那一点，意识到支持自动化不是我们的核心能力。我们需要一个焦点就是按规模做这件事的伙伴。」拐点出现在 Ramp 开始把 AI agent 扩到问答之外。「一旦我们走进个性化——查找用户数据、为客户采取动作——我们就知道必须走出内部工具。用一小支团队自己管那种复杂度不可持续。」

Ramp 需要能跟自己的产品一样快演进的 AI agent。一项关键要求：能保留完整工程控制又不牺牲速度。Ben：「Sierra 的 Agent SDK 突出，因为它让我们把客户旅程写成代码、跟踪变更、建复杂逻辑，同时不放弃我们的开发工作流。它是第一套真正达到我们技术杠的方案。不是交出控制。感觉像工程实践的延伸。」同样重要的是协作。Sierra 不像供应商，而是紧密与 Ramp 共同开发 agent。Ben 把 Sierra 团队描述成「文化对齐、深深上手」，让 Ramp 能快速动，同时学会独立构建和维护旅程。「他们不只在发功能——他们在教我们钓鱼。」

对 Ramp，跟 Sierra 合作最大优势之一是知道信任和安全在基础设施层被处理。Ben：「如果我们端到端自建系统，就得自己拥有滥用预防和风险缓解的每个维度。有 Sierra，我们可以盯建出色客户旅程——知道越狱检测、滥用监控和监督模型这类保障已经在位。」那份安心也延伸到对话质量。Sierra 的编排层和分诊能力帮防止漂移或失控行为，确保 agent 盯任务又不变得过死。Ramp 也受益于 Sierra 的测试套件，上线前按规模模拟对话测 agent 表现。这套 AI 驱动测试框架支撑回归检查、预测分析和基于结果的评测。Ben：「它给我们一套我们自己建不出来的测试水平。我们可以有信心地发货，知道 agent 行为稳定、可靠、对齐我们的目标。」

Ramp 的 agent 支撑广且在增长的用户发起和管理员工作流。Ramp 持卡人可以轻松锁卡或换卡，或快速拿到交易细节和失败的解释。agent 处理收集和核验地址信息，为需要更新记录的用户理顺过程——它甚至能寄实体卡。对管理员，agent 可以协调批量动作帮理顺工作，如发多张卡或从一桩生意里拉特定交易数据。这些都用 Agent SDK 建，确保旅程容易维护、版本化和扩展。Ramp 也在试不同界面风格以适合不同用户。Ben：「我们的一些持卡人只想快进快出。另一些——像管理员——要可见性和控制。我们把 agent 设计成对两者都能弯。」

上线以来，Ramp 经自动化达到 90% 案子解决率——戏剧性减少例行工单量并帮防止支持积压。这让 Ramp 的支持专家把时间和专长集中在最复杂、最高价值、他们对客户体验影响最大的案子。Ben：「Sierra agent 照料直截了当的问题，所以我们的团队能集中在真正受益于人的触感的更难问题。」Ramp 也维持严格的质量保证环，把 Sierra 的数据喂回产品运营和知识管理团队。这些团队不仅管给人坐席的产品赋能，也管给 AI 的。Ben：「我们给产品运营者在他们领域里对 AI 成功的所有权。他们在读转录、更新知识、塑造旅程——就像他们为我们的支持团队做的。」团队已经开始推出语音 agent。Ben 说它演进很快：「甚至六个月前，语音 agent 仍感觉卡在诡异谷。但 Sierra 的语音体验现在处理上下文、跟进和口吻的方式感觉真正有帮助。」

Ben 相信 AI agent 只和支撑它们的团队一样好。在 Ramp，知识管理嵌在产品组织里，专门的产品运营伙伴被委以像赋能支持团队一样赋能 AI。每周反馈环帮排优先级更新，无论是打磨一篇知识文章还是圈定一条定制旅程。「当 AI agent 失败，常常不是因为模型不够聪明——是因为底层知识含糊，或 prompt 不够具体。」第二条建议是不要低估支持团队。「他们往往对客户实际需要什么有最多上下文。」下一步 Ramp 正在把 agent 扩到所有支持通道，并探索非支持用例，AI 可以在产品上支撑一层增长中的对话层。他们对更自主的模式也感兴趣——不只响应、而是按定义信号观察并行动的 agent。

给负责人

要解决什么
用能做用户特定动作（锁卡/换卡、寄实体卡、管理员批量发卡）的智能体替换 2023 年自研分流器，同时工程师把旅程当代码来维护。
结果
经自动化达到 90% 工单解决率，减少常规工单并防止积压。
接了哪些系统
Agent SDK 旅程即代码；QA 循环进入产品运营与知识管理；语音渠道起步。
用了什么数据
Ramp 用户/管理员数据；由产品运营管理的知识。
人还管哪一步
专员处理最难的案例；产品运营在其领域拥有 AI 成功（转录、知识、旅程）。每周反馈循环。
怎么交给客户
Ben Levick，领导 Ramp 客户运营与对话式 AI 产品。

给现场的人

主要用在哪
持卡人：锁卡/换卡、解释交易/失败、更新地址、寄实体卡。管理员：批量发卡、拉取交易数据。语音智能体正在铺开。
以前怎么干
内部 AI 助手做简单问答；在小团队的多步个性化动作上撑不住。
卡在哪
支持自动化不是 Ramp 的核心能力；需要越狱/滥用/监督模型和模拟测试，否则这些都得自己扛。
用了什么模型
Sierra Agent SDK + 编排/分诊；语音体验。
事情怎么流转
用户与管理员发起的工作流；界面对快速持卡人与寻求控制的管理员有弹性。
怎么验收
经自动化的工单解决率；上线前的对话模拟。
怎么上线
支持自动化已生产；语音正在铺开；扩展到所有支持渠道以及非支持对话层。
失败了怎么改
自研助手对问答还可以，一旦需要个性化/动作就不可持续。
能不能复用到下一家
Agent SDK 作为工程实践；探索自主观察并行动的模式。
Sierra 的 Agent SDK 脱颖而出，是因为它让我们把客户旅程写成代码、跟踪变更，并构建复杂逻辑，而不放弃我们的开发工作流。他们不只是交付功能——他们在教我们钓鱼。——Ben Levick，Ramp 运营与 AI
