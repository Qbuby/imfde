Criteo 用 Sourcegraph 通用代码搜索对付 Big Code

Criteo 用 Sourcegraph 又快又直观的搜索和代码智能，换掉又慢又靠文本的工具。开发者每天能省下几小时，在异构生态里更好找路，把精力放到真正有冲击的方案上。Criteo 2005 年在法国成立，跟零售商合作，用广告再定向给潜在客户推荐商品。公司在自建服务器上存着海量数据，开发者在巴黎和美国两边改着数百万行代码。Criteo 的生态很杂，仓库有几千个。改单个仓库时，开发者用 IDE 搜代码。可跨职能、跨多仓库的团队，这种小范围搜索不够用，还特别耗时间。

给负责人

要解决什么
在 IDE 搜索只覆盖一个仓库时，跨数千仓库与语言的异构生态准确、快速地搜索。
结果
早期采用者调查：83% 每天使用 Sourcegraph；近三分之二每天用几次。55% 说每天节省几十分钟；18% 说每天节省超过一小时。
接了哪些系统
一站式搜索所有 Criteo 代码库。
用了什么数据
数千仓库；数百万行；本地服务器；多种语言/生态。
人还管哪一步
开发者用推荐过滤器细化查询。

给现场的人

主要用在哪
查询 + 过滤器，在代码库/语言/工具中定位代码或弃用模式。「浏览代码的在线 IDE。」
以前怎么干
单个仓库内的 IDE 搜索。跨仓库工作用遗留基于文本的搜索。
卡在哪
遗留文本搜索有安全问题、结果质量差、响应慢。跨职能 / 多仓库工作是时间黑洞。
用了什么模型
Sourcegraph 通用代码搜索 + 代码智能（未点名 Cody/LLM）。
怎么验收
Sourcegraph 早期采用者内部调查（使用频率与节省分钟）。
怎么上线
用作跨仓库搜索骨干；调查是早期采用者，不一定是全公司。
失败了怎么改
遗留基于文本的搜索：安全问题、质量差、慢。
Sourcegraph UI 的质量及其代码智能对我们是两个改变游戏规则的功能。就像有一个浏览代码的在线 IDE。——Loic Teikiteetini-Vaysse

备注

Sourcegraph 官方案例（抓取 2026-08-29）。具名 Loic Teikiteetini-Vaysse 与 Francois Jehl。调查数字是早期采用者，不是全部 Criteo 开发者。导语里的「每天数小时」是该调查的营销摘要。
