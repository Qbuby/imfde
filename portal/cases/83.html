用 Devin 规模化 GOAT 的开源开发

Crossmint 提供开发者工具，帮助公司把应用、项目和智能体上链。GOAT SDK 是他们开源工作的核心，这是一个社区拥有的库，让 AI 智能体能调用区块链工具。

作为 GOAT SDK 的维护者，我们遇到了典型的扩展难题。库需要不断集成新协议和新 dApp，社区开发者再多，积压的任务还是增长得更快。我们需要一种既能扩大开发规模，又能保持代码质量的办法。

Cognition 通过开源计划给了我们 Devin 额度，我们决定验证一个想法：能不能用 AI 来扩大开源开发，让人类开发者专注更高阶的问题？

第一次试用，Devin 按 PR 数量成了我们最大的贡献者。它合并了 8 个 PR，第二名贡献者是 4 个。大部分代码质量高，直接被合并。

两个典型例子：

DEXScreener 插件支持
DEXScreener 提供 REST API，用于查询代币价格和活跃度。我们只给 Devin 一个文档链接和一句“做个插件”的指令。它先是照着文档写，之后我们让它看仓库里的例子来学习写法，最后在 GitHub 上给了一次反馈就合并了。

Sui 区块链集成
Sui 是一条类似 Ethereum 和 Solana 的区块链。这次任务更难，需要改多层代码，还得加示例。我们给的提示更具体，也给了三轮反馈。它一度卡住，因为用了旧版 Sui 标准库。不过我们只花了大约一小时人工介入就完成了合并，如果从零开始大概要好几天。

最让人印象深刻的是，Devin 能在极少上下文的情况下工作——常常只要一个集成文档链接就能输出可用代码。

通过这次实践，我们总结出三条成功经验：

给 Devin 足够的仓库和流程知识；
提供清晰的任务背景和具体目标；
提前定好验收标准。

最常见的错误是高估 Devin 的能力、期望过高，导致失望。开发者容易把它当“超人”，结果给的上下文不够、假定它已懂代码库、期望不切实际。

虽然 Devin 还处于早期阶段，我们对它在可持续扩展仓库方面的作用持乐观态度。它能把日常集成工作接过去，让人类贡献者把精力放在架构改进、开发者体验、社区运营和战略优先级上。
