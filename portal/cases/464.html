F5 为全球分布式软件团队理顺协作

Sourcegraph 给出代码库的统一视图，帮开发者理解依赖、调试 API、分享知识，让 F5 的全球团队更快、更高效地交付软件。F5 盯任何多云环境里 Web 应用的开发、交付、安全、性能和可用性。下一代软件基础设施项目背后的团队一年半前从零代码起步，现在有超过 350 个仓库、多种编程语言，以及分布在六个时区的 125 名开发者。这个项目会活 10+ 年，代码在那期间必然会按数量级往上长。拆掉烟囱。「有 Sourcegraph 之前，各团队是隔开的。开发者能懂自己的代码库，可很难看见和理解其他团队成员的代码。」

给负责人

要解决什么
一个约 1.5 年前从零代码起步的下一代软件基础设施项目，增长到 350+ 个仓库、多种语言、以及跨六个时区（团队相差超过 12 小时）的 125 名开发者，需要一种共同方式来阅读代码和 API。
结果
页面：350+ 个仓库 / 125 名开发者 / 六个时区的统一视图。结果为定性（孤岛下降、更好的 API 测试反馈、对全球排期必不可少）。无小时数或百分比数字。
接了哪些系统
Sourcegraph 作为跨 API 边界的共同代码讨论界面。
用了什么数据
350+ 个仓库；多种语言；125 名开发者；六个时区；预期寿命 10+ 年。
人还管哪一步
开发者仍一起走读代码；测试人员仍写反馈。
多久上线
项目本身从零代码约 1.5 年；未给出 Sourcegraph 采用日期。

给现场的人

主要用在哪
对话中在 Sourcegraph 里走读另一团队的代码；测试人员阅读 API 实现/参数/错误路径并给出反馈。
以前怎么干
团队孤岛：开发者懂自己的代码库，但不懂其他团队的。API 讨论缺少共同视图。
卡在哪
关起门来的设计在全球不再可行。测试人员需要跨仓库边界走读 API、参数和错误条件。
用了什么模型
Sourcegraph 代码索引/搜索（未点名 Cody/LLM）。
怎么验收
仅定性。无调研或数字 KPI。
怎么上线
用于下一代基础设施项目（125 名开发者 / 350+ 个仓库）。
失败了怎么改
采用 Sourcegraph 之前，团队看不到其他团队的代码。
我们比以往任何时候都更快地开发软件，排期激进，并且跨越边界。过去在关着的房间里搞定的事，现在必须在团队散落全球时完成。Sourcegraph 在这种环境里必不可少，没有它我无法想象自己能胜任工作。

备注

Sourcegraph 官方案例（抓取 2026-08-29）。350+ 个仓库 / 125 名开发者 / 六个时区 / 相差超过 12 小时 / 10+ 年寿命是页上项目事实。所有引语均未具名。无数字结果。
