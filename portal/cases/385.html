Quorum 用 Augment 的上下文感知 AI 助手改善开发者体验

故事。公共事务平台领先者 Quorum，怎样从 GitHub Copilot 换到 Augment Code，改善开发工作流。响应更快、上下文更好，工程团队在现代技术栈上的开发者满意度更高。

挑战。Quorum 的工程团队管着一套复杂代码库，服务跨多个辖区的公共事务专业人士，包括国会、州议会和国际机构。大约 70 名活跃开发者分布在美国、巴西和摩尔多瓦，保持代码质量稳定和开发者生产力至关重要。

给负责人

要解决什么
让一个较大、相对初级（约许多人司龄 <3 年）的分布式团队更容易理解和扩展不断演进的大型公共事务代码库。
结果
未公布量化生产力增益。页上：团队衡量仍早；在 30 天评估中看到明确价值。不要把预期的 PR/前置时间改善当作结果。
接了哪些系统
多种 IDE（页上：Copilot 仅原生维护 VS Code）。
用了什么数据
跨辖区的 Quorum 代码库（国会、州、国际）。
人还管哪一步
CTO Chris McFadden 指导 DX 焦点。

给现场的人

主要用在哪
跨文件补全（在 React 组件上建议新 CSS 类）；更小、更自然的补全。
以前怎么干
切换前用了大约一年 GitHub Copilot Business。
卡在哪
Copilot 建议随机 CSS 类名；原生几乎只有 VS Code；几乎没有使用报告（最后使用日期）。需要更好的 DX 与一致性。
用了什么模型
Augment Code（页上：Context Engine / agent / 补全；除非另有说明，无单个模型名）。
事情怎么流转
自动补全与上下文感知建议；衡量生产力的早期阶段。
怎么验收
30 天评估。跟踪 PR 的 Change Lead Time；预期 PR 量、前置时间与质量——尚未作为结果公布。
怎么上线
约 70 名活跃开发者。30 天评估 → 更广铺开。
失败了怎么改
切换前一年 Copilot Business。
由于我们许多开发者司龄不到三年，并且在处理大型且不断演进的代码库，我们当前焦点是让开发者更容易理解和扩展代码，同时改善整体开发者体验。——Chris McFadden，Quorum CTO
