Nutanix 用 Sourcegraph 又快又有把握地修好了 Log4j

Nutanix 用 Sourcegraph，在庞大复杂的代码库里迅速找出并修复 Log4j 漏洞，缩短了补救时间，也让安全流程更有底气。Nutanix 解决方案工程技术总监 Jon Kohler 很清楚：要护住撑起这么大一家公司的海量应用和方案，有多复杂。「在 Nutanix，安全是我们特别在意的事，」Jon 说，「因为它是底盘的一部分。客户喜欢我们也是因为这个，我们必须当真。」

Log4j：把整个行业掀翻的漏洞。2021 年 12 月，全球软件公司发现，很多软件包里捆着的开源日志库 Log4j 有重大漏洞，其中一个在 CVSS 上是 10/10。

给负责人

要解决什么
在庞大的多版本控制系统代码库中找到并彻底修好 2021 年 12 月的 Log4j 漏洞（包括一个 10/10 CVSS 问题），并向客户交付补丁。
结果
页上主角：5 分钟看到 JMSAppender 在哪、修好它并发送发布；4 天交付彻底修复 Log4j 的补丁；在庞大代码库上 100% 识别。正文：几天内几次查询识别每一个实例；不到四天到客户补丁；三次连续补丁。
接了哪些系统
跨多套源代码控制系统的统一搜索；与团队共享的搜索上下文。
用了什么数据
单体仓库分支 + 数百个 git 仓库 + 多套构建/制品系统。
人还管哪一步
向客户打补丁前仍需 QA 与测试。审慎方法，而不是发出未测修复。
多久上线
2 天 / 几天内识别每一个实例。JMSAppender：几乎不到五分钟看到、修复并发送发布。不到四天完成全部客户补丁。三次连续补丁。

给现场的人

主要用在哪
Sourcegraph 查询以识别每一个 Log4j 实例；几乎不到五分钟内完成 JMSAppender 查找-修复-发布；共享搜索上下文，使团队能核验存在/不存在。
以前怎么干
多套构建与制品系统；带许多组件分支的大型单体仓库；数百个 git 仓库。替代方案本会是问每个组件负责人或扫描/手工构建检查。
卡在哪
这个缺陷「无处不在又无处可寻。」多套源代码控制系统。正值假期。Grep/OpenGrok 会很痛苦。代码扫描慢；手工检查并不万无一失。
用了什么模型
Sourcegraph 代码搜索（未点名 Cody/LLM）。
怎么验收
识别时间、向客户打补丁时间、已找到每一个实例的信心。三次连续补丁。客户对速度与质量的反馈（定性）。
怎么上线
Log4j 消息传来时已在使用 Sourcegraph。
失败了怎么改
没有 Sourcegraph：驱赶组件负责人或在仓库里磕磕绊绊。Grep/OpenGrok 被点名为痛苦。
能不能复用到下一家
准备用同样方式查找/修复下一个开源漏洞。Sourcegraph 也为其他公司发布了 Log4j 搜索博客。
能直接跑一份报告说「在这儿」或「不在这儿」，这很好。这比不得不说「老板，我觉得我们都搞定了」好得多。——Jon Kohler，Nutanix Technical Director of Solution Engineering

备注

Sourcegraph 官方案例（抓取 2026-08-29）。具名 Jon Kohler。5 分钟 / 2 天 / 4 天 / 三次补丁 / 100% 识别在页上。100% 是 Nutanix 陈述的信心，不是独立审计。Log4j 10/10 CVSS 与 FTC「无处不在」是背景，不是 Sourcegraph 结果。
