The Citation Group 如何用 Devin 衡量工程 ROI

Citation Group 是合规、风险管理和认证技术及服务的领先供应商，覆盖 HR、健康安全、ISO 认证和网络安全等领域。他们为英国、加拿大、澳大利亚和新西兰的 125,000 多家中小企业提供支持。

公司由私募股权支持，通过收购扩张，面临工程产出规模化、遗留系统、分布式团队和技术债务堆积的挑战。

工程负责人需要可靠方法评估 Devin 是否产出生产级代码。传统 sprint 速度指标波动太大，无法单独衡量 Devin 的影响。分布式团队和合作开发者担心 AI 生成的变更可能达不到人工标准，反而增加技术债务。

团队先把 Devin 接入一组项目，按 pull request 级别衡量质量。前三个月，271 个 Devin PR 经资深工程师审查后合并，成功率 80%。

“通过直接跟踪 Devin 的 pull request，我们终于得到清晰的生产级影响信号。”——Anthony Wray，AI Engineering Lead

Citation 先通过内部和合作团队举办的黑客松引入 Devin。每支团队指定负责人记录结果并分享做法。早期项目中，提示不结构化时结果不稳定；把任务拆到 Jira、写清验收条件，再把文档直接拉进 Devin 会话，生成的 PR 就能通过审查。

三项做法最关键：
Jira 工单拆分，定义清晰验收标准。
Devin search-to-session，直接把文档和架构上下文拉进编码会话。
Markdown 规格文件，提供结构化输入，减少歧义。

“把 Devin 和结构化规格配对后，结果变得稳定。我们建立了一套工程师信得过的可重复模式。”——Wray

工作流建立后，Citation 把 Devin 应用到多类项目：

遗留系统现代化：一个合规工具原估三月迁移（.NET Framework + AngularJS → .NET Core + React 18），Devin 两周就拿出可用原型。它把单体拆成清晰架构，从界面到数据库端到端交付垂直切片，静态分析和自动化测试覆盖率超过 90%。

积压任务吞吐：原本 sprint 间滑动的依赖升级和 bug 修复被持续完成。一个纠正动作功能里，Devin 贡献 147 个合并 PR，约 367 个故事点，相当于把多 sprint 的 epic 几周内交付。

非工程师调试：业务分析师用 Devin 直接查询代码库，解释异常行为。一位 BA 发现细微前缀不匹配，提交 PR 后获资深工程师批准，避免了面向客户的 bug。

客户支持：Devin 自动分析 help desk 工单根因，减少升级到工程团队的问题。

快速原型：工程师用 Devin 几天内做出工作原型，包括扩展现有工具和测试新功能，这些工作原本要等团队完成核心交付后才能排上。

Devin 现已成为 Citation 日常工程实践的一部分。工程师每周运行 180 多次会话，GitHub 上累计记录超过 1,200 次。从黑客松里的限定项目起步，已扩展到工程组织日常生产使用，业务分析师和支持团队也开始采用。

“Devin 不只是另一个工具。要拿到价值，必须改变工作方式。改变后，它开始交付我们原本达不到的结果。”——Anthony Wray

Citation 计划未来十二个月在平台现代化和遗留升级中扩大 Devin 的角色。团队还在推进更深流程整合，包括自动 Jira 拆分和标准化规格文件，让 AI 驱动的开发更可预测。

对 Anthony Wray 来说，意义不止于吞吐量。“真正价值在于它迫使我们重新思考流程。你不能把 AI 简单贴在旧工作方式上，必须为现在可能做到的事重新设计。”——Anthony Wray

给负责人

要解决什么
在遗留系统、分布式团队和合作方开发者之间扩大工程产出，同时证明 AI 生成的 PR 达到与人类相同的标准。
结果
前三个月合并 271 条 PR，合并率 80%。前 3 个月工程产出效率（ACU-to-PR 比率）提升 50%。页首：遗留应用刷新时间减少 85%；正文：原估计三个月的 .NET/AngularJS 迁移，两周内做出可运行原型，覆盖率高于 90%。一项功能：147 条已合并 PR / 约 367 故事点（速览表也写 147 条 PR 合计约 300 故事点）。每周 180+ 次会话；累计 1,200+ 次 GitHub 会话。
接了哪些系统
黑客松 AI 倡导者；Jira 范围划定；search-to-session；计划中的自动化 Jira 范围划定。
用了什么数据
Jira 工单；markdown 规格；经 Devin search-to-session 拉取的文档；GitHub 会话。
人还管哪一步
每一条计入的已合并 PR 都经资深工程师评审。BA 提交 PR 待审批。支持团队在升级前用 Devin 做 RCA。
多久上线
前三个月：271 条已合并 PR。遗留原型两周完成，原估计三个月。

给现场的人

主要用在哪
遗留合规工具迁移（.NET Framework + AngularJS → .NET Core + React 18）；待办史诗；BA 调试；服务台 RCA；快速 POC。
以前怎么干
Sprint 速率噪声太大，无法单独衡量 Devin 的影响。早期黑客松中非结构化提示词产出不稳定。
卡在哪
担心 AI 改动会增加技术债。中优先级升级/缺陷从一个 sprint 拖到下一个。
用了什么模型
Devin
事情怎么流转
结构化规格 → Devin 会话 → 提交 PR 供资深评审。遗留系统：拆解单体、从 UI 到 DB 的垂直切片、静态分析与测试。
怎么验收
已合并 PR 与合并率；ACU-to-PR 效率；故事点；每周/累计会话。
怎么上线
日常使用；每周 180+ 次会话；上线以来 1,200+ 次 GitHub 会话。采用范围扩展到 BA 与支持团队。
失败了怎么改
非结构化提示词结果不稳定，直到采用 Jira + 文档 + markdown 规格。
能不能复用到下一家
可重复模式：Jira 范围划定、search-to-session、markdown 规格；ACU-to-PR 指标。
通过直接跟踪 Devin 的 pull request，我们终于有了干净、生产级的影响信号。——Anthony Wray，AI Engineering Lead
