提高生产力、加强安全：Sourcegraph 怎样改了 Nine 的开发工作流

Nine 靠高级 Code Search 和 Batch Changes，每年省下 1,200 小时和 $276K，同时能顺畅做大规模代码维护，并在微服务架构里高效共享知识。Nine 生产力团队工程经理 Conor Holmes 讲，Sourcegraph 产品怎样改了他们的开发工作流：开发者更高效、代码更好管、安全也更强。靠 Code Search 和 Batch Changes，Nine 预计能让平台工程团队的 30 名开发者每年最多省下 1200 小时，使用六个月就能省 $276K。Sourcegraph 的 Code Search 对 Nine 开发者很有用：在庞大代码库里更快找到信息，好做有依据的决定。

给负责人

要解决什么
跨数百个仓库搜索模式与依赖，并停止为统一基础设施即代码/持续集成和去重手工开数百个合并请求。
结果
页上主角：Platform Engineering 估计节省 $276,000；经 Batch Changes 每年节省 1,200 小时。导语：「Nine 每年节省 1,200 小时和 $276K。」正文：「Nine 预测 Sourcegraph 将为其 Platform Engineering 团队的 30 名开发者在六个月使用期内每年最多节省 1200 小时和 $276K。」按估计/预测报告——不要把预测/最多/六个月措辞当作已确认的过去一年实际值。
接了哪些系统
在 AWS + Kubernetes 上自托管；点名 Aurora 数据库与日志。Batch Changes 跨仓库/代码托管打开变更集。
用了什么数据
跨多个代码托管的数百个仓库；微服务；IaC/CI/CD。
人还管哪一步
工程师仍审查批量变更集。SME 在改代码前用搜索获取上下文。

给现场的人

主要用在哪
全局搜索代替克隆/脚本；脚本化批量变更代替数百个合并请求；基础设施即代码与持续集成重构；跨仓库的安全相关变更；5 秒片段+仓库列表查找（Todd Turner）。
以前怎么干
跨仓库搜索有限。工程师手工为统一变更创建数百个合并请求。知识分散；业务专家把时间花在手工任务上。
卡在哪
平台随许多微服务和工具扩张。代码重复明显。安全响应需要先找到漏洞再改许多仓库。
用了什么模型
Sourcegraph Code Search + Batch Changes + 代码监控（未点名 Cody/LLM）。
怎么验收
英雄与正文发布估计/预测的 $276K 与 1,200 小时数字（见 measured_outcome / evidence_note）。
怎么上线
平台团队在 AWS/Kubernetes 上托管 Sourcegraph；部署到他们的集群「相当直接」。
失败了怎么改
手工数百个 PR 的工作流以及克隆或脚本搜索。
今天下午 Sourcegraph 帮我大约 5 秒就答了一个问题。正常我大概会去烦一堆人，但「这是那段片段，以及使用它的仓库列表」这个总览让它成了自助。——Todd Turner，Platform Engineer @ Nine
