GoFundMe 以送达的帮助衡量工程速度

GoFundMe 与 Augment Code 合作。

GoFundMe 的存在就是为了帮助人们互相帮助。对首席产品和技术官 Arnie Katz 来说，这个使命直接反映在运营上：每周缩短的周期时间、清理的积压工单、加快上线的功能，都能让更多资金更快到达需要帮助的人和非营利组织。团队有 400 名技术人员，速度不再是虚荣指标，而是必须。

GoFundMe 是 Augment Code 的早期客户之一。那时大模型刚出现，AI 辅助开发还停留在自动补全阶段。工程师们从点击 Tab 补全开始，收益有限；现在他们已经运行起横跨前端、后端、性能、安全、测试、隐私合规的夜间多代理工作流。每天早上，工程师们看到的就是已审查、随时可合并的 PR 队列。曾经需要数月的 PRD 到 PR 周期，现在大幅缩短。代码审查代理在某些场景下把周期时间减少了一到两天。

“我们现在远远超出了 AI 只是加快打字的阶段，”Katz 说，“利用的关键路径是上下文，然后是意图，最后是自动化。”

Arnie 描述了一次和产品经理、设计师、一名工程师的会议。他们录下自己讨论 Giving Funds（GoFundMe 的免手续费捐赠咨询基金产品）新支付类型的过程：边界情况、防护措施、正常流程。一小时的对话。ChatGPT 把录音转成规格。Augment 再用这个规格在另一小时内完成了前端、后端、功能开关。三个人的两小时，换来原本需要几个月的工作。

这种结果改变了团队对“值得做什么”的判断。

支持团队成员注意到 PDF 收据的 recurring bug，因为他们一直在接相关电话。他们用 Augment 追踪根因、提出修复方案，并为工程师打开一个待审 PR。一位有财务背景的产品经理在 45 分钟的航班上完成并上线了一个功能：她口述需求、生成计划、拆解任务交给 Augment。落地后她向工程师们讲解 PR，功能直接上线。

“这真正扩大了能构建、能成功贡献的人群，”他说，“不再只有工程师才能做到。”

过去因为不划算而一直不动的积压，现在开始清零。原本需要产品、设计、工程两月交接的功能，现在几小时就能上线。原本要等系统宕机才暴露的性能漏洞，现在一夜之间就能被发现。

对 GoFundMe 来说，结果是工程团队越来越聚焦在需要判断力的工作上：架构、产品意图、接下来要做什么，而代理负责执行。Arnie 已经每天和团队里角色从手写代码转向其他工作的工程师对话，他预计这个数字还会增长。

“目标不是让 AI 写代码，”他说，“目标是在保持高安全、可靠和信任的前提下更快交付结果。”

对于一个每天把数十亿美元送往人们关心的事业的平台，这已经不是一个工程故事，而是使命本身。

给负责人

要解决什么
把周期时间压短，让更多钱更快到个人和非营利组织手里。速度被当成使命，不是虚荣指标。
结果
400 名技术人。代码审查智能体在某些情况下把周期时间减 1–2 天。Giving Funds 新支付类型：一小时讨论 + 一小时 Augment 实现（前端、后端、功能开关），对照此前数月。需求文档到 PR 比数月「显著更少」——页上没有替代数字。支持发起的 PDF 收据 PR 和 45 分钟航班交付是轶事，不是组织比率。
接了哪些系统
覆盖前端、后端、性能、安全、测试、隐私和合规的多 agent 工作流。ChatGPT 用于将录音转为规格（页面）。
用了什么数据
产品对话录音；规格；生产代码库；支持报告的 bug。
人还管哪一步
工程师审查 PR（包括 45 分钟航班上的 PR）。判断仍在架构、产品意图以及构建什么上。部分工程师的角色已从动手编码转移开（未给出人数）。
多久上线
PRD 到 PR：曾经数月，现在「显著更少时间」（页面未给出新时长）。代码审查 agent：在某些情况下周期时间减少一到两天。Giving Funds 支付类型：三人约 2 小时 vs 此前数月。一个 PM 功能：45 分钟航班到 PR，然后经工程师讲解后上生产。

给现场的人

主要用在哪
隔夜多智能体 PR 队列。录了 1 小时关于新 Giving Funds 支付类型的产品/设计/工程讨论 → ChatGPT 规格 → Augment 又一个小时做出前端、后端、功能开关。支持同事追 PDF 收据缺陷并开了 PR。金融背景的产品经理在 45 分钟航班上交了一个功能。
以前怎么干
早期 Augment 客户：从 tab 补全开始，收益有限；后来变成覆盖前端、后端、性能、安全、测试、隐私/合规的隔夜多智能体工作流。
卡在哪
需求文档到 PR 曾经要数月；从没划算过的积压；产品、设计、工程之间交接。
用了什么模型
Augment Code（页面：Context Engine / agents / completions；除非另有注明，无单一模型名）。
事情怎么流转
隔夜 agent 产出经审查、可合并的 PR。非工程师（支持、PM）用 Augment 提出修复/功能供工程师审查。
怎么验收
代码审查 agent 周期时间减少「在某些情况下」。轶事性日历对比（数月 → 两小时；45 分钟航班）。
怎么上线
400 名技术人。经审查 PR 的早间队列。
失败了怎么改
自动补全时代只产生有限收益。
能不能复用到下一家
agent 工厂运营模型；扩大谁能贡献。
我们现在远远、远远超出了 AI 只是解锁更快打字。杠杆路径是上下文，然后意图，然后自动化。——Arnie Katz, Chief Product and Technology Officer, GoFundMe
