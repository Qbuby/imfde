Tyson：用 AIP + Ontology SDK 做系统迁移（AIPCon 2024 年 9 月）

AIPCon 演示海报写的是 AIP + Ontology SDK 做系统迁移。问题：2019 到 2021 年，Tyson 在 Google Cloud 上做了一套数据分析平台。到 2023 年，数据快速增长带来扩展、性能和成本上的显著挑战。数据延迟、云费用飙升、对数据过程可见性差，开始影响业务运营。

为应对这些问题，Tyson 决定从遗留数据平台 ACE 迁到 DBT Cloud。迁移比预想更难，造成资源紧张，还需要专门技能。为走通这些挑战并保证平稳过渡，Tyson 请来 Palantir。

方案：用 Foundry 和 AIP，Tyson 部署了一套工作流，自动把代码从 ACE 译到 DBT。过程由 AIP Logic 配 GPT-4o、Automate、Ontology 和 Ontology SDK 驱动，自动执行，并把人的反馈算进去。结果：一个最初预计要 10–15 人、三年完成的项目，由一个人在 3–4 个月做完。

工作流。Seeding：摄入全部遗留 ACE 模型和当前 DBT 译文，用 Palantir OSDK 把模型和译文加载进 GitLab。这一步的关键是对模型内容做 embedding 和向量化，好做有效语义搜索。Insights：目标是教语言模型怎么把 ACE 模型译成 DBT。通过分析以往译文生成可行动洞察和规则，不必额外微调成本。人审阅并批准这些学习。Translation：先用语义搜索找出相似的已批准译文，语言模型再应用学到的规则并纳入用户反馈后执行翻译。OSDK ping DBT 做外部语法和编译检查。Feedback：用户在 Feedback Cockpit 审阅并批准译文，也可加反馈触发重译。Harvesting：已批准译文和配置用 Ontology SDK 推到 GitLab，准备做标准 DBT 测试并合入生产。

给负责人

要解决什么
遗留数据平台（Google Cloud 上的 ACE，2019–2021）到 2023 年碰上扩展、性能和成本问题（数据延迟、云成本飙升、看不清）。ACE→DBT Cloud 迁移比预期更难，把人拖住。
结果
一项 10–15 人 / 3 年的迁移由单人在 3–4 个月内完成。
接了哪些系统
Foundry + AIP；Ontology SDK (OSDK) ping DBT 做语法/编译检查；回写 GitLab。
用了什么数据
遗留 ACE 模型、DBT 译文、GitLab 仓库、模型内容 embeddings。
人还管哪一步
用户在 Feedback Cockpit 中审核/批准译文；可添加反馈触发重新翻译；对生成的洞察进行人工监督。
多久上线
项目预期 10-15 人 / 3 年 -> 由 1 人在 3-4 个月内完成。

给现场的人

主要用在哪
AIP 驱动的自动化 ACE→DBT 代码翻译：对已批准译文做语义搜索、经 AIP Logic 调 GPT-4o、Automate、Ontology + Ontology SDK；人工在环反馈驾驶舱；harvest 到 GitLab；seed/embed/vectorize；无需微调即可生成洞察。
以前怎么干
手工、很吃人的迁移，最初范围是 10–15 人、3 年。
卡在哪
迁移需要专业技能，而且是重大资源消耗。
用了什么模型
经 AIP Logic 调用 GPT-4o；语义搜索 + 已学习的翻译规则；模型内容向量化。
事情怎么流转
翻译 -> 反馈 -> Harvesting -> Seeding -> Insights，带重新翻译循环。
怎么上线
与 Palantir 在 Foundry + AIP 上构建。
