公司自己讲的数字 · 一般

构建背后：Imprint 上一个 agent，覆盖多个品牌

金融服务。Behind the Build 是一套系列，Sierra 客户讲他们怎样设计、部署并放大 AI agent。Imprint 给 Booking.com、Shell、Rakuten 这类品牌做联名信用卡。每一段合作都意味着一批新客户：他们不觉得自己是 Imprint 持卡人，而是 Booking.com 持卡人或 Rakuten 持卡人。品牌永远在前。「如果他们只听到 Imprint，他们知道自己是 Imprint 客户；可要真正有家的感觉，他们想听到『你的 Rakuten 卡，由 Imprint 提供支持』，」Imprint CTO Will Larson 说。「这对持卡人才对味，对我们合作的品牌也是。」每个触点都要反映伙伴品牌、而不是 Imprint，这个预期塑造了公司建的一切。

给负责人

要解决什么
同一个智能体必须变成 Booking.com / Shell / Rakuten 等——各自有自己的声音——同时赞助银行能审计每一项行为。
结果
对最常见任务（余额、付款、新卡），智能体比人更快：无需等待、立即核验。官方页面无拦截率或 CSAT 百分比。
接了哪些系统
Sierra Agent Studio 配置层；供审计员使用的模拟测试日志；计划通过手机生物识别做应用内预鉴权。
用了什么数据
卡片账户工具；品牌覆盖配置（语气、发音、持卡人名词）。
人还管哪一步
复杂判断仍由支持团队处理；持卡人可强制升级；每次互动自动分类以填补缺口。
怎么交给客户
Will Larson，CTO，Imprint。

给现场的人

主要用在哪
基于模式的智能体：未登录 / 登录中 / 已登录 / 多账户；各模式对应工具；verbatim 标签用于必须出现的法律用语；供银行使用的模拟日志。
以前怎么干
有人值班时人工支持很彻底，但队列会积压，非工作时间并不总可用；品牌感停留在表面。
卡在哪
IVR 树状图对审计员可读；追求目标的智能体则不然。需要鉴权 + 逐字法律用语。
用了什么模型
带 Agent Studio 覆盖的 Sierra 智能体。
事情怎么流转
基线智能体 + 品牌覆盖；在已文档化的模式内做目标导向的工具调用；目前用 OTP，下一步是应用内生物识别。
怎么验收
常见任务上相对人工的速度（定性）；互动 vs 强制升级（页上无百分比）。
怎么上线
跨合作品牌的语音/电话智能体；正在扩展到应用内预鉴权。
能不能复用到下一家
一个平台、通过覆盖服务多个品牌；语音可能成为上线新工具最快的渠道。
持卡人和合作伙伴都不关心我们的成本结构。我们真正想先搞清楚的是如何做出出色体验。然后再以可负担的成本做到。——Will Larson，CTO，Imprint

备注

Sierra 官方 Behind the Build 页面。第一方定性（常见任务快于人工；银行批准的模式架构）。无数字拦截率/CSAT。
