Warp

公司自己讲的数字 · 比较可靠

创业公司 Warp 押注用 GPT-5.5 做开源构建

Warp 用 GPT-5.5 在本地、云和开源工作流里编排 agent。页上数字：GPT-5.5 每任务少用 30% token；内部 pull request 的 90% 由 agent 创建。

Warp 起步是现代终端。编码 agent 从实验变成日常工程后，Warp 看见终端成了开发者跟 agent 一起干活的自然地点。今年它开源终端客户端，OpenAI 是仓库的创始赞助方，同时推出 Open Agentic Development：人定义目标和监督结果，agent 规划、写代码、测改动、开 pull request。内部基准里，GPT-5.5 每个 agentic 编码任务比 GPT-5.4 少用 30% token。今天 Warp 有近 100 万开发者，被超过 56% 的 Fortune 500 使用。在 Warp 自己的工程组织里，agent 现在共同创建大约 90% 的公司 pull request。CEO Zach Lloyd：「我们觉得跟社区一起监督一队 agent，能更快交出更好的 Warp。OpenAI 模型帮这种系统所需的长程编码工作长期可持续。」

Open Agentic Development 的赌是：agent 写代码，开发者指定意图、核输出、决定最终发什么。这些选择变成可复用上下文。编排够好，Warp 相信 agent 能产出比松散协调的一群人更一致的代码。开源将更少是人直接贡献实现，更多是贡献只有人能给的产品判断和共享愿景。持久、并行的 agent 需要共享记忆、可复现环境、评测、权限和协调方式。Warp 建了云编排平台 Oz，管本地和云环境里的 agent。开源贡献相关的 agent 用 GPT-5.5。OpenAI 模型在 Warp 内部评测里，对涉及推理、规划、代码生成和代码评审的长程工程任务表现也很强。

Oz 当控制平面：经 web 界面启动 agent、选预定义技能和环境、选模型和托管配置、集中监控长跑工作流。agent 可远程继续跑，开发者检查现场会话、在云和本地之间交接而不丢上下文。Oz 也支持像定时 cron 一样的循环工作流。用上下文压缩、持久记忆、以及代码搜索和文件分析的专用子 agent，帮长工作流保持可靠。任务按类型和难度分类，更复杂的编码和推理走更强模型配置。Warp 还把 OpenAI 模型当评测管线里的 LLM-as-a-judge。Lloyd：「我们发现 OpenAI 模型经常给出前沿级智力，完成同样任务用的 token 和轮次更少。尤其擅长要在大问题空间上推理的编码任务。」

到目前这场赌看起来在回报。Warp 的 ARR 去年增 35x，企业收入自 2025 年 Q4 起升超过 500%。公司说增长很大一块来自想更灵活规模化 agent 工作流的组织。底层工作流仍早、仍高度实验。Lloyd：「没人确切知道 agentic 开发的未来长什么样。我们觉得社区应该能参与塑造它。」

给负责人

要解决什么
把长时运行的智能体工作流（可观测性、协调、记忆、人工审阅）铺开，并公开写软件。
结果
GPT-5.5 每个智能体编码任务比 GPT-5.4 少用 30% token。智能体现共同创建 Warp 约 90% 的 pull request。Warp 的 ARR 去年增长 35 倍，企业收入自 2025 年 Q4 起上升超过 500%。Warp 有近 100 万开发者，被超过 56% 的财富 500 强使用。
接了哪些系统
Oz 控制面经 web UI 启动/监控 agent；评估管道中 OpenAI 模型作为 LLM-as-judge；GPT-5.5 路由到苛求的编码/推理任务
用了什么数据
开源仓库；内部基准；长时编码工作流
人还管哪一步
人定义目标、监督结果、核验输出并决定交付什么

给现场的人

主要用在哪
Open Agentic Development（人定目标，智能体规划/编写/测试/开 PR）在 Warp 的开源终端上；Oz 云编排平台跨本地和云协调智能体。
以前怎么干
不适用（以终端为中心的开发）。
卡在哪
长视野编码需要撑得住的编排和监督。
用了什么模型
GPT-5.5（API）
事情怎么流转
Agent 规划工作、写代码、测试变更并开 pull request；Oz 使用语境压缩、持久记忆和专用 subagent；选择成为未来 agent 可复用的语境
怎么验收
内部基准；GPT-5.5 每个 agentic 编码任务比 GPT-5.4 少用 30% token；OpenAI 模型用作 LLM-as-judge
能不能复用到下一家
开源终端客户端；Oz 编排平台
