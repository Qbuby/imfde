Observe, Inc. 用 Augment 越过 IntelliSense 上限，提高生产力

故事。Observe, Inc. 怎样在复杂代码库里用 Augment 解决 IntelliSense 问题。补全更快更准、代码更好懂，开发者更高效，入职时间缩短，工作流也稳住了。

挑战。领先的可观测性平台 Observe, Inc. 技术栈又大又复杂。前端是 TypeScript 和 React，后端用 GraphQL、Go、Kubernetes，还有为自定义查询语言写的 C++。传统工具比如 VS Code 的 IntelliSense 跟不上代码规模，建议很差甚至没有。「我们代码库太大，TypeScript 服务器根本跟不上……VS Code 基本没法好好用，」Observe 主任软件工程师 Erica Gucciardo 说。

给负责人

要解决什么
在代码库大到 VS Code IntelliSense / TypeScript 服务器几乎无法工作的情况下，保持开发者生产力。
结果
页上无数字组织 KPI。定性：比 IntelliSense 更快/更好；减少入职摩擦；按指令重构。
接了哪些系统
VS Code 与 IntelliJ。
用了什么数据
Observe 的大型多语言代码库。
人还管哪一步
Staff 工程师 Erica Gucciardo 仍阅读并接受建议；向新加入者推荐 Augment。
多久上线
入职被描述为更快；无周/月数字。

给现场的人

主要用在哪
胜过 IntelliSense 的补全；为非 Go 读者注释/解释 Go；整文件重构指令。
以前怎么干
VS Code IntelliSense 在规模上挣扎；建议差或几乎没有。前端 TypeScript/React；后端 GraphQL、Go、Kubernetes、C++ 定制查询语言。
卡在哪
TypeScript 服务器跟不上；开发者在补全和阅读不熟悉的 Go 上受阻。
用了什么模型
Augment Code（页上：Context Engine / agent / 补全；除非另有说明，无单个模型名）。
事情怎么流转
补全加上聊天/指令（高亮一个文件，要求重写；请它注释代码）。
怎么验收
对照 IntelliSense 速度/质量的定性。无数字生产力表。
怎么上线
团队规模 70。向新加入者推荐。
失败了怎么改
IntelliSense 在代码库规模上不可用。
我们的代码库太大，TypeScript 服务器没法真正跟上……VS Code 基本上几乎没法用。——Erica Gucciardo，Observe Staff Software Engineer
