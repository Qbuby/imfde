给负责人

要解决什么
如何为 FDE 岗位筛选：多数候选人在技术 half 与咨询 half 中只占一半，而角色两者缺一不可
接了哪些系统
REST、GraphQL 或事件驱动集成；安全处理第三方 SDK 与 webhook，涉及资金或数据时用幂等模式
多久上线
从零全职招聘通常 8–14 周；人员增补可在数天内开始；预筛管线可把全职搜索压到数周
怎么交给客户
要求文档与交接能脱离具体工程师存活（架构说明与 runbook，而非口头传承）

给现场的人

以前怎么干
多数招聘团队把 FDE 当后端工程师筛、或当解决方案架构师筛，只测了工作的一半
卡在哪
70% 以上 AI 试点死在上生产之前
事情怎么流转
要求 RAG 与 agent 编排的工作知识
怎么验收
五维评估矩阵（weak signal vs hire signal）：Coding（只会 leetcode 无生产经验 vs 交付并维护过线上 AI 系统）；Client discovery（照单全收表面需求 vs 挖到表面诉求背后的真实约束）；Debugging（只在 dev 环境调试 vs 在压力下修过线上故障）；Documentation（只留下 tribal knowledge vs 写他人可用的 ADR 与 runbook）；Ownership（部署完就交差 vs 上线后追踪采用率并迭代）。面试问法：问上线后什么坏了，而不是黑客松里做了什么；用与真实技术栈和约束绑定的 scoped work sample
失败了怎么改
红旗：只有简历上的 FDE 经验（2025 年前该头衔罕见，长期履历站不住）；没有生产环境 war story；纯技术或纯咨询背景；没有文档习惯（招进来的是瓶颈而非 owner）；部署确实需要时仍不愿出差
如果你筛的候选人自称 FDE，但描述的是售前 demo 工作，你评估的是换了标签的解决方案工程师。
