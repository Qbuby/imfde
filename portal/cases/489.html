影响研究：用 Palantir Foundry 加速互操作性（2022，美国政府机构）

2022 年影响研究：Accelerating Interoperability with Palantir Foundry。文首写信息专有、仅供告知；其中数据是 notional。一家大型美国政府机构数据生态由异构系统组成，孤岛环境急需要数据和分析平台之间的互操作。机构立了互操作框架，并做 Foundry 概念验证：已在 Foundry 里配好的集成数据转换管道，能否在平台外复用，以免锁定。

第三方软件咨询（validator）测 Foundry 和一套开放架构组件平台能否双向交换。Phase 1：从 Foundry 抽出数据、代码和元数据，重建并在第三方平台跑管道逻辑，确认两边产出同一数据集和结果。Foundry 的 API 和 Git 支持的逻辑仓库让逻辑能快速抽出。Phase 2：从第三方平台把一次性抽出的数据、属性和元数据经配置好的连接器拷进 Foundry。评估期间第三方平台不支持导出逻辑，只导出数据和元数据。结论：Foundry 被认定为开放且可互操作，其能力成为该机构评估所有其他 IT 投资的互操作标准。没有业务美元 KPI，是技术验证。

给负责人

要解决什么
不断增长、异构的数据生态需要在孤岛化的数据/分析平台之间实现互操作，以避免厂商锁定；机构需要保证数据、逻辑和元数据能在 Foundry 之外被复用。
结果
Foundry 被视为开放/可互操作；其能力成为该机构评估所有其他 IT 投资的标准。（无业务金额 KPI；技术验证。）
接了哪些系统
Foundry REST API；Git 支持的逻辑仓库；用于持续接入的可配置数据连接器。
用了什么数据
机构特定配置的数据模型、本体子集、源数据集、元数据。
人还管哪一步
政策专家维护规则；验证方执行导出；Palantir 就库镜像提供咨询。
多久上线
不适用（互操作性验证 PoC）。
驻场怎么写的
Palantir 在互操作性测试期间与验证方协商，镜像库并验证输出一致性。

给现场的人

主要用在哪
第三方验证方测试了通过开放 REST API 和 Git 支持的逻辑，在 Foundry 与第三方平台之间双向交换数据、代码和元数据；用相同输出复现了本体子集。
以前怎么干
孤岛系统；手工/有限的数据交换；锁定到单一平台的风险。
卡在哪
无法跨平台导出/再利用管线；合规/互操作强制要求。
怎么验收
验证方确认在第三方平台上重新生成的本体与原始 Foundry 子集之间没有差异。
怎么上线
与独立第三方软件咨询公司的概念验证。

备注

第一方 Foundry 互操作性影响研究 PDF；技术验证，无量化业务结果。
