McCarthy Holdings, Inc. 如何用 Glean 把分散的公司知识变成 AI 驱动的优势

McCarthy Holding Companies, Inc.（McCarthy）是 McCarthy Building Companies, Inc. 的控股公司，160 多年来一直在解决复杂的建筑难题。公司在美国几乎每个州都有业务，建造医院、数据中心、政府设施等，项目规模从不到 100 万美元到超过 10 亿美元不等。公司在全国有约 4000 名领薪员工，分布在办公室和活跃工地。

公司把对建筑的严谨规划也用在了技术上：每个工作流和工具都必须能切实提升安全、效率和决策。

在用 Glean 之前，公司有 1 亿个文件，涵盖几十年前的项目和每个岗位的详细文档。关键信息——政策、流程、项目记录、材料规格、历史数据——分散在 SharePoint、Microsoft Teams、Procore 等多个企业系统中。员工担心花时间找答案，却发现答案明明存在，却拿不到。

McCarthy 的数字团队评估了 Microsoft Copilot。Copilot 在做笔记和摘要上表现不错，但搜索和检索体验不透明，缺少团队想要的 LLM 灵活性和用户体验。跑完对比 POC 后，他们选择了 Glean。

Glean 上线后，界面更直观，搜索能跨系统进行。Glean 的企业知识图谱是自动从 McCarthy 自己的数据里建的，不依赖微软的图谱，团队获得了前所未有的控制力和透明度。

AI Platform Manager McKenzie Lewis 回忆：“一切都轻轻松松就完成了。”

对一个以微软为核心的公司来说，引入 Glean 不是替换现有工具，而是加一层安全层，让所有工具都更有用。Glean 的 LLM 无关架构意味着 McCarthy 不会被单一 AI 供应商锁定。

Glean 从一开始就被定位为内部 AI 实验层——一个受管控的环境，让全公司员工都能探索 AI 驱动的工作实际是什么样子。公司团队采用率很快达到 90%。现场和运营团队几个月内达到近 60%。

对 McCarthy 员工来说，最直接的影响是更快找到信息。以前需要跨多个系统翻找的知识，现在几秒就能出来。有一个用户几乎瞬间找到一个 14 年前的 3D 建筑模型文件——以前这需要多人花大量时间。

全公司估算，每名员工每周保守节省两小时，能更快做出决策。

借助 Glean 的 Agent 能力，McCarthy 团队开始构建和部署针对复杂数据密集型工作流的专用 Agent。他们已经上线多个核心和高级 Agent，包括：

产品团队的政策和流程审查 Agent：上线前两个月运行超过 4 万次，帮助各部门员工遵守公司指南。

HR 福利和 ERP 支持 Agent：员工能即时获得培训、福利和流程文档的准确答案，减少对 HR 支持的依赖，缩短入职时间。

监管情报（REGI）Agent：每周主动发送摘要，让项目负责人及时了解与建筑相关的行政命令、监管变化和拟议立法。

流程更新 Agent：重组或流程变化后，团队用 Glean 对比新旧流程矩阵，推荐需要更新的数千份受影响文档——以前这需要领导层手动花几周完成。

变更指令 Agent：已自动化部分贸易伙伴账单与合同条款核对流程，帮助人工同事审查超过 270 万美元的变更指令。

材料质量管理追踪 Agent：追踪失效材料在数十个活跃项目中的关联，现在几分钟就能完成，比任何手动流程都更快更完整。

Lewis 认为 McCarthy 的 AI Agent rollout 是行业竞争壁垒。“我们已经在从 AI 获得价值，而很多其他团队还在努力实现这一点。”

McCarthy 的 Agent 推广在开放和管控之间保持了平衡。任何员工都能用 Glean 在 Lewis 所说的“我们的 Agent 构建游乐场”里实验和创建，而一个较小的、经过审查的群体拥有公司范围部署的发布权——结构足够负责，开放程度足以推动全组织真正创新。

与绑定单一 AI 供应商的方案不同，Glean 的上下文系统和 LLM 灵活性让 McCarthy 团队能为每个用例选择最佳底层模型，并在不从头重建的情况下快速采用新能力。

采用数字反映了一个更难量化的东西：一支真正把 AI 当成工作方式的员工队伍。团队甚至创建了一个“Glean Help”Agent，让员工按自己的节奏学习 Glean。

对 Lewis 来说，结果不言自明。“我们觉得在这里做了一件真正棒的事。”

“我们把 Glean 当成构建 Agent 的游乐场——有护栏，我们把它开放给所有人。同时我们的专家开发高级 Agent、维护我们的库、帮助大家学习、量化 ROI 并分享成功。”

McCarthy 的 Glean 驱动 AI 路线图很简单：更多使用、更多 Agent、在工作发生的地方更深集成。计划与 Procore 的连接将把 Glean 的能力与 McCarthy 的主要施工管理环境结合在一起，让员工对公司知识有更大可见度。

给负责人

要解决什么
让 100 million 份文件和角色级文档可在 SharePoint、Teams、Procore 及其他系统中搜索，使现场和公司员工不再把时间花在找已经存在的答案上。
结果
保守估计每名员工每周节省 2 小时（叙述）。公司端采用 90%；现场/运营数月内几乎 60%。Policies 智能体最初两个月 >40,000 次运行。变更单智能体帮助评审超过 $2.7 million。页首回答 82K 个问题（说明错位）。Searles：新设备/材料业务单元超前进度 2–3 个月。
接了哪些系统
定位为 Microsoft 为中心技术栈上的一层，而非替代。知识图谱来自 McCarthy 数据而非 Microsoft 的图谱。计划下一步连接 Procore。
用了什么数据
约 100 million 份文件；SharePoint、Microsoft Teams、Procore 及其他企业系统。政策、程序、项目记录、材料规格、历史数据。贸易伙伴账单 vs 合同条款（变更单）。与建筑相关的行政令和立法（REGI）。
人还管哪一步
发布权限于核验小组。专家开发高级智能体、维护库、帮人学习、量化 ROI、分享成功（Lewis）。变更单智能体协助人类对应角色。
多久上线
Ibong：过去三个月的成果。Searles：超前进度两到三个月。Policies 智能体最初两个月 40,000 次运行。无第一天日历日期。
怎么交给客户
Glean Help Agent 按员工自己的方式教他们用 Glean。专家帮人学习并分享成功。

给现场的人

主要用在哪
跨系统企业搜索。智能体：Policies and procedure reviews（使用最多）；HR Benefit and ERP Support；Regulatory Intelligence REGI（每周摘要）；Procedural Update Agent；Change Order Agent；Materials Quality Management Tracking；教人用 Glean 的 Glean Help Agent。
以前怎么干
知识分散在 SharePoint、Microsoft Teams、Procore 及其他企业系统。数字化团队评估过 Microsoft Copilot：擅长记笔记/摘要，但搜索/检索不透明，且缺少他们想要的 LLM 灵活性和 UX。头对头 POC，然后选 Glean。
卡在哪
员工担心把时间浪费在搜索某处已有的答案上。现场劳动力分散在在建工地。Copilot 搜索/检索不透明。
用了什么模型
Glean 搜索 + 智能体。LLM 无关 / 可替换 LLM（Lewis）。评估过 Copilot 且未选作搜索。未为特定智能体点名基础模型。
事情怎么流转
Policies 智能体在最初两个月记录了超过 40,000 次运行。HR 智能体回答培训/福利/程序问题。REGI 发送每周政策摘要。Procedural Update 比较新旧矩阵，并建议跨数千份文档的更新。Change Order 帮助核验贸易伙伴账单；已帮助评审超过 $2.7 million 的变更单。材料智能体跨数十个项目追踪失败材料。任何员工都可以试验；较小的核验小组做全公司发布。
怎么验收
保守估计：每名员工每周节省两小时。公司端采用很快到 90%；现场/运营在数月内几乎 60%。页首还印智能体评审的业主变更单 $2.7M+；回答 82K 个问题（该标签说明写「search time saved per employee, weekly」— 装饰不匹配）；公司参与 90%。
怎么上线
全公司试验层。公司端 90%；现场/运营数月内约 60%。约 4,000 名受薪员工在办公室和工地。
失败了怎么改
保留 Copilot 作为评估对照：笔记/摘要好，搜索不透明，无 LLM 灵活性 — 未选为搜索/AI 前门。
能不能复用到下一家
更多使用、更多智能体、更深集成。计划连接 Procore。材料质量智能体旨在主动的项目生命周期 / 规格交叉对照 — 是目标，不是已完成的 KPI。
Glean 是我们构建智能体的试验场 — 有护栏，我们已向所有人开放。同时我们的专家开发高级智能体、维护库、帮人学习并量化 ROI，并分享成功。——McKenzie Lewis，AI Platform Manager
