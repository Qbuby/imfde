Paystone

公司自己讲的数字 · 一般

Paystone 用 Augment Code 的代码库感知 AI 提高开发者生产力，并拿到能动手的洞察

故事。Paystone 怎样靠 Augment Code 的 AI 助手提高开发效率、处理代码隐私顾虑，并拿到有价值的数据指标。

挑战。Paystone 是忠诚度、口碑营销和支付方案的领先者，想用 AI 编码助手提高开发者生产力。技术栈语言多（PHP、TypeScript、JavaScript），代码库也大，新人不好上手。通用 AI 编码助手没有代码库上下文，建议常常不准。「要写精确的真代码，ChatGPT 对我来说不太行……通用还凑合，真要干实事，它还不到，」Paystone 技术负责人 Philippe Daniel Brin 说。

给负责人

要解决什么
在大型多语言代码库上提高开发者生产力，同时保持专有代码私密，并拿到领导层能用的使用指标。
结果
仅使用指标：「在某些情况下，Augment 为我的开发者每写的一行代码写出两行代码」。无交付时间或质量 KPI。
接了哪些系统
VS Code、IntelliJ；与 Augment 共享 Slack。
用了什么数据
Paystone PHP/TypeScript/JavaScript 代码库。
人还管哪一步
技术负责人 Philippe Daniel Brin；工程副总裁 Paul Dysko。

给现场的人

主要用在哪
上下文感知补全；关于助手如何影响代码补全的管理指标。
以前怎么干
通用助手（引用 ChatGPT）缺乏代码库上下文，对精确生产代码弱。新团队成员在栈上挣扎。
卡在哪
不准确的建议；代码离开的隐私担忧；没有好的参与指标。
用了什么模型
Augment Code（页上：Context Engine / agent / 补全；除非另有说明，无单个模型名）。
事情怎么流转
IDE 内补全。工程副总裁用产品分析看参与。
怎么验收
引用的产品指标：在某些情况下 Augment 每写两行，开发者写一行。
怎么上线
Paystone 工程。经开放 Slack 的合作。
失败了怎么改
ChatGPT「对通用用途还行」，但不适合精确生产代码。
在某些情况下，Augment 为我的开发者每写的一行代码写出两行代码……那是一个非常有意思的指标。——Paul Dysko，Paystone 工程副总裁

备注

官方 Augment 案例。具名 Philippe Daniel Brin 与 Paul Dysko。唯一量化主张是使用比率，不是结果 KPI。
