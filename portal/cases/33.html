WEX

公司自己讲的数字 · 比较可靠

自动化 SDLC，一次一个 agent

WEX 正在把软件开发全流程变成一串连起来的 AI agent，覆盖需求、写代码、审查、安全、部署。人类只管方向和意图，不再盯具体实现。

Bill Mayhew 是 WEX Benefits Platform Engineering 的 VP。有一次产品会议需要快速搞清一段后端流程。以前得找架构师约会，现在 Bill 直接在代码库里扔一句提示词，Augment 立刻吐出白话说明：目标、流程、作用。他把这段说明发给产品经理，产品经理再发给产品负责人，最后直接给 WEX Health & Benefits 团队做了现场演示，再到整个产品组织。Augment 不只是写代码的工具，它让复杂系统逻辑在工程师和领导之间快速流通。

WEX 是智能支付方案的全球领导者，每年处理数十亿美元的车队、健康和福利支付。2024 年初 Bill 开始评估 AI 编程工具，核心问题不是“能不能写代码”，而是“能不能理解我们庞大且互相连接的代码库”。他说：“我们的代码库又大又复杂。Augment 能跨代码库回答问题，上下文能力和解析能力很明显。”

WEX 正在把应用重构成统一平台，代码库感知是前提。

WEX 的理赔处理系统负责 FSA 报销和福利申请，复杂度很高。一次 webform 大重构原本排期 7-9 个月，他们让一名工程师用 5 天时间、固定提示词流程，再加上 Augment 的代码库上下文。第五天结束：新的 RESTful API 行为与旧系统一致，配套 UI 已进 QA，全量测试覆盖，数据库输出新旧一致。

Bill 说：“原本要团队花大半年的事，一个工程师 5 天就推进到能让客户测试。我们把与客户测试的时间提前了几个月，同时没降低 WEX 一贯的质量。”

日常里，WEX 工程师还用 Augment 快速处理合作伙伴的次要 backlog。一次，一个长期未解决的需求被扔进 Augment，工具几分钟就定位根因、给出带完整测试的修复方案。现在团队能把精力留在主产品路线图上，同时把长尾需求清掉。

WEX 把 SDLC 拆成阶段，一个个 agent 接力。

Stage 1：产品 intake
产品经理提交用例，agent 把问题按领域拆分，标出各团队负责范围，输出符合下游 agent 格式的 epics、stories、tasks。票据质量决定一切，他们把格式标准放在最前面。

Stage 2：代码生成
工程师在 VS Code 里引用工单，Augment 用上下文管道生成带架构感知的代码。

Stage 3：代码审查
审查 agent 已上线，正在评估接受率、问题类型和噪音降低。它先把明显问题清理一遍，再给同事看 PR。团队还在调校：agent 什么时候加分，什么时候添乱。

Stage 4：安全与 QA（设计中）
InfoSec agent 在每个 PR 上跑静态和动态安全测试，再交给 QA agent 验证预期行为。目前已在 VS Code 里用 Snyk 做编辑器内反馈。

给负责人

要解决什么
把开发生命周期每一次交接重塑成智能体串起来的流水线（需求、代码、评审、安全、部署），面向很大、互相耦合的代码库，包括一项范围定为七到九个月的理赔网页表单重构。
结果
理赔网页表单重构范围 7–9 个月：一名工程师五天内产出新 REST API、已进 QA 的 UI，以及匹配旧到新数据库输出的完整测试——「为我们与客户测试的时间砍掉了数月」。合作伙伴/长尾请求：根因 + 修复 + 测试，几分钟。评审/安全/部署智能体处于现场评估或路线图——不是结果。没有公布组织级 PIV 数字。
接了哪些系统
VS Code。计划中/部分完成：评审 agent；编辑器内 Snyk；未来的 InfoSec SAST/DAST 门禁和 QA agent。
用了什么数据
WEX 代码库；为下游 agent 格式化的工单；Snyk 已在 VS Code 中（既有，不是 Augment 的成果）。
人还管哪一步
人审方向和意图，而不是实现细节。评审 agent 校准仍在进行（信号 vs 摩擦）。Bill：完全自主的 SDLC 是他们逐步逼近的目标。
多久上线
理赔 webforms 重构：范围 7–9 个月 → 一名工程师，五天，取得显著进展（API + QA 中的 UI + 完整的输出匹配测试）。合作伙伴请求：带完整测试，几分钟。页面：「为我们与客户测试的时间砍掉了数月」。
怎么交给客户
更快地与 WEX 客户一起进入测试（已陈述）。向读者提供提示词手册。

给现场的人

主要用在哪
为期五天的理赔网页表单重构实验：新的 REST API 镜像旧行为，UI 已进 QA，完整测试匹配旧到新的数据库输出。长期存在的合作伙伴请求：根因 + 建议修复 + 完整测试，几分钟完成。正在评估实时代码评审智能体。InfoSec/QA 智能体处于设计中；部署智能体在路线图上。
以前怎么干
福利平台工程副总裁 Bill Mayhew 在 2024 年初评估了用于代码库级推理的 AI 编码工具。此前产品会议需要预约一名首席架构师。理赔网页表单重构范围为 7–9 个月。
卡在哪
大型复杂代码库；漫长重构；合作伙伴/长尾需求被核心路线图挤掉；开发生命周期交接需要评审和上下文。
用了什么模型
Augment Code（页面：Context Engine / agents / completions；除非另有说明，没有单一模型名）。
事情怎么流转
五阶段设计：（1）产品接入 agent → 映射到领域的 epics/stories/tasks；（2）引用工单、带架构上下文的代码生成；（3）实时评审 agent（接受率 / 问题类型 / 噪声——仍在校准）；（4）安全+QA 处于设计中；（5）部署在路线图上。北极星：完全自主的 PR-to-production，还要「一段时间」。
怎么验收
产品创新速度（PIV）= 从构思到交付客户。效率通过更广的速度指标跟踪；有说服力的证据是日常成果（5 天重构；下午处理的合作伙伴请求）。
怎么上线
Benefits Platform Engineering / WEX Health & Benefits。页面没有给出席位数。
失败了怎么改
评审 agent 的噪声 vs 信号仍在学习。未声称完全自主的 PR-to-production 已经完成。
能不能复用到下一家
工单质量标准，以便下游 agent 消费工作。页面发布了三条可复用提示词（遗留系统叙述、重构范围、长尾缺陷）。
原本需要一个团队用一年大部分时间才能推进的事——一名工程师在短短五天内就取得了显著进展。我会称之为出色的结果。——Bill Mayhew，Benefits Engineering 副总裁，WEX

备注

官方 Augment 案例。具名 Bill Mayhew。量化：7–9 个月理赔重构 → 5 天工程师实验，含 API+QA UI+测试；合作伙伴修复在几分钟内。PIV 是跟踪指标但没有公布数字。后续 SDLC 阶段处于设计/路线图。
