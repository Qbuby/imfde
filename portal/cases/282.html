Circles 用 OpenAI 技术驱动电信个性化

Circles 用 OpenAI API 做个性化支持、实时解决问题，在新加坡这类市场带来 22% 的 ARPU 增长。页上数字：新加坡 AI 驱动个性化让 ARPU 增加 22%；引入 AI 推荐后 churn 降 9%；CareX 客服自主解决率 65%；用 Codex 做设计、编码协助和单元测试，开发效率增加 29%。

电信公司手里有用量、账单、网络活动和位置等信号，但很难及时变成个性化动作。Circles 用 OpenAI 搭一套 AI-native 电信栈，把支持、个性化、运营和变现在实时里接上。面向客户的入口是 AI Concierge，对话界面跑在 OpenAI API 上。Circles 2014 年在新加坡成立，SaaS 平台帮数字电信运营商上线和运营 AI 客户体验，自己也运营消费电信业务 Circles.Life，合作运营商覆盖 14 个国家、六大洲。

传统支持往往是事后反应：菜单、重复说明、出了问题再等。AI Concierge 把搜索、账户管理、支持和个性化推荐收进一次体验，按实时上下文（在看漫游套餐、在查账单）路由到专科 agent，不必让客户重复信息。Circles Global Chief Growth Officer Awais Malik：「AI 应该赋能用户，而不是把他们塞进过时旅程。OpenAI 的角色对 Circles 把这套愿景铺到全球很关键。」

CareX 是 Concierge 背后的自有多 agent 架构：编排 agent 看历史和当前活动，专科 agent 管账单、订阅、网络和账户。早期部署里，一家运营商第一周就做到 55% 自主解决；今天在支持的工作流里 CareX 自主解决 65% 的客服交互，不经人。扩到实时语音后，平台目标是整条工作流（含文字和语音）95% 自主解决——这是目标，不是已经完成的结果。

Xplore IQ 是个性化引擎，按行为和实时信号推荐下一步（漫游包、升套餐、防流失）。新加坡对比：拿到 AI 推荐的一组 ARPU 增加 22%，及时相关推荐帮 churn 降 9%。内部工程、信息安全和事故管理用 Codex，开发效率增加 29%，校验和终审仍在专家。治理上：PII 进模型层前识别并加密；专科 agent 只拿解决该任务所需信息；还有人工升级、分阶段上线、限流、回滚和商业护栏。

给负责人

要解决什么
电信公司有用量、账单、网络、位置等信号，但很难变成及时、对这个人的行动；传统支持是事后才动。
结果
在新加坡，AI 个性化使 ARPU 增加 22%，流失减少 9%（对照未收到 AI 推荐的客户）。CareX 为客户支持做到 65% 自动解决率（早期部署第一周为 55%）。Codex 在设计、编码协助和单元测试上带来 29% 的开发效率提升。
接了哪些系统
OpenAI API；多 agent 架构；PII 在到达模型层前被识别并加密；专家 agent 获得范围化访问
用了什么数据
用量、账单、网络活动和位置信号；实时客户语境（例如浏览漫游选项、账单问题）
人还管哪一步
无缝升级给带完整语境的人工 agent；专家负责校验和最终审阅

给现场的人

主要用在哪
AI Concierge（OpenAI API 上的对话界面）；CareX 客户支持多智能体架构；Xplore IQ 个性化引擎。
以前怎么干
传统电信支持：菜单、重复信息和问题发生后等待帮助。
卡在哪
事后支持；无法实时按信号行动。
用了什么模型
OpenAI API（模型）
事情怎么流转
编排 agent 理解历史和当前活动，并路由到专家 agent（账单、订阅、网络、账户）；带着完整语境升级给人工 agent
怎么上线
部署在新加坡；目标 95% 自主解决，配实时语音支持
能不能复用到下一家
增强 CareX 可观测性并引入实时语音支持
「AI 应让用户更能做事，而不是把他们硬塞进过时旅程。OpenAI 的角色对 Circles 在全球扩展这一愿景至关重要。」——Awais Malik，Global Chief Growth Officer，Circles
