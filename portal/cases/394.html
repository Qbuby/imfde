Rubrik 不只给代码上 AI，他们用 Augment 把整个 SDLC 重想了一遍

故事。Rubrik 工程副总裁 Adam Gee 改主意，不是因为一场演示或路线图。是他看着一个 agent 在 Rubrik 真实代码库上从头干到尾。他给 Auggie 的是一个想法——不是片段，也不是精心写的 prompt——然后看着它开工。它检查代码库、做出计划、做协调过的获批改动、跑单元测试、修失败、再跑，直到系统通过。「那对我来说是真正的转折点。」打动他的不是 Augment 写代码快，而是这个 agent 能对一套又大又乱的生产系统推理，并把活干完，不用人一路扶。那一刻成了后面一切的参照——Rubrik 怎么评工具、工程师怎么采用、AI 怎样从个人生产力铺成一种新干活方式。

给负责人

要解决什么
让 agent 在跨越多个产品线的 12 年单体上有用——其他 agent 只在小仓库里有帮助——然后把它们用到开发者时间中约 80% 不是写代码的部分。
结果
无数字交付 KPI。全公司有机创建约 100 条提示。「开发者时间只有约 20% 花在写代码上」是 Adam 对机会的框定，不是已衡量的 Augment 差值。其他 agent 在单体上失败（选型背景）。
接了哪些系统
VS Code、IntelliJ IDEA；InfoSec 对工具调用的控制；Jira 做发布协调。
用了什么数据
12 年单体；日志；Jira；堆栈跟踪。
人还管哪一步
已批准变更；InfoSec 治理。采用不强制——工程师不想放弃它。

给现场的人

主要用在哪
在真实代码库上的端到端 Auggie。Agent 人设：「Auggie，变成分诊员」（日志/信号）。约 100 条提示有机产生。发布经理自动化抓取 Jira；支持安装 IDE 读堆栈跟踪。
以前怎么干
试过其他 AI 编码工具；在单体上不加价值时很快丢掉。跨组织评估；Augment Context Engine 索引整个代码库并胜出。InfoSec 推动工具调用控制、政策、治理；Augment 迭代。
卡在哪
巨大单体；安全门槛；其他 agent 在规模上失败。开发者时间只有约 20% 在写代码（Adam 的框定）。
用了什么模型
Augment Code（页上：Context Engine / agent / 补全；除非另有说明，无单个模型名）。
事情怎么流转
想法 → 检查 → 计划 → 协调的已批准变更 → 单元测试 → 修复 → 再跑。分诊、审查、发布协调、支持的人设。
怎么验收
定性信任/采用。约 100 条有机提示。无交付 KPI 表。
怎么上线
1,100 名工程师。支持与发布经理使用超出核心工程。
失败了怎么改
其他工具在小仓库里有帮助，在 12 年单体上没有；工程师丢掉不加价值的工具。
能不能复用到下一家
有机人设/提示；Auggie 作为分诊员/审查者/发布协调者/支持助手。
那对我是真正改变游戏规则的时刻。——Adam Gee，Rubrik 工程副总裁
