把 2,000 名工程师扩到 3 倍速度：Pure Storage 与 Augment Code 的路

Pure Storage 与 Augment Code 的旅程。故事。Pure Storage 2,000 人的工程团队，正在用 Augment 的 Context Engine 建一套新开发方法——目标是把交付速度翻三倍，同时保住企业级安全。

挑战：在庞大代码库上规模化采用 AI。Pure Storage 安全与 GenAI 首席技术官 Ratinder Ahuja 博士第一次向董事会讲「GenAI 改造的企业」愿景时，他就知道最大的机会和挑战，是改 2,000 名工程师怎么干活。Pure Storage 不是典型软件公司。作为全球领先的数据存储商之一，他们的代码库又大又互相连。「把我们想成嵌入式系统——什么都连着什么，」Ratinder 解释。「设备驱动里一个小改动，就能在系统其他部分掀起大影响。」

给负责人

要解决什么
改变 2,000 名工程师在嵌入式风格互联单体（设备驱动变更会到处涟漪）上的工作方式，并在不破坏企业安全的情况下提高交付速度。
结果
页上无全组织 3 倍结果——「未来两年的总体目标是把交付结果的速度提高两倍」。爱好项目：作者不读代码就通过了 1,000+ 测试。Copilot 在单体上「并没有真正增加价值」（选型背景）。不要把索引卡「3x velocity」当作已交付 KPI。
接了哪些系统
Context Engine；CLI/agent。生成中的安全 SDLC 指令。
用了什么数据
单体多语言仓库；MRD/PRD/设计文档；安全 SDLC / DevSecOps 指令。
人还管哪一步
SME 创建/审查正式文档。人类专家仍看着它们。目标是一致基线，让没人掉队。
多久上线
爱好项目轶事：1,000+ 测试，作者从未看过代码。组织 3 倍是两年目标。

给现场的人

主要用在哪
标准化「配方」/指令，使 2,000 名工程师共享基线。四阶段方法：正式需求/MRD/PRD/设计文档；数学上完整的设计（真值表、状态机）；嵌入安全（威胁建模、漏洞查找与补丁、最小权限政策）；从这些规范做正式测试。还提及：安全 AWS 部署；连接 Salesforce、NetSuite、SAP 的财务机器人；公民开发者——作为应用，不是已衡量结果。
以前怎么干
董事会级「GenAI 转型企业」愿景（Dr. Ratinder Ahuja，安全与 GenAI CTO）。先前 Copilot 实验：工程副总裁 Dilip Kumar Uppugandla——面对巨大单体代码库，Copilot 并没有真正增加价值。跨组织工具评估；Augment 在安全姿态与 Context Engine（C++ 包装直到设备驱动调用）上胜出。
卡在哪
数千工程师，各有习惯；Copilot 在单体上弱；早期 Augment 用户一次糟糕会话后很难赢回来。
用了什么模型
Augment Code（页上：Context Engine / agent / 补全；除非另有说明，无单个模型名）。
事情怎么流转
正式规范 → agent 构建 → 全面测试。Agent 用于过去需要专家的文档与安全需求。
怎么验收
未来两年的总体目标：把交付结果的速度提高两倍（例如一年一个功能 → 三个）。那是目标，不是已衡量结果。Dilip：目前满意，对合作有信心。
怎么上线
把方法铺到 2,000 名工程师。发现 CLI/agent 后的热情倡导者（「除非从我尸体上跨过去」）。
失败了怎么改
单体上的 Copilot 增加价值很少。早期糟糕的 Augment 会话让再采用很难，直到 agent/CLI 点通。
能不能复用到下一家
配方/指令基线；四阶段安全方法；Augment 作为组织最佳实践的未来导师（愿景）。
工程师告诉我们：「你们别把这个拿走。除非从我尸体上跨过去。」——Dr. Ratinder Paul Singh Ahuja，Pure Storage 安全与 GenAI CTO
