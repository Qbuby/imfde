DBS 怎样通过接入 AI，让员工把精力放到有意义的活上

挑战。跨所有来源和屏障的一体化 AI 方案：DBS 想加强内部搜索、拆掉烟囱，并在所有系统和应用上立一套一体化 AI 工具。模型探索和试验：被 LLM 和 AI 的表现打动后，DBS 问自己——如果模型能用世界知识做到这个，我们怎样让它对企业知识也成立？愿景是把企业知识和世界知识结在一起，帮员工干得更快、更聪明、更好。

给负责人

要解决什么
增强内部搜索、打破孤岛，并把企业知识与世界知识结合，使员工在银行级安全下更快/更聪明地工作。
结果
超过 40,000 名 Glean 用户。最多 10% 的员工工时被解放。支持工单解决时间减少（无分钟/%）。HR 政策查询改善且常见问题被分流（无 %）。10% 与 40,000 在页上但无具名证明人。
接了哪些系统
数百连接器。Glean Protect 用于规模化而不过度分享/泄漏。经自然语言查询的 agent builder。
用了什么数据
经数百连接器的企业知识；相关外部数据。HR 政策文档。支持工单数据。未按系统名逐项列出。
人还管哪一步
Glean Protect 防止过度分享。时间被解放后，员工聚焦「有意义、增值的任务」。
多久上线
未标注日期。

给现场的人

主要用在哪
企业搜索加上 Glean Agents：客户支持 agent（工单解决）；HR 支持 agent（政策问题）；经自然语言向任何人开放的 agent builder，配 Glean Protect 防止过度分享。
以前怎么干
寻找跨所有系统的集成 AI 工具。对 LLM 在世界知识上的表现印象深刻；问如何让那与企业知识一起工作（Nimish Panchmatia，首席转型官——框定为愿景，不是结果引言）。
卡在哪
孤岛；需要跨来源与屏障的单一 AI 工具。
用了什么模型
Glean 搜索、Glean Agents、Glean Protect、agent builder。泛泛讨论 LLM。无基础模型品牌。
事情怎么流转
支持 agent 提供正确数据以削减工单解决时间（未量化）。HR agent 改善政策文档、查询解决，以及常见问题分流（未量化）。任何人都能在 Protect 下用自然语言构建 agent。
怎么验收
DBS 超过 40,000 名 Glean 用户。「解放最多 10% 的 DBS 员工工时。」支持/HR 影响是定性。40,000 / 10% 数字上无具名发言人。
怎么上线
推动 AI 素养/采用；40,000+ 用户。agent builder 向任何人开放。

备注

Glean 官方客户故事页（抓取 2026-08-29，HTTP 200）。company=Glean。重复英雄芯片「1.5+ hours saved / search time saved per employee, weekly」出现在许多 Glean 故事上，除非叙述重述周数字，否则不视为客户特定 KPI。官方故事 200。40,000 用户与最多 10% 工时在页上但未归于具名发言人。Panchmatia 引言是愿景（「把企业知识与世界知识结合」），不是结果。支持/HR 影响未量化。
