Deepgram — Claude 带来 4–10x 更持久代码，95% Claude 编写代码

Deepgram 的工程面非常大：推理、API、SDK、计费、集成、基础设施和应用。传统流程已经跟不上。

“我们的竞争对手，还有我们还没听说过的初创公司，都在用原生 AI 方式开发，生成代码的成本快到零了，”Deepgram 工程副总裁 Kris Efland 说。“我们不发，别人就发，客户跟着谁发就跟谁走。”

事故排查最能说明问题。客户报告文本转语音错误激增时，工程师得手动拉日志和指标，拼在一起再回复，往往要来回好几天。数据散在五个地方，接单的工程师还不一定是出问题的服务负责人。

Claude 的使用已经跑在官方计划前面：工程师从个人 API 密钥换成自掏腰包的 Claude Max 订阅。

“如果你最能干的人都自费绕过公司限制，那你损失的已经比买 License 多，”Efland 说。

结论是：要么重建成代理式公司，要么被别人甩开。Deepgram 把这个项目叫 DG2。

先拿数据说话：用真实代码库对 Claude Code 和其他编码代理做了一场 bake-off。最重要的是模型在 Deepgram 的 Rust、Python 和基础设施即代码上的原始质量、与内部工具的契合度、自我验证能力，以及零摩擦访问。

“模型就是更好，句号，”一位重度用户在 Claude Opus 4.6 上线后说。“其他都是次要的。”

内部分析把开发者按 Claude 使用量分组，追踪代码后来被替换的频率；留在代码库里的算持久代码。常规和重度 Claude 用户产出的持久代码，大约是非用户的 4–10 倍，而最重度用户带来的代码替换率也高出约 9 倍。

于是 Deepgram 把 Claude 生成代码的测试覆盖标准定得更高，而不是更低。

正式开放权限意味着 2026 年年中硬切到 Claude Enterprise。Deepgram 处理 HIPAA、SOC 2、GDPR、PCI-DSS 和 CCPA 下的客户数据，所以必须用 Enterprise 许可，默认关闭训练且用户无法改。

留存、工具权限和 MCP 白名单集中管理，新员工账号在入职前自动下发。

“Claude 是唯一一个周边系统够好，让我们把自家基础设施都围着它重塑的前沿模型，”Efland 说。

Deepgram 开源了一个终端 API，让代理能直接驱动终端 I/O，把工具改成适配代理，而不是反过来。

代码评审走 Claude，按项目所处生命周期的 rubric 执行，明确要求别在小问题上卡人，但要盯住安全。

Claude 还跑在 Slack 里，做环境简报和站会回顾。

“区别在于 Claude Code、Cowork、MCP、skills 和 subagents 组成的生态，”Efland 说。“这些创造的价值远超单一模型的天花板。这是我们和其他提供商都没达到的集成深度。”

默认的工程循环走 Claude Code：先 plan 模式，迭代到对，再让 Claude 执行并验证。

Claude Code 通过 Model Context Protocol（MCP）连到工程师已经在用的系统，从 Slack、Asana 到 GitHub、Grafana，再驱动日常 CLI 工作。

全靠一个 CLAUDE.md 文件和几个斜杠命令。

“紧凑的配置永远打败复杂的配置，”Efland 说。

可复用的方案就变成 SKILL.md，放在 deepgram/agents 仓库里，全公司都能用、都能改进。

非编码工作也一样：Slack 消息变成 Asana 工单或事故调查。

底层用 Opus 处理重度编码和推理，Haiku 负责高频自动化。

Claude 也出现在产品侧：Voice Agent API 把 Deepgram 的 Nova、Flux、Aura 语音模型和 Sonnet（Advanced 档）、Haiku（Standard 档）搭配做推理端到端延迟约 700ms 以内。

一位叫 Jake 的工程师用 Claude Code 做了内部多代理支持系统 Deephive。

一个中心 Opus 级代理读问题，然后并行拉起只读的 Sonnet 级 worker，从 Slack、DevRev、Notion、GitHub、Asana 拉上下文，合成诊断、起草内部交接和客户回复。任何发送或修改都需要人工批准。

Deepgram 用这套服务顶级客户，包括 Anthropic 自己，从根因定位到拉 PR 只用几小时，给 GPU 规格建议只要几分钟。

最清楚的一次是客户报告持续的文本转语音降级。

Deepgram 工程师把事故响应 skill（带 Loki 和 Prometheus 权限的 Claude Code）指向问题。

它给出了正确诊断：低基线服务器端流错误，不是宕机；还给出了确切的客户端修复 reconnect-on-1011，纠正了工程师之前的猜测。

回复签了“Sent using Claude”。

“把‘水通过管道’变得容易了，”Efland 说。“把所有 bug 都揪出来，还是得读代码。”

每一次生产变更都有人工签字，每一个交付物都有一个负责的人。

“Claude 是唯一一个周边系统够好，让我们把自家基础设施都围着它重塑的前沿模型。”

Kris Efland
Deepgram 工程副总裁

给负责人

要解决什么
工程面太大（推理/API/SDK/计费/集成/基础设施/应用），老工作流跟不上。竞品按 AI 原生在建，写代码成本趋近于零。
结果
常规/重度 Claude 用户比非用户多 4–10 倍持久代码。最高产工程团队约 95% 代码由 Claude 写。团队项目 3–5 倍增益、个人常规工作 2 倍以上。客户事件分诊从多天→分钟。替换约 80% 遗留研究栈。1 名新兵 6 周 40+ 个 PR。Voice Agent API 端到端延迟不到 700ms。
接了哪些系统
Claude Code 经 MCP 连工程师现有系统；全公司迁 Claude Enterprise（SSO、集中合规、组织级 MCP allowlist）；开源 terminal API 让 agent 驱动终端 I/O
用了什么数据
内部代码库（Rust/Python/IaC）、Loki/Prometheus/Grafana 日志指标、Slack/DevRev/Notion/GitHub/Asana；受 HIPAA/SOC2/GDPR/PCI-DSS/CCPA 监管
人还管哪一步
任何发出/变更需人工批准；每次生产变更带人工签核；每交付物有且仅有 1 个负责人类；Claude 在 Slack 做环境简报
多久上线
新员工入职小时/天级（非周）；事件分诊根因→PR 小时级、GPU 建议分钟级；1 新兵 6 周 40+ PR
怎么交给客户
Deepgram 工程团队自运营；VP Engineering（Kris Efland）主导 DG2 与标准

给现场的人

主要用在哪
内部工程重建：Claude Code 计划/迭代/执行/验证，经 MCP 连 Slack/Asana/GitHub/Grafana。多智能体客服系统 Deephive（1 个 Opus 智能体拉起并行只读 Sonnet worker，从 Slack/DevRev/Notion/GitHub/Asana 拉上下文，合成诊断并起草内部交接和客户回复）。事故响应技能（Claude Code + Loki/Prometheus）。
以前怎么干
客户报 TTS 错误时，工程师手工拉日志指标（数据散在 5 处），来回好多天。工程师从个人 API key 转到自掏腰包买 Claude Max。
卡在哪
事件分诊来回好多天。官方额度限制导致人才流失（有人自掏腰包绕开）。传统工作流速度不够。
用了什么模型
Opus（重编码/推理，含 Opus 4.6）、Haiku（高容量自动化）、Sonnet/Haiku（产品侧 Voice Agent API 推理，延迟 <700ms）
事情怎么流转
plan mode→迭代→Claude 执行并验证；Deephive 中心 Opus agent 生成并行只读 Sonnet worker；可复用方案存为 SKILL.md；代码审查按生命周期 rubric，不因 nit 阻断但盯安全
怎么验收
同期群分析追踪代码留存（持久度）；Claude Code 真实对比评测（模型质量、与内部工具契合、自验证、零摩擦访问）；Claude 生成代码测试覆盖标准定得更高
怎么上线
2026 年中硬切换到 Claude Enterprise；retention/权限/MCP allowlist 集中管；新员工账号第一天前自动发
能不能复用到下一家
DG2 agentic 重建；Claude Enterprise 集中合规；开源 terminal API
