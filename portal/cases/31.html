Pearl Technologies 如何借助 Augment Cosmos 实现 3x 生产力提升

Pearl Technologies 从手动交付卡点，切换到云原生 AI-SDLC，再把这套模式推到整个工程组织。

难题：规模和知识瓶颈
Pearl Technologies 的工程团队超过 100 人，分布在全球各地。他们在扩展 Transportation Management System 时遇到三道坎：

手动 SDLC 卡壳：开发人员每周只能交付 40 小时。从工单到可上生产的 PR，全靠人工写故事、搭本地环境、反复跑单元测试。

知识孤岛：知识传递靠同步会议或大段文档，拖慢协作。

硬件门槛：早期 agentic AI 流程要在本地跑，需要高配 GPU 和大内存，不是每个人都能用。

“在用 Cosmos 之前，我要是想分享知识，只能约电话或者写一大堆文档传过去。我们在会话共享、工作区和知识延续上都卡住了。”
Gaurav Thakur
Senior Engineer Manager

解法：转向云原生 AI-SDLC

Pearl Technologies 试用 Augment Cosmos，把 AI 从简单聊天升级到完整 agent 编排。落地分三条线：

1. 通过 Azure DevOps 编排 agent
团队用 webhook 把 Cosmos 直接连到 Azure DevOps。改用对话式指令下命令，Cosmos 自动写用户故事、生成代码、跑单元测试，再直接把 PR 推到 GitHub。

2. 去掉硬件门槛
Cosmos 在云端执行（Daemon/VPC 编排），把 AI agent 的重活从个人笔记本搬到 Augment 的基础设施上。无论本地机器配置如何，全员都能参与 agent 流程。

3. 专家工作区和会话共享
团队用工作区分隔前端、后端和 DevOps 上下文。更关键的是 Session Sharing：一个开发者做完任务，能立刻把完整上下文交给队友继续。

关键发现

吞吐量爆发：基线期 4 月 3–6 日团队 0 PR；采用 Cosmos 后，13 个工作日完成 728 个 PR。效率从 3.2 提升到 4.7 PR/会话，三周内增长 47%。

周期大幅缩短：原本多天的复杂迁移，现在一天内完成。

Agent 自主与成功率：2026 年 6–7 月的 21 个 agent 驱动案例中，71% 成功，29% 部分成功，0% 失败。7 个文件变更的中位耗时约 5.5 分钟。一个 agent 用 5 分钟完成 16 个文件的 carrier driver Kafka 集成，这项工作通常需要高级开发人员数小时。

定性回报：代码更好，零故障。21 个案例均无下游故障。AI 辅助 PR 包含结构化根因分析、详细测试计划和工单关联，评审质量高于人工 PR。

预估节省：分析师估算，21 个案例中 agent 完成的工作，节省了 73–113 小时高级开发人力。全年推算，可把数千小时从重复劳动和迁移中释放出来，转向高价值架构和产品工作。

影响：超出工程范围
Cosmos 的成功不只停留在核心工程团队。第一个月内，团队为 Charger Logistics 的运维部门打造了专用 Email Automation Expert，把 60–70% 的人工邮件沟通自动化，让运维团队腾出时间做更高价值的事。

展望：新运营模式
对 Pearl Technologies 来说，Cosmos 不是工具，而是运营模式的根本转变。他们下一年的目标是把 TMS 内 20–40% 的决策自动化，走向“人在回路”系统，让 AI agent 处理大部分操作动作。

“工程正在走向 AI 驱动的 SDLC，不管你准备好了没有……”
