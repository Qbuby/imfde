Atlassian — Claude 作基础 agent 模型，每月 500 万+ agent 跑在客户工作流

聊天机器人只能总结线程、起草更新，活还是得人干。Atlassian 的客户想把活直接交给可信的 agent：先审合同、分拣支持工单、挖销售线索。

把这种要紧、重复的工作交给 agent，门槛比聊天高得多。agent 必须像人一样在产品里调用 Atlassian 的功能，业务才敢信结果。

“我们擅长给人做界面，”Atlassian AI 负责人 Sherif Mansour 说，“下一个能力是让 agent 也能用这些功能。怎么让 agent 成为软件的同等用户？”

信任最难建立在最值钱的地方：复杂、长时间的任务，错一次越拖越严重。Atlassian 开放几百个 AI 能力，横跨 20 多款产品，agent 能访问什么、返回什么，全靠部署方式决定。agent 拿不到信任，客户就不会把值得自动化的活交给它。

“规模、复杂度和信任，是反复出现的三大主题，”Mansour 说。

Atlassian 把 Claude 放在出错代价最高的工作流上。Claude 在指令遵循、长上下文处理、工具编排上表现稳定。

“我们优先考虑企业工作流的可靠性，”Mansour 说，“Claude 模型更擅长一致执行复杂指令、处理大量上下文而不丢细节，尤其在质量和信任最关键的地方。”

这项能力首先出现在 Rovo Chat 里。Rovo Chat 服务数百万用户，Claude 是其中一个模型，从 Atlassian 暴露的数千个工具和技能里挑出合适的来用。

Claude 还驱动 Rovo CLI，这是 Atlassian 主要的开发者 AI 体验；也支撑 Rovo Max——Chat 的一个早期模式，它接目标而不是任务，一直干到完成。

Rovo Max 借助 Teamwork Graph——Atlassian 把客户各应用里数十亿对象连成的图谱——在管理员可控的包和网络环境下运行。

很多 Atlassian 客户本身就是软件和 IT 团队，Claude 帮他们做代码审查和生成，需要跨大型代码库阅读。

有些客户更进一步，把 Jira 工单直接扔给 Claude agent，让它接手并执行。

Atlassian 内部也用 Claude Code，工程团队用得重，最近试点扩展到非技术团队，产品经理和设计师用它做原型、提交小改动、建内部应用。

Claude 跑在 Atlassian 自建的内部 AI 平台上。平台核心是用 Gemini Enterprise Agent Platform（原 Vertex AI）做的 AI 模型网关，负责跨提供商路由和管理 AI 负载。

Atlassian 在 Google Kubernetes Engine 上扩展这个框架，同时用 Google Cloud 的 GPU 和 TPU。

“在 AI 世界，不能只用一种工具，”Mansour 说，“和 Google Cloud、Anthropic 合作，让我们拥有最终的企业工具箱，能在最合适的时间把正确的工作负载自动路由到正确模型。”

团队建新能力时，自己写评估、按质量和成本跑基准，然后上线表现最好的模型。

Atlassian 把高量级自定义 agent 的平台切到 Google 的 Gemini Flash 系列。

“我们大幅降低了客户在平台上跑持续 AI 工作流的运营成本，”Mansour 说，“通过 Google Cloud 用 Gemini 和 Claude，我们同时做到三件事：成本下降、质量提升、延迟保持最优。”

Gemini Flash 现在是通用客户 agent 的默认模型，Claude 负责复杂、长时间的任务。

供应商退役模型时，团队可以直接换新模型，不用重构架构。

“如今 AI 里的长期路线图大概不超过三个月，”Mansour 说，“对所有组织来说，最重要的是让团队手上有工具，能快速应对变化。”

“通过 Google Cloud 用 Gemini 和 Claude，我们同时做到三件事：成本下降、质量提升、延迟保持最优。”

给负责人

要解决什么
AI 已经嵌进 Atlassian 每款产品；客户要智能体干真活（审合同、分诊工单、挖销售线索），不要只会聊天的助手。
结果
单月 500 万+ 智能体跑在客户业务工作流上。35 万+ 客户；20+ 产品、数百项 AI 能力。页上称「成本降、质量升、延迟优」三赢。
接了哪些系统
自建 AI 平台：AI model gateway 基于 Gemini Enterprise Agent Platform（主路由），跑在 GKE + Google Cloud GPU/TPU；Claude 用于复杂长任务
用了什么数据
Teamwork Graph（跨客户应用的十亿级对象连接图）；Jira board、Figma、Google Docs
人还管哪一步
Rovo Max 仅在需 Instagram 账号时由人提供；管理员控制包与网络访问
怎么交给客户
Atlassian 客户自服务；AI 负责人（Sherif Mansour）主导信任标准与路由策略

给现场的人

主要用在哪
Rovo 系列：Rovo Chat（Claude 当基础智能体模型，数百万用户）、Rovo CLI（开发者主要 AI 体验）、Rovo Max（早期访问，跨 Atlassian 工具规划/推理/执行复杂工作）、Rovo Studio（Claude Opus 4.8 / Sonnet 4.6 做低代码智能体）。
以前怎么干
Jira/Confluence 等 20+ 产品、35 万+ 客户、数十亿工作流；聊天助手仍把活留给人。
卡在哪
越值钱的长任务，信任越难建。规模、复杂度、信任是三大主题。聊天助手「还是把活留给人」。
用了什么模型
Claude 作基础 agent 模型（Rovo Chat/CLI/Max/Studio 用 Opus 4.8、Sonnet 4.6）；Gemini Flash 作通用客户 agent 默认
事情怎么流转
Rovo Max 取目标而非任务，用 Teamwork Graph 自主工作于受管环境；部分把 Jira ticket 直接交给 Claude-powered agent 执行；Claude Code 内部用于原型/小改动/内部 app
怎么验收
团队自建评估，按质量/成本基准测模型；Claude 在复杂指令一致性与大上下文上更优
怎么上线
AI 模型网关基于 Gemini Enterprise Agent Platform；高容量自定义 agent 迁到 Gemini Flash；厂商退役模型时无缝换新版
能不能复用到下一家
Rovo Chat/CLI/Max/Studio 全线；AI 平台支持模型路由与热替换
我们优先考虑企业工作流中的可靠性。Claude 模型更擅长始终如一地遵循复杂指令…… — Sherif Mansour, Head of AI, Atlassian | 通过 Google Cloud 使用 Gemini 和 Claude，我们打出了罕见的三赢：成本下降、质量提升、延迟保持优化。 — Sherif Mansour
