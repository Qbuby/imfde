闭环工程

学习目标：Atlassian 页上，聊天助手还把活留给人，有的把 Jira 工单直接交给 agent。这一步写清工具边界、失败怎么恢复、何时停。做成不能只看一次点击。

这一步怎么做

  1. 定时发现，写入外部状态

    Atlassian 页上，聊天助手还把活留给人，有的把 Jira 工单直接交给 agent。设置定时发现与分诊，把发现写入工单或状态库，再按优先级调用。信号要落成外部状态，不要停在对话里。

  2. 并行任务用独立分支

    Jira 工单交给 agent 时，并行任务用独立分支和 Git worktree，完成后再审查、合并。共用主目录会互相覆盖。不要轮流写，也不要让一个 Agent 只出建议却不设验收。

  3. 约定写成版本化 Skill

    Rovo Max 取目标而非任务。项目约定、验证步骤和禁止事项写成版本化 Skill，任务匹配时调用。不要每次重新猜规则，也不要把全部旧对话永久附上。

  4. 受控 connector 才能推进

    只会生成 Markdown 报告，Jira 工单推不动。页上：管理员控制包与网络访问；自建 model gateway。通过受控 connector 接入工单、代码托管和通知，才能开 PR、更新任务。工具边界写死，凭证不要放进提示词。失败要能恢复；做成、预算耗尽或需人工判断时停止并升级。

  5. 交一页闭环简报

    信号、外部状态、工具边界、失败恢复、停止条件、并行隔离、Skill、connector，写在一页上。模糊成功不能只用一次点击率来评。页上「单月 500 万+ agent」只当规模陈述，不是闭环做成的验收。

作业 · 一页闭环简报

抄到自己的笔记里填。

客户 / 现场：
信号从哪来（定时发现，写入哪份外部状态）：
优先级与调用顺序：
工具边界（能调什么、不能调什么）：
失败恢复（超时 / 重试 / 补偿）：
停止条件（做成 / 预算耗尽 / 升级人工）：
并行任务如何隔离（独立分支 / worktree）：
版本化 Skill（约定 / 验证 / 禁止事项）：
受控 connector（工单 / 代码托管 / 通知；谁授权）：
成功怎么评（不要只用一次点击率）：
页上有口径的数字（只抄、不当验收）：
明确不做：

  • 及格

    定时发现写入外部状态；并行任务有独立分支；约定进了版本化 Skill；受控 connector 能推进 PR / 工单；工具边界、失败恢复和停止条件写死；成功标准不是一次点击率。

  • 不及格

    每天手动问、共用主目录轮流写、只会写报告、把凭证放进提示词，或只用一次点击率评模糊成功。

  • 不要编的数

    「单月 500 万+ agent」是规模陈述；「成本降、质量升、延迟优」不当验收公式。不要编点击率、PR 合并率、SLA 或 FDE 头衔。
