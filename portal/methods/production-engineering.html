生产工程

学习目标：Atlassian 交给客户之后，要能值班、能回滚、能看日志。对着页上已有的网关、路由、热替换写交接。没有的 SLA 不要编。

这一步怎么做

  1. 先问能不能值班

    Atlassian 交给客户自服务之后，要能值班、能回滚、能看日志，才叫生产。页上已有网关、路由、热替换——这些比 demo 更能决定是否留下。

  2. 写超时、降级、接管、幂等

    有的把 Jira 工单直接交给 agent，关键路径不能断：超时预算、降级路径、人工接管、幂等重试。写操作失败后状态不明，要查外部事实、用事务或补偿，歧义升级。

  3. 监控任务是否做成

    聊天助手还把活留给人，做成不能只看 API 可用率。质量、任务成功、延迟、成本、高风险失败都要看。

  4. 页上已有的平台能力写进步骤

    有网关、路由、热替换就写进交接，不要发明 SLA。厂商退役模型时换新版——平均质量更高但尾部延迟翻倍时，按任务评估延迟预算，影子或灰度比较，并保留回滚。

  5. 交一页生产交接

    值班人、日志入口、回滚、降级、监控项、谁接管。页上「单月 500 万+ agent」只当规模陈述；「成本降、质量升、延迟优」不当验收公式。

明确不做：

  • 及格

    写得出值班、回滚、日志；有超时 / 降级 / 接管 / 幂等；监控覆盖质量、任务成功、延迟、成本、高风险失败；页上已有网关 / 路由 / 热替换写进了步骤。

  • 不及格

    只有 demo；只监控 API 可用率；立刻全量换模型；或盲目重放写操作。

  • 不要编的数

    不要发明 SLA、可用率或上线后百分比。页上 500 万+ agent 是规模陈述；「成本降、质量升、延迟优」不当验收公式。不要补 FDE 头衔。
