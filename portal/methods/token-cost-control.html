控制 Token 成本

学习目标：Atlassian 高容量自定义 agent 迁到 Gemini Flash，复杂长任务才上 Claude。对着这页写预算、缓存、路由，以及这场对话还值不值得继续烧。单价页上没有就空着。

这一步怎么做

  1. 按真实任务估预算

    Atlassian 页上有质量/成本基准和单月 500 万+ agent 规模；规模不是单价，页上也没给单价，不要编。按真实任务估算输入、输出、缓存命中、重试、工具调用和峰值，再设预算阈值。第一张账单没到，也要把预算写上。

  2. 稳定前缀放在前面

    同一份长政策每次都放开头、但前缀不稳定，缓存命中会低。稳定共享前缀保持一致，用户、时间等易变内容放到后面，并监控缓存 Token。页上没写缓存命中率，简报里留空。

  3. 按质量门槛做路由

    Atlassian 页上：高容量自定义 agent 迁到 Gemini Flash，Claude 用于复杂长任务；厂商退役模型时换新版。用已评测的质量与风险门槛做模型路由，只把需要的任务升级。这是路由，不是把「成本降、质量升、延迟优」当公式。

  4. 压缩要用完成率验证

    把回答一律截短，成本下降但 Jira 工单做不成。按任务定义足够的结构和上限，用完成率与质量评测验证压缩没有破坏结果。预算耗尽或质量掉出门槛时停止或降级，把「这场对话还值不值得继续烧」写进方案。

  5. 交一页 Token 成本简报

    任务基线、预算、前缀与缓存、路由门槛、压缩验证、停止条件，写在一页上。页上「成本降、质量升、延迟优」是厂商定性，作业不要当验收公式。没有的单价留空。

页上路由 / 评测口径（只抄）：
页上没写的单价（留空，不要编）：
明确不做：

  • 及格

    按真实任务写了输入 / 输出 / 缓存 / 重试 / 工具调用 / 峰值；稳定前缀与易变内容分开；质量与风险门槛用于路由；压缩用完成率验证；停止或降级写进了方案。

  • 不及格

    只用单价乘用户数、等账单再定、总调最贵或最便宜模型，一律截短当省钱，或把「成本降、质量升、延迟优」当验收公式。

  • 不要编的数

    单价、缓存命中率、每任务 Token 页上没写，不要填。「单月 500 万+ agent」是规模陈述；「成本降、质量升、延迟优」是定性。不要补节省金额或 FDE 头衔。
